# YIAN 内存安全机制概述

本文介绍 YIAN 的内存安全设计。

## 1. 它要解决什么问题

手动管理内存的语言通常会遇到几类典型错误：

- 访问数组、切片或对象末尾之外的区域；
- 指针计算时发生整数溢出，导致地址跑到完全错误的位置；
- 对象释放后仍然使用旧指针；
- 同一块内存被释放两次；
- 函数返回后继续使用指向局部变量的指针；
- 一块内存被重新分配给其他对象后，旧指针“误以为”自己仍然有效。

这些问题的共同点是：一个普通指针通常只保存一个地址。仅凭地址本身，程序无法判断这个地址属于哪个对象、对象是否仍然存活，以及本次访问是否在对象范围内。

YIAN 的安全模式不把指针看成单纯的地址，而是让指针同时携带“它来自哪里”和“它当前能访问多大范围”等信息。每次真正访问内存前，运行时都会利用这些信息进行检查。

## 2. 核心思路：指针不只保存地址

普通指针可以简单理解为：

```text
指针 = 一个地址
```

YIAN 安全模式中的指针还会携带以下信息：

| 信息               | 作用                                       |
| ------------------ | ------------------------------------------ |
| 数据地址或地址锚点 | 找到对象或对象中的当前位置                 |
| 生命周期锁的位置   | 找到记录对象是否仍然有效的地方             |
| 生命周期键         | 确认这个指针是否属于当前这一轮对象生命周期 |
| 当前位置           | 表示指针位于对象的第几个元素               |
| 可访问范围         | 防止访问超过对象末尾                       |

这种带有额外信息的指针通常称为“胖指针”。额外信息是由语言规则和运行时共同维护的安全元数据。

## 3. 三种指针形态

YIAN 将指针能力分成三个层次。它们都保留生命周期信息，但空间信息逐步减少：

```text
完整指针  →  切片/字符串  →  单个元素引用
```

### 3.1 完整指针

完整指针可以进行元素级移动和范围计算。除了地址和生命周期信息，它还知道当前位置以及从当前位置开始剩余的可访问元素数量。

它适合表达“我正在一个对象内部移动”的场景，例如遍历数组。

### 3.2 切片和字符串

切片表示一段连续的元素区域。它记录起始位置、长度以及原对象的生命周期信息。

切片不是新的独立对象，而是原对象的一段视图。因此，切片仍然会受到原对象生命周期的约束：原对象释放或失效后，切片也会失效。

从一个有偏移的完整指针生成切片时，切片长度会变成“当前位置到原对象末尾的剩余长度”，而不会继续使用原对象的完整长度。这样可以避免偏移后的切片越过原对象末尾。

### 3.3 单个元素引用

引用表示一个已经确认存在的完整元素。它不再需要保存数组索引和长度，但仍然保留生命周期锁和生命周期键。

引用只能从已经确认有效的元素或非空切片产生：

- 指向对象末尾之后的位置不能转换成引用；
- 空切片不能转换成引用；
- 引用访问时仍然要检查对象的生命周期。

因此，引用并不是“永远安全”的地址，而是“空间范围已经在构造时确认，但生命周期仍需要检查”的地址。

## 4. 生命周期安全：锁和键

空间检查只能回答“这个位置是否在范围内”，还需要另一套机制回答“这个对象是否还活着”。YIAN 使用生命周期锁和生命周期键解决这个问题。

### 4.1 分配对象时创建生命周期

每次分配堆对象或进入需要取地址的函数帧时，系统都会创建一个新的生命周期，并生成一个新的键。

指针不会只记住对象地址，还会记住：

```text
生命周期锁的位置 + 创建这一轮生命周期时的键
```

只要锁中仍然保存着同一个键，指针就属于当前有效生命周期。

### 4.2 释放对象时立即使锁失效

释放堆对象时，运行时会先把生命周期锁改成一个特殊的无效值，再把内存放回运行时的空闲池。

函数返回时也采用类似顺序：

1. 先让整个函数帧的生命周期锁失效；
2. 再结束这个函数帧；
3. 之后才允许锁槽被新的函数帧复用。

因此，指向局部变量的旧指针即使保存着一个看起来仍然相同的地址，也会因为生命周期键不匹配而失效。

### 4.3 内存复用不会让旧指针复活

假设一块堆内存被释放，之后又被分配给新的对象。新对象会得到一个全新的生命周期键。

旧指针仍然携带旧键，因此：

```text
地址相同，不代表生命周期相同
```

旧指针访问新对象时会被拒绝，而不是因为物理地址相同就重新获得权限。

### 4.4 键不会自然回绕

生命周期键由单调递增的计数器产生，并且堆对象和栈对象使用不同的键空间。键空间耗尽时，系统选择明确终止，而不是让计数器回绕后重新产生旧键。

这样可以避免极端情况下新生命周期意外获得旧生命周期的身份。

## 5. 空间安全：每次访问前检查

一次内存访问必须同时满足几个条件：

1. 指针的生命周期仍然有效；
2. 起始位置没有超出对象范围；
3. 本次访问的元素数量没有超过剩余长度；
4. 元素大小、偏移量和最终地址的计算没有发生整数回绕；
5. 访问的完整跨度都位于同一个有效对象内。

只有全部条件满足后，程序才会真正执行读取、写入或复制操作。任一条件失败，程序会进入 trap 状态，拒绝执行这次危险操作。

### 5.1 支持 one-past 位置，但不能解引用

遍历数组时，指针移动到数组末尾之后一个位置通常很有用，因为它可以作为循环结束标记。YIAN 允许这种位置存在，也允许比较它，但不允许从这个位置读取或写入元素。

因此：

- “末尾之后的位置”可以作为边界值保存；
- 但不能把它转换成有效元素引用；
- 也不能对它执行元素访问。

### 5.2 指针算术也受到检查

指针加减不能产生负索引、超过对象范围的索引或整数回绕。即使某个计算结果在机器整数中看起来合法，只要它导致最终字节地址溢出，也会被拒绝。

指针之间的大小关系和差值也不是任意定义的：只有来源相同、锚定在同一个对象上的指针，才可以进行有意义的关系比较或相减。不同对象的指针不能通过比较或相减推导出对象内部关系。

## 6. 堆对象的保护

YIAN 安全模式使用运行时管理的单线程堆池。每个堆块都分为两部分：

```text
生命周期和分配元数据 | 用户可以访问的对象数据
```

用户对象只能从数据区域开始访问，堆块前面的元数据区域不属于用户对象的一部分。有效的用户指针不能把堆块头、空闲链信息或生命周期锁当作普通数据访问。

释放堆对象时，处理顺序是：

1. 检查它确实是有效的堆对象；
2. 检查释放视图确实覆盖完整堆块，并且能够定位到对象起点；
3. 先使生命周期锁失效；
4. 再把堆块加入空闲池；
5. 下次复用时生成新的生命周期键。

这带来三个结果：

- 释放后的旧指针不能继续读写；
- 同一个指针第二次释放时会因为生命周期已经失效而被拒绝；
- 堆块复用不会让旧指针重新获得访问权限。

为了保持这套生命周期协议，释放操作不是对任意地址都开放的。内部指针、偏移后的切片、偏移后的单元素引用、栈地址、字符串字面量以及已经失效的指针都不能直接释放。

有两个重要的完整视图例外：覆盖整个堆块的切片可以释放；满足整块释放条件、并且确实来自堆对象起点的单元素引用也可以释放。无论通过哪种视图释放，运行时释放的都是背后的整个堆块，而不是只释放视图覆盖的那一小段数据。

## 7. 栈对象的保护

函数中的局部变量通常位于栈上。YIAN 为每个需要取地址的函数帧分配一个独立的生命周期锁，同一函数帧中取得的地址共享这个锁。

函数返回时，整个函数帧的锁会失效。因此，下面这种情况会被拦截：

```text
函数内部创建局部变量
    ↓
返回指向局部变量的地址
    ↓
函数返回
    ↓
外部继续使用这个地址 → trap
```

即使下一次函数调用恰好使用了相同的物理栈地址，新的函数帧也会使用新的生命周期键，旧指针不会因此复活。

当前设计的失效粒度是整个函数帧，而不是函数内部的每一个词法作用域。也就是说，某些局部对象可能在更小的作用域结束后仍保持到函数返回；这是设计上的限制，而不是细粒度作用域安全保证。

## 8. 指针转换不会绕过检查

指针只能沿着能力逐渐减少的方向转换：

- 完整指针转换成切片时，必须确认当前位置合法，并把长度缩短到剩余范围；
- 完整指针转换成引用时，必须确认当前位置确实还有一个完整元素；
- 切片转换成引用时，切片必须至少包含一个元素；
- 转换后的值继续携带原来的生命周期锁和键。

转换过程确认的是空间来源，不等于把已经失效的指针重新变成有效指针。一个失效的完整指针即使能够被转换成失效的切片或引用，之后真正访问时仍会因为生命周期检查失败而 trap。

用户代码也不能随意把整数、裸地址或任意内存重新解释成带有伪造元数据的安全指针。否则，所有边界和生命周期检查都可能被绕过，所以这类能力必须被限制在经过审计的运行时或标准库代码中。

## 9. 典型错误是怎样被拦截的

| 错误场景                   | 安全机制的处理                               |
| -------------------------- | -------------------------------------------- |
| 数组越界读取               | 检查当前位置和完整访问跨度，失败后 trap      |
| 跨越对象末尾的批量复制     | 检查整个复制跨度，而不是只检查起点           |
| 指针偏移发生整数回绕       | 在地址和跨度计算阶段拒绝回绕                 |
| 释放后使用                 | 释放时锁失效，旧指针的键不再匹配             |
| 双重释放                   | 第一次释放后生命周期已经失效，第二次检查失败 |
| 函数返回后使用局部变量地址 | 返回时帧锁失效，旧地址不能访问               |
| 堆块被新对象复用           | 新对象使用新键，旧指针不能访问新对象         |
| 释放一个内部指针           | 释放视图必须覆盖完整堆块，内部指针不满足条件 |
| 空切片转引用               | 转换前检查长度，空切片不能产生引用           |
| 使用 one-past 指针访问元素 | one-past 只允许作为边界值，解引用会失败      |
| 用户写入堆块头或锁槽       | 有效用户访问范围不包含运行时元数据区域       |

## 10. 安全边界与可信部分

这套机制不是凭空产生安全性，它依赖一组需要被信任和审计的基础部分：

- 编译器必须正确生成指针元数据和访问检查；
- 运行时必须正确维护堆池、生命周期锁和生命周期键；
- 标准库中的受限内存原语必须遵守长度、布局和生命周期约束；
- 编译后端、目标平台和底层内存分配器必须按约定工作；
- 普通用户代码不能任意修改胖指针元数据、堆块头或帧锁槽。

标准库可以拥有普通用户代码没有的底层能力，因此它属于整个安全机制的可信基础。增加新的底层原语时，不能只添加一个 API，还需要同时审查它是否可能伪造指针、扩大访问范围或绕过生命周期检查。

当前模型还假设程序是单线程的，不覆盖并发数据竞争；跨 FFI 边界的裸指针和对象生命周期也需要额外的封送与管理协议。

## 11. 这套机制能保证什么，不能保证什么

在可信基础正确、程序运行在单线程环境、用户代码不能伪造或破坏安全元数据的前提下，YIAN 安全模式的目标是保证：

- 成功执行的用户内存访问位于当前活动对象内部；
- 地址、偏移量和访问跨度不会通过整数回绕绕过边界；
- 释放后的堆对象和返回后的栈对象不能被旧指针访问；
- 双重释放会被拒绝；
- 物理地址复用不会使旧指针重新有效。

它不能自动保证：

- 程序逻辑正确；
- 输入数据符合业务要求；
- 多线程程序没有数据竞争；
- FFI 传入的裸指针生命周期正确；
- 受限标准库或编译器自身没有实现错误；

## 12. 代码示例

下面的示例以 `secl` 分支中的胖指针实现为准，使用该实现的指针、动态分配、数组和切片语法；其中 `T&`、完整堆块视图释放等行为也以该分支为准。标有 `trap` 的语句是故意制造的错误场景，用来说明安全检查会在哪里阻止程序；它们不应作为正常程序运行。

### 12.1 正常的指针和切片访问

```yian
fn main() {
    let data: i32[5] = [10, 20, 30, 40, 50]

    // 取数组中第二个元素的地址。
    let p: i32* = &data[1]
    assert *p == 20

    // 切片是原数组的一段视图，不会拥有新的独立数据。
    let tail: i32[] = data[1u64..5]
    assert tail.len() == 4
    assert tail[0] == 20
    assert tail[3] == 50
}
```

这里的 `p` 和 `tail` 都保留了 `data` 的生命周期信息。只要 `data` 仍然处于当前函数帧中，它们就可以访问各自允许的范围。

### 12.2 动态数组的边界检查

```yian
fn main() {
    let values: i32* = dyn[3] i32

    values[0] = 10
    values[1] = 20
    values[2] = 30

    // 合法下标只有 0、1、2。
    values[3] = 40  // trap：越过动态数组末尾
}
```

检查的不只是起始地址，还包括本次访问的完整跨度。因此，批量复制或多元素访问如果跨过对象末尾，同样会被拒绝。

### 12.3 one-past 位置可以存在，但不能访问

```yian
fn main() {
    let data: i32[3] = [10, 20, 30]
    let first: i32* = &data[0]

    // 指向数组末尾之后的位置，可以作为循环边界保存。
    let end: i32* = first + 3

    // let value: i32 = *end
    // trap：one-past 位置不能被解引用
}
```

这使得“当前指针还没有到达结束位置”的遍历逻辑可以表达出来，同时不会把边界标记误当成一个真实元素。

### 12.4 释放后使用和双重释放

释放堆对象后，生命周期锁会立即失效。旧指针即使仍然保存着原来的地址，也不能再访问对象：

```yian
fn main() {
    let p: i32* = dyn[1] i32
    p[0] = 42
    del p

    p[0] = 7  // trap：释放后使用
}
```

第二次释放也会失败，因为第一次释放已经使 `p` 对应的生命周期失效：

```yian
fn main() {
    let p: i32* = dyn[1] i32
    p[0] = 42
    del p
    del p  // trap：双重释放
}
```

### 12.5 内部指针不能代表整个堆对象

释放目标必须能够代表完整堆块。指向对象内部的偏移指针不能被当成整块对象释放：

```yian
fn main() {
    let p: i32* = dyn[4] i32
    let inner: i32* = p + 1

    del inner  // trap：inner 不是分配返回的对象起始指针
}
```

这样可以避免释放一个对象的中间位置，破坏运行时的堆块记录。

### 12.6 分级转换与单个元素引用

安全模式允许指针逐级减少空间信息，但每一级转换都会保留生命周期锁和生命周期键：

```yian
fn bump(r: i32&) -> i32 {
    *r = *r + 1
    *r
}

fn main() {
    let value: i32 = 41
    let p: i32* = &value

    // 显式类型标注触发 T* -> T[] 和 T* -> T& 转换。
    let view: i32[] = p
    let reference: i32& = p
    let reference2: i32& = view

    assert view.len() == 1
    assert *reference == 41
    assert *reference2 == 41
    assert bump(reference) == 42
    assert value == 42
}
```

`T&` 只表示一个已经确认存在的元素，但它仍然要检查生命周期。切片为空、指针位于 one-past 位置或来源对象已经失效时，都不能成功产生可用的 `T&`。

### 12.7 哪些视图可以释放

覆盖整个堆块的切片可以作为释放目标；指向堆对象起点的合适引用也可以触发整个堆块的释放：

```yian
fn main() {
    // 这个切片覆盖整个 dyn[4] i32 堆块，因此可以释放。
    let whole: i32[] = dyn[4] i32
    assert whole.len() == 4
    del whole

    // 一元素堆对象的起点引用也可以释放背后的整个堆块。
    let p: i32* = dyn[1] i32
    p[0] = 7
    let r: i32& = &p[0]
    assert *r == 7
    del r
}
```

下面的视图只覆盖堆块的一部分，不能释放整个堆块：

```yian
fn main() {
    let p: i32* = dyn[3] i32
    let offset: i32[] = p[1u64..3]

    del offset  // trap：offset 不是完整堆块视图
}
```

同理，指向堆对象内部元素的引用也不能作为释放目标：

```yian
fn main() {
    let p: i32* = dyn[3] i32
    let r: i32& = &p[1]

    del r  // trap：r 指向堆块内部，不是对象起点
}
```

### 12.8 函数返回后的局部变量地址

局部变量的地址只能在对应函数帧仍然有效时使用。下面的代码返回了一个局部变量的地址；函数返回后，访问这个地址会触发生命周期检查：

```yian
fn make_pointer() -> i32* {
    let local: i32 = 42
    &local
}

fn main() {
    let p: i32* = make_pointer()
    let value: i32 = *p  // trap：原函数帧已经退出
}
```

函数返回时，帧锁会先失效，然后函数帧才会结束。即使下一次函数调用恰好使用了相同的物理栈地址，新的函数帧也会使用新的生命周期键，旧指针不会因此重新有效。

### 12.9 堆块复用不会让旧指针复活

```yian
fn main() {
    let first: i32* = dyn[4] i32
    let old: i32* = first
    first[0] = 1
    del first

    let fresh: i32* = dyn[2] i32
    assert old == fresh  // 物理地址可能被空闲池复用
    fresh[0] = 2

    // 即使两者地址相等，old 仍然携带旧生命周期键。
    // let value: i32 = *old
    // trap：旧生命周期不能访问新对象

    del fresh
}
```

地址复用只改变物理存储位置，不会改变指针所代表的生命周期身份。

## 13. 一句话总结

YIAN 的安全思路可以概括为：

> 让每个指针携带自己的生命周期身份和访问范围，在每次真正触碰内存之前验证这两件事；对象释放或函数返回时立即使身份失效，内存复用时再分配新的身份。

这样，地址本身即使被复用，旧指针也不能凭借“地址看起来一样”继续访问新的对象。
