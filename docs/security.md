# SecL 内存安全语义与纸面证明

本文给出 SecL `check` 模式的安全模型、操作语义和纸面证明。编译器与 LLVM 的对应关系见
[`security-code.md`](security-code.md)。本文只声称单线程、良构 SecL 程序在受信任计算基
（TCB）正确时获得空间、时序和整数地址计算安全；`raw` 与 `nocheck` 是实验模式，不在定理
范围内。

## 1. 威胁模型

### 1.1 范围内错误

攻击者可控制程序输入及由此影响的控制流和普通数据。以下错误在范围内：

- 堆对象和栈对象的越界读写，包括访问跨度跨越对象末端；
- 指针索引、字节偏移和访问末端计算发生的有限位宽回绕；
- 释放后使用、双重释放以及函数返回后的悬垂访问；
- 堆块复用或后续函数帧复用相同物理地址后，旧指针再次被使用。

### 1.2 范围外错误

以下情况不在本文定理范围内：

- 并发数据竞争；当前运行时和堆池均为单线程设计；
- 跨 FFI 边界的对象生命周期与裸指针操作；
- 攻击者已能任意改写胖指针元数据、堆块头或帧锁槽；
- 同一函数帧内的词法内层作用域退出；当前栈失效粒度是整个函数帧；
- `unsafe`/受限标准库原语自身的实现错误。

### 1.3 TCB

TCB 包括 SecL 编译器、LLVM 后端、SecL 标准库、本文所述的单线程堆池，以及平台 ABI 和
libc `malloc` 对新物理块的分配。标准库可以使用用户程序不能调用的受限原语，因此必须单独
审计。证明还假设 LLVM 保持编译器生成的控制依赖、trap 和整数溢出检查。

检查失败转入吸收态 `trap`。进入该状态后没有后续程序步骤，也不会发生被拒绝的访问或释放。

## 2. 表示与机器状态

### 2.1 三级胖指针

设机器字和地址均为 64 位，`|T|` 是元素类型 `T` 的字节大小。`check` 与 `nocheck` 使用相同
表示：

| 类型 | 大小 | 字段 | 含义 |
| --- | ---: | --- | --- |
| `T*` | 40B | `{data, lock_ptr, key, index, size}` | `data` 为锚点，当前地址为 `data + index*|T|` |
| `T[]` / `str` | 32B | `{data, lock_ptr, key, size}` | `data` 已是切片首元素，`size` 是剩余元素数 |
| `T&` | 24B | `{data, lock_ptr, key}` | 指向一个已在构造时验证存在的 `T` 对象 |

三级表示共享 `{data, lock_ptr, key}`。降级转换只删除不再需要的空间元数据，不能提升回原级。
`raw` 模式中 `T*` 与 `T&` 是裸地址，切片仅保留 `{data,size}`，且不适用本文证明。

### 2.2 堆块头与帧锁

每个 SecL 自管堆块使用满足 ABI 对齐的固定 32B 块头：

| 偏移 | 字段 | 含义 |
| ---: | --- | --- |
| 0 | `lock: u64` | 活动键或 `SENTINEL` |
| 8 | `capacity: u64` | payload 字节容量 |
| 16 | `next: Header*` | 空闲链下一块 |
| 24 | `reserved: u64` | 保留并维持固定布局 |

块首为 `b` 时，用户 payload 起点为 `b+32`，可访问区间是
`[b+32, b+32+capacity)`。块头永不成为用户 payload。释放只把 `lock` 写为 `SENTINEL`
并把块挂入空闲链；不会把仍可能被旧胖指针引用的块头交回 libc。新分配采用 first-fit，选择
容量不小于请求的空闲块；没有合适块时才由 libc 分配新物理块。

每个活动函数帧有一个独立的 8B 帧锁槽。进入函数时写入新栈键；所有正常返回路径先写
`SENTINEL`。帧内对象的 `lock_ptr` 均指向该槽，因此当前实现的失效粒度是整个函数帧。

### 2.3 键与哨兵

令 `SENTINEL = 2^64-1`。动态键只由单调计数器产生：

- 栈键最高位为 0，键体范围为 `1 .. 2^63-1`；
- 堆键最高位为 1，键体范围为 `1 .. 2^63-2`；最后一个键体保留，以保证堆键永不等于全 1
  的 `SENTINEL`；
- 下一次生成将超出相应范围时确定性 trap；计数器绝不自然回绕。

堆与栈由最高位区分；同类键由严格递增区分。因此两个动态生命周期不会获得相同键。字符串
字面量使用永不释放的静态锁槽，不参与动态键生成和复用论证。

### 2.4 扩展机器状态

机器配置写作：

`<mu, A, Q, F, Gh, Gs, C>`

- `mu`：字节寻址存储；
- `A`：堆块表。每个块记录基址、容量，以及 `Active(k,n,T)` 或 `Free` 状态；
- `Q`：空闲链，恰好包含 `A` 中所有 `Free` 块且不重复；
- `F`：活动帧表。每帧记录锁槽、当前键及对象有效区间；
- `Gh`、`Gs`：下一堆键体和下一栈键体；
- `C`：待执行控制项。

`owner(a)` 给出地址所属的活动堆 payload 或活动帧对象；块头、空闲块 payload 和已退出帧均
没有用户对象所有权。

## 3. 谓词与不变量

### 3.1 时序有效性

对任意三级指针 `p`：

`live(p) := p.lock_ptr != 0 && mu[p.lock_ptr .. p.lock_ptr+8] == p.key`。

`live` 只检查来源生命周期。`delete`、堆复用和帧退出均通过改写锁槽使旧指针失效；转换不重复
检查 `live`，实际读取、写入或释放时才检查。

### 3.2 空间有效性与不回绕

对 `T*` 值 `p` 和跨度 `n>=1`：

`in_bounds(p,n) := index+n` 在 64 位无符号运算中不溢出，且 `index+n <= size`；同时
`index*|T|`、`n*|T|` 和字节地址末端的计算均不得溢出。

对切片 `s:T[]`，直接索引先构造 `{s.data,s.lock_ptr,s.key,i,s.size}`，随后使用同一谓词。
one-past 值可以存在和比较，但不能成功访问一个元素。

### 3.3 引用来源不变量

引用没有界字段，因此不能把其空间安全定义成“`in_bounds` 恒真”。定义：

`RefOrigin(r,T,O) := [r.data, r.data+|T|)` 在构造时完整包含于活动对象 `O` 的用户有效区间，
且 `r.lock_ptr/key` 与 `O` 的生命周期锁一致。

`RefOrigin` 只能由下列规则建立：

1. `T* -> T&`：先验证 `index < size` 及全部地址计算不溢出，再令
   `data' = data + index*|T|`；
2. `T[] -> T&`：先验证 `size >= 1`，再保留切片的 `data`；
3. `&x` 或 `&x.field`：编译器根据已知对象/字段布局建立一个元素的有效区间；
4. 从已有引用进行保持类型和生命周期的复制或字段派生。

用户代码不能凭空构造或重解释引用。只要 `live(r)` 仍成立，引用所指的一个完整 `T` 就仍属于
同一活动生命周期。引用访问因此检查 `live`，空间结论来自 `RefOrigin`，而不是一个空洞的运行时
恒真谓词。

### 3.4 原始堆指针

只有未偏移、覆盖完整活动堆对象的 `T*` 才能释放：

`is_heap(p) := msb(p.key)=1`

`is_raw(p) := p.index=0 && p.data=p.lock_ptr+32`

`delete` 还要求 `live(p)`。因此内部指针、切片、栈地址、字面量和已释放指针均不能释放。

### 3.5 全局不变量

所有从初态可达的正常状态保持：

- I1（块划分）：每个堆块的 32B 头与 payload 不相交，不同物理块不重叠；
- I2（池一致）：块恰为 `Active` 或 `Free`；`Q` 恰好且无重复地列出所有 `Free` 块；
- I3（活动锁）：活动块/帧的锁值等于其当前键，空闲块/退出帧的最后协议写为 `SENTINEL`；
- I4（键新鲜）：所有动态生命周期键互异，且均不等于 `SENTINEL`；
- I5（指针来源）：每个良构胖指针来自分配、取址、字段派生、转换或指针算术，并保留来源锁；
- I6（引用来源）：每个 `T&` 都满足 `RefOrigin`；
- I7（元数据隔离）：任何用户对象有效区间都不包含堆头或帧锁槽。

## 4. 小步语义

以下规则省略纯表达式求值。任何前提失败均一步转入 `trap`。

### 4.1 堆分配与释放

`alloc T[n]`：

1. 安全计算 `bytes=n*|T|`；
2. 从 `Q` 取第一块 `capacity>=bytes` 的块，或向 libc 请求 `32+bytes` 字节的新块；
3. 生成新堆键 `k`，耗尽则 trap；
4. 写 `header.lock=k`、保持/写入容量并清空空闲链字段，将状态设为 `Active(k,n,T)`；
5. 返回 `<b+32,b,k,0,n>`。

`delete p`：若 `live(p) && is_heap(p) && is_raw(p)`，则先写
`mu[p.lock_ptr]=SENTINEL`，把对应块从 `Active` 改成 `Free` 并插入 `Q`；否则 trap。释放不调用
libc `free`。第二次执行时 `live(p)` 已为假，故双重释放 trap。

### 4.2 帧进入、取址与退出

进入帧时生成新栈键并写入独立帧锁槽；耗尽则 trap。`&x` 返回
`<addr(x),frame.lock,k,0,1>`，数组退化返回相应数组长度，字段取址使用经布局验证的字段区间。
所有返回边在离开帧前写 `SENTINEL`，然后移除帧活动记录。

### 4.3 分级转换

对 `p:T*`：

- `T* -> T[]` 要求 `index<=size`，安全计算
  `data'=data+index*|T|`，返回 `<data',lock_ptr,key,size-index>`；
- `T* -> T&` 要求 `index<size`，安全计算同一 `data'`，返回
  `<data',lock_ptr,key>`；one-past 指针在此 trap；
- `T[] -> T&` 要求 `size>=1`，返回 `<data,lock_ptr,key>`；空切片在此 trap。

转换只证明空间来源并保留锁字段，不要求当前 `live`。因此从已经失效的源值转换可以产生同样
失效的目标值，但其后任何引用访问仍在 `live` 检查处 trap。

### 4.4 指针算术、比较与指针差

`p+i` 和 `p-i` 在数学整数意义上求候选索引；若不能表示为 `u64` 或不满足
`0<=index'<=size` 则 trap，否则仅更新 `index`。允许构造 one-past。

相等比较逐字段比较或采用编译器规定的同源地址比较，不解引用。关系比较与指针差只允许来源
锁相同且对象锚点一致的指针；随后安全计算当前字节地址。指针差必须是 `|T|` 的整数倍并能装入
结果类型，否则 trap。异源关系比较/相减没有可证明含义，故 trap。

### 4.5 读写

对 `T*` 的 `n` 元素读写，只有 `live(p) && in_bounds(p,n)` 时才计算最终地址并访问整个跨度。
切片索引通过 §3.2 的派生指针使用同一规则。对 `T&` 的一个 `T` 读写，只有 `live(r)` 时访问
`[r.data,r.data+|T|)`；空间合法性由 I6 提供。字段读写再与已验证的类型布局区间相交。

检查节点支配实际 LLVM load/store/memcpy；失败边调用 trap，故检查与访问之间没有用户代码步骤。

## 5. 纸面证明

证明对 §4 的每个规则分支做归纳。纯计算、控制流和比较不改变内存划分或锁；下面列出所有会
改变相关状态或产生指针的分支，因此不是把关键义务留给实现的证明提纲。

### 5.1 引理：不变量保持

**分配。** 新 libc 块与已有块不重叠；复用分支只从 `Q` 取 `Free` 块。两者均在 32B 头之后
建立 payload，故保持 I1/I2/I7。键生成由 §2.3 保证新鲜且非哨兵，写锁后保持 I3/I4。返回指针
由规则构造，保持 I5。

**释放。** 前提保证目标是唯一对应的活动原始块。写哨兵后旧键立即失配，块只加入 `Q` 一次，
故保持 I2/I3；没有用户区扩张，I1/I7 不变。第二次释放因 `live` 为假，走 trap 而不改变状态。

**帧规则。** 进入帧获得新键和不与对象区间重叠的锁槽；取址使用类型布局中的区间。退出先写
哨兵再移除活动记录，故旧地址即使被后续帧复用也不会在旧键下重新活动。

**算术和转换。** 算术只在 one-past 闭区间内更新索引并保留来源锁。`T*->T[]` 折叠当前位置
且将界缩为剩余长度；`T*->T&` 与 `T[]->T&` 的前提分别证明至少存在一个完整元素，因而建立
I6。所有地址计算显式拒绝回绕。复制和比较不创造新来源。

**访问。** 成功访问只修改已由谓词证明的用户区间；由 I7，该区间不含块头或帧锁。访问不改变
块表、空闲链或键生成器，故保持全部不变量。

于是由初态显然满足 I1--I7以及上述穷尽规则分支，所有可达正常状态均满足 I1--I7。

### 5.2 O-1：完整跨度与算术安全

对 `T*`，成功访问的前提显式证明 `index+n<=size`，并证明元素偏移、跨度字节数和末端地址均
不回绕，所以访问区间完整包含在来源对象有效区间中。切片先形成等价五字段视图，结论相同。
对 `T&`，I6 给出一个完整 `T` 的构造时包含关系；I3 与 `live` 说明该来源生命周期仍活动，且
活动期间对象有效区间不收缩。因此每个成功的引用访问也覆盖且仅覆盖一个完整元素。

### 5.3 O-2：失效后访问和释放均失败

释放或帧退出的第一项可观察状态更新是把来源锁写为 `SENTINEL`。由 I4，旧键不等于哨兵，故
所有携带旧键的派生指针立即满足 `!live`。每条访问规则和释放规则都以 `live` 为前提，所以随后
访问和重复释放只能 trap。转换可延迟 `live` 检查，但保留旧锁和旧键，不能改变结论。

### 5.4 O-3：键唯一、哨兵保留与确定性耗尽

在尚未耗尽时，每个计数器返回当前键体并严格加一，故同类调用不重复；最高位使堆键和栈键
不相等。堆计数器上界排除了产生全 1 字，栈键最高位为 0，也不可能等于 `SENTINEL`。到达上界
后的下一次调用按规则 trap，不执行加法，因此不存在回绕后的重复键。

### 5.5 O-4：复用不能恢复旧指针

堆复用保持同一 `lock_ptr`，但分配规则必须生成全新键 `k'`。由 O-3，`k'!=k_old`，所以旧胖
指针的 `live` 仍为假。帧地址和锁槽即使由 ABI 复用，帧进入也获得全新栈键，论证相同。物理
地址相等不蕴含生命周期相等。

### 5.6 O-5：经检查的用户写不可到达元数据

由 I1/I7，活动堆对象从 `b+32` 开始，帧对象与帧锁槽不重叠。由 O-1，任何成功用户写的完整
跨度包含在某个活动用户对象中。因此它与堆块头、空闲链元数据及帧锁槽不相交。分配、释放和
帧协议对元数据的写是 TCB 内部写，不是用户可选择地址的写。

### 5.7 主定理

**定理（SecL check 模式内存安全）。** 对任意通过类型检查、仅通过 §4 规则执行、初态满足
I1--I7 的单线程 SecL 程序，假设 TCB 正确且攻击者不能预先任意改写元数据，则每个实际执行的
用户内存读写都完整位于一个当前活动对象内且其地址计算不回绕；对已释放堆块、已退出帧的访问
及重复释放均在操作前 trap；物理堆块或帧地址复用不会恢复旧指针。

**证明。** 由 §5.1 得所有正常前缀保持 I1--I7。任取最早一个实际执行的访问，O-1 给出空间和
算术安全，O-2 给出时序有效；若其前提不满足则语义进入吸收态而访问不执行。任取释放操作，
O-2 保证目标活动且不能重复释放。O-3/O-4 排除键碰撞导致的生命周期复活，O-5 排除一个已通过
检查的用户写先破坏机制元数据。对执行步数归纳即可组合这些结论。证毕。

该证明是完整纸面证明而非机器验证。它不扩大 §1.2 的范围，也不适用于 `raw` 或 `nocheck`。

## 6. 实现代价与局限

- 堆池在进程期不向 libc 归还块；驻留内存可能随峰值增长，first-fit 且不拆块会产生内部碎片；
- 单线程空闲链没有锁或原子同步，不能直接用于并发分配；
- 帧级锁使函数内层作用域结束后对象仍活到函数返回；
- 胖指针改变 ABI，FFI 需要显式封送和独立生命周期协议；
- 标准库、编译器、LLVM 与堆池属于 TCB；
- 元数据防伪建立在攻击者尚无任意元数据写能力的前提上；
- 键空间虽大但有限；设计选择耗尽时 trap，而不是以回绕换取不安全继续执行；
- benchmark 的工作量缩放与跨编译器配置会影响性能外推，实验结论仅按已报告协议解释。
