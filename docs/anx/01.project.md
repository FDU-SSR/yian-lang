# 01 · 项目与清单

## 目录规范

```text
<项目根>/
├── package.anx           # 清单（必需）
├── src/                  # 分包源码根（必需）
│   ├── main.an           # 默认入口（仅 bin / hybrid）
│   └── utils/math.an     # 模块路径 = 相对 src/ 的路径 → utils.math
├── tests/                # 项目测试源码（可选）
│   ├── smoke.an
│   ├── output/           # 测试期望文件
│   └── input/            # 测试的进程参数与标准输入
└── build/                # 构建产物（anx 生成，不纳入版本管理）
    ├── pkg.json          # 传给编译器的包图（v2 契约）
    ├── app               # 可执行文件
    └── test/             # `anx test` 的中间产物
```

规则：

- **源码根固定是 `<包根>/src`**，清单里不可配置。它同时是「收集边界」（递归扫描 `.an`）和
  「解析基准」（`from pkg.a.b import x` → `<src>/a/b.an`）。
- **模块就是 `.an` 文件**；目录不是模块，只是路径中的一段。`src/a/b.an` → 模块 `a.b`，
  而 `a/` 目录本身没有模块名。
- `build/` 里全部是产物，可以随时删除重建（`anx new` 生成的骨架已用 `.gitignore` 忽略它）。
- 路径依赖可以落在另一个包的 `src/` 之下，但**两个包的源码根互相嵌套会报 `AX013`**，
  且文件一律归属到最深的那个源码根。

## 清单格式

```toml
[package]
name = "app"            # 必需；同时是导入时使用的第一段
kind = "bin"            # "bin" | "lib" | "hybrid"；省略视为 "bin"
entry = "src/main.an"   # 可选；仅 bin / hybrid，默认即此值
version = "0.1.0"       # 可选，默认 "0.1.0"；本阶段只做格式校验

[dependencies]
mathlib = { path = "../lib" }        # 键必须等于 ../lib 清单里的 name

[dev-dependencies]
testkit = { path = "../testkit" }    # 只有 `anx test` 看得见
```

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `name` | 是 | 合法标识符（`[A-Za-z_][A-Za-z0-9_]*`）、非空；缺失/非法 `AX002`；不得是保留名 `std`（`AX011`） |
| `kind` | 否 | 只能是 `bin` / `lib` / `hybrid`，其它取值 `AX002`；缺省 `bin` |
| `entry` | 否 | 相对包根解析，必须存在、以 `.an` 结尾、且落在该包源码根之内；不符 `AX008` |
| `version` | 否 | 版本字符串，只做格式校验，不参与任何求解 |
| `[dependencies]` | 否 | 路径依赖；键 == 被依赖包的 `name`（`AX005`） |
| `[dev-dependencies]` | 否 | 同上，但只有项目测试可见，且普通构建不编译它们 |

**包名同时就是导入名**：`[package].name = "mathlib"` 的包，只能通过 `from mathlib.… import …`
被导入；依赖不可重命名。

## `kind` 的三档语义

| `kind` | 入口 | 可否作依赖 | `build` / `run` | `check` |
| --- | --- | --- | --- | --- |
| `bin` | 必须有 | **不可以**（`AX015`） | 产出 `build/app` / 构建后执行 | 分析根包全部顶层定义 |
| `lib` | 不得有 | 可以 | **不支持**：本阶段没有库产物 | 同左 |
| `hybrid` | 必须有 | 可以（入口模块除外） | 同 `bin` | 同 `bin` |

- `lib` 声明了 `entry`，或目录里存在 `src/main.an`，都是 `AX008`。
- `bin` / `hybrid` 的入口缺失、不是 `.an`、不在源码根内，都是 `AX008`。
- 入口里**缺少 `main` 或存在多个 `main`**，由编译器报错（不是 `AX00x` 诊断）。
- 为什么 `bin` 不能作依赖：它没有对外的库接口。需要被复用的代码要做成 `lib` 或 `hybrid`。
  这一点与 Cargo 一致——bin-only crate 不能被依赖，其 `tests/` 也没有 library 可链接。
- `hybrid` 的**库接口 = 除入口之外的全部模块**；**入口模块本身不可被导入**（`AX014`）。

## 包名与目录同名时会发生什么

`import` 的第一段按**包名**解析，所以一个包里的目录名永远不会遮蔽依赖包：

```text
demo/src/dup/foo.an   ← 模块 dup.foo（本包）
vendor/dup/src/foo.an ← 包 dup 的模块 foo
```

若 `demo` 依赖了包 `dup`，那么 `from dup.foo import x` **永远**解析到依赖包 `dup`，
本包的 `src/dup/foo.an` 变成不可导入的模块。这是「第一段是包名」的必然结果，不是缺陷；
编译器会在这种情况下打印一条 `warning:` 提示，让用户改目录名或依赖名。

## 从清单到编译器

anx 加载清单后会生成 `<项目根>/build/pkg.json`（v2 契约）并交给编译器，其中每个包记录
`sourceRoot` / `kind` / `entry` / `dependencies`。这个文件内容不变时不会被重写。
契约细节见[编译脚本文档](../compile_script.md) 2.6 节。
