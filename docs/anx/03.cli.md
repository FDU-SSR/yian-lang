# 03 · 命令行

```text
anx <command> [project] [options]
```

`[project]` 是项目根目录，缺省为当前目录；`anx` 会从它向上查找最近的 `package.anx`，
因此**在项目的任意子目录里都能执行**。找不到清单时报 `error[AX001]`。

## 命令

| 命令 | 作用 |
| --- | --- |
| `anx new <name> [--kind bin\|lib\|hybrid] [--lib]` | 生成项目骨架 |
| `anx build [project] [-O n] [--release] [--raw-pointers]` | 构建可执行文件到 `<项目根>/build/app` |
| `anx build profile [project] [-O n] [--release] [--raw-pointers] [--profile-dir PATH]` | 构建并写编译统计，不运行程序 |
| `anx run [project] [-O n] [--release] [--raw-pointers] [-- args…]` | 构建后执行 |
| `anx run profile [project] [-O n] [--release] [--raw-pointers] [--profile-dir PATH] [-- args…]` | 插桩构建、执行本次产物并写运行时统计 |
| `anx check [project] [-O n] [--release] [--raw-pointers]` | 运行前端与中端检查（编译器的 `--check`），不进入 CFG/LLVM，不发射可执行文件 |
| `anx test [project] [-O n] [--release] [--pointer-mode {both,fat,raw} \| --raw-pointers]` | 运行项目自己的测试（见 [04](04.testing.md)） |
| `anx fmt [project] [--check]` | 就地格式化根包源码；`--check` 只报告差异 |
| `anx graph [project] [--json]` | 打印依赖图、文件索引与诊断 |

### `anx new`

```bash
anx new demo                # kind = "bin"
anx new mylib --kind lib    # Library without an entry point.
anx new tool  --kind hybrid # Library with a CLI.
anx new mylib --lib         # --lib is shorthand for --kind lib.
```

生成 `package.anx`、`src/`（`lib` 不生成入口）、`tests/smoke.an` + 期望文件、
以及忽略 `build/` 的 `.gitignore`。目标目录已存在时报错并退出 1。

### `anx build` / `anx run`

```bash
anx build                   # → build/app
anx build -O 3              # Optimization level.
anx build --release         # = -O 3
anx build --raw-pointers    # Bare eight-byte pointers: diagnostic mode without memory-safety guarantees.
anx run                     # Build and execute.
anx run -- alpha beta       # Pass arguments after '--' unchanged to the program.
```

- `-O` 缺省时不传，由编译器用自己的默认值（0）。
- `anx run` **继承**父进程的 stdin/stdout/stderr：程序参数与标准输入都是直接透传的。
- 根包是 `lib` 时 `build` / `run` 报「不支持」并退出 1——没有库的编译产物。

### `anx build profile`

```bash
anx build profile                    # → build/profile/<run-id>/
anx build profile -O1                # Optimization level forwarded to the compiler.
anx build profile --profile-dir reports/compile
```

`profile` 紧随 `build`，项目参数在它之后。该命令只执行一次普通编译，产物仍是
`<项目根>/build/app`，不会运行程序，也不会生成运行时插桩。报告根由 `--profile-dir` 指定；
相对路径以**项目根**为基准，绝对路径直接使用，缺省为 `<项目根>/build/profile`。每次调用都在该根下
创建唯一的 run 目录，保存 `profile.json`、`summary.txt` 和 `compiler/<序号>.json`。报告包含 anx
编排区间、compiler 等待、compiler pass、runtime/C shim 编译和链接统计。编译失败仍写入已完成和失败
阶段的部分报告；报告写入故障只打印警告，不改变编译结果。

### `anx run profile`

```bash
anx run profile                     # → build/runtime-profile/<run-id>/
anx run profile -O2 --release --raw-pointers
anx run profile --profile-dir reports/runtime -- alpha beta
```

该命令用编译器插桩构建一个独立产物到
`<项目根>/build/runtime-profile-artifacts/<run-id>/app`，然后运行**本次**产物，并写
`<报告根>/<run-id>/profile.json` 与 `summary.txt`。报告根规则与 `anx build profile` 相同，缺省为
`<项目根>/build/runtime-profile`。普通 `build/app` 不被覆盖；每次运行保留独立报告和产物。
程序参数、stdin/stdout/stderr 和运行 cwd 沿用普通 `anx run`；只有额外的报告目录提示写到 stderr。
正常退出时 anx 校验两份报告存在并显示本次报告的绝对目录；程序退出码原样返回。

统计覆盖本次进程中实际执行的根包、YIAN 依赖和标准库函数，包括方法、具体泛型实例、闭包、函数指针和
trait object 的真实动态目标。按完整调用路径聚合节点，重复路径合并，递归保留层级；函数汇总等于其所有
路径节点之和。未执行的函数不出现。耗时使用 `CLOCK_MONOTONIC` 的经过时间，单位纳秒，包含 I/O 与调度
等待；`inclusive_ns` 含子调用，`self_ns` 扣除直接计时的 YIAN 子调用。递归下函数累计值可以重叠，
因此父子累计值不能相加当作程序总时间，也不是进程墙钟总时间。采集按调用逐次计数，不做采样，不校正
插桩开销，也不展开 C/系统库或跟踪子进程。

`profile.json` 的 `format` 为 `1`，`kind` 为 `"yian-runtime-profile"`。`run` 记录本次 run id、
报告目录、产物绝对路径、指针模式和优化级别；`measurement` 记录时钟、单位、时钟分辨率、测量方法和
`overhead_compensated:false`；`functions` 按函数身份给出调用次数与两种耗时；扁平的 `call_tree` 用
`node_id`/`parent_id` 表示路径。函数身份包含包、模块、源码路径、从 1 开始的行列号（列按 Unicode
scalar value 计数）、函数/方法/闭包类别、方法所属类型、具体泛型实参和生成来源；同名函数不合并，
不同泛型实例有不同 ID。`summary.txt` 从同一聚合数据生成，包含自身耗时与含子调用耗时的热点排名、
完整调用树、单位、分辨率以及统计扰动说明。

只有 `main` 自然返回并正常收尾、且采集与报告导出无故障时才保证两份报告。`exit(0/非0)`、panic、
安全错误、资源错误、信号、崩溃或其他绕过正常返回的路径不保证报告或完整数据。采集、时钟、分配、
序列化和报告 I/O 的故障行为不作保证：可以直接终止，不承诺告警、恢复、部分报告或保留退出状态。
这些边界不改变语言既有的安全错误协议。

旧的四个 `--profile` 参数已从 `build`、`run`、`check`、`test` 移除；它们在编译或运行前作为参数
错误退出 2，并提示使用 `anx build profile`。`run` 的 `--` 之后内容属于程序，`--profile` 原样传给
程序。项目目录恰好名为 `profile` 时用 `./profile` 或绝对路径，避免与子命令关键字混淆。

### `anx check`

运行前端与中端检查，不进入 CFG/LLVM，不发射可执行文件，因此 `lib` 根包也可以 `check`。检查范围是**根包的全部顶层
定义**（未实例化的泛型体除外）；依赖包按需检查，各自的 `anx check` 负责自己。

### `anx fmt`

```bash
anx fmt                     # Format root-package sources in place.
anx fmt --check             # Report differences only; exit 1 when formatting is needed.
```

- 只处理**根包**的文件；标准库与依赖是输入，不属于本项目。
- 项目选择之后，`anx` 启动一个独立的 `yian-fmt` 子进程，传入 `-w` 或 `--check`、`--` 和根包文件的
  绝对路径；stdout/stderr 继承，格式化与摘要由该命令负责。
- 子进程返回 0 时 `anx fmt` 返回 0；任何非零、信号或启动错误都返回 1。零个根包文件打印
  `0 file(s) checked, 0 rewritten` 或 `0 of 0 file(s) need formatting` 并返回 0，不启动子进程。
- 无法格式化的文件打印 `skip <path>: cannot be formatted`；`--check` 发现差异时子进程返回 1。
- `yian-fmt` 的查找顺序是：非空 `YIAN_FMT`（显式路径或 `PATH` 名称）、调用进程同目录、`PATH`；
  显式配置无效时不回退。

### `anx graph`

```bash
anx graph                   # Text output.
anx graph --json            # Structured output.
```

载荷包含 `root`、`std`、`packages`（每包的 `kind`/`root`/`manifest`/`sourceRoot`/`entry`/
`dependencies`/`devDependencies`）、`files`（文件列表，每项含 `path`/`package`/`module`）、
`dependencies` / `devDependencies` 映射，以及 `diagnostics`。载荷**总是**打印；退出码 `1`
表示项目不可用或带诊断，`0` 表示干净。

## 退出码

| 命令 | 码 | 含义 |
| --- | --- | --- |
| `new` / `build` / `check` / `test` / `fmt` / `graph` | `0` | 成功 |
| | `1` | 用户错误：目录已存在、清单/依赖诊断、编译失败、`lib` 的 `build`/`run` 不被支持、测试失败、`fmt --check` 发现差异、`yian-fmt` 非零退出或启动失败 |
| `build profile` | `1` | 编译失败；已完成的编译统计仍尽力写入 |
| `run profile`（子进程启动之后） | 程序退出码 | 正常返回时原样传播；异常出口不保证报告 |
| `run`（子进程启动**之前**） | `0` / `1` | 同上 |
| `run`（子进程启动**之后**） | 程序自己的退出码 | **原样传播**，不做任何映射 |

所以程序调用 `exit(2)` 时 `anx run` 也退出 2，不会被当成 anx 的内部错误；
`Ctrl-C` 返回 130。

## 产物

| 路径 | 内容 |
| --- | --- |
| `<项目根>/build/pkg.json` | 传给编译器的包图（v2 契约）；内容不变时不重写 |
| `<项目根>/build/app` | `anx build` / `anx run` 产出的可执行文件 |
| `<项目根>/build/compile.log` | 编译器日志（`--log-spec` 控制详细程度） |
| `<项目根>/build/test/{fat,raw}/` | `anx test` 各模式的 package map 与可执行文件 |
| `<项目根>/build/profile/<run-id>/` | `build profile` 的 JSON 明细、文本汇总和每次 compiler 调用的独立报告 |
| `<项目根>/build/runtime-profile/<run-id>/` | `run profile` 的 `profile.json` 与 `summary.txt` |
| `<项目根>/build/runtime-profile-artifacts/<run-id>/app` | `run profile` 本次运行使用的插桩产物 |

`build/` 全部是产物，可以随时删除重建。

## 参数透传的范围

anx 只透传**白名单**内的编译器选项（`-O` / `--raw-pointers`）；`build profile` 自己转成每次调用的
`--profile-output` 路径，`run profile` 转成 `--runtime-profile-dir` 本次 run 目录。其余选项交给编译器自己的
命令行（见[编译脚本文档](../compile_script.md)）。编译器打印的警告与诊断会**原样转发**，
包括成功路径上的 `warning:`——例如包名遮蔽本包目录时的提示。
