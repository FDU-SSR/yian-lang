# 05 · 诊断目录

`anx` 的清单和项目加载诊断使用稳定的 `AX` 码，例如：

```text
error[AX005]: /path/to/lib/package.anx: Dependency key 'renamed' does not match the package name 'mylib'
  hint: Rename the key to "mylib", or rename the package to "renamed".
```

原生 `Diagnostic` 保存 code、message、可选 path 和可选 hint；它没有独立源码 span。TOML 语法错误的行列号在
message 中。诊断按路径（无路径优先）、code、message 排序。加载器会收集可独立发现的问题；普通项目命令在有
任何加载诊断时停止。`anx graph --json` 会在 `diagnostics` 数组中输出这些项目诊断，`span` 为 `null`。

## anx 诊断

| 码 | 含义 |
| --- | --- |
| `AX001` | 找不到项目根（向上没有 `package.anx`） |
| `AX002` | 清单读取、TOML 解析或字段校验失败 |
| `AX003` | 依赖路径不存在 |
| `AX004` | 依赖目录里没有 `package.anx` |
| `AX005` | 依赖 key 与目标清单里的包名不一致 |
| `AX006` | 依赖环；项目不可用，消息含环路径 |
| `AX007` | 同一包名解析到不同路径 |
| `AX008` | `src/`、`kind` 或入口文件布局错误 |
| `AX011` | 包名使用保留名 `std` |
| `AX013` | 两个包的源码根相互嵌套 |
| `AX015` | 依赖了 `kind = "bin"` 的包 |

`AX009`、`AX010`、`AX012`、`AX014` 不是当前 anx loader 诊断码。import 解析错误由 compiler 产生：
`E304` 表示导入路径没有对应模块文件，`E307` 表示导入了入口模块，`E308` 表示未知包，`E309` 表示未声明或
不可见的依赖，`E310` 表示把包名直接当成模块。它们不会进入 `anx graph` 的项目诊断数组。

## 常见例子

| 输入 | 结果 |
| --- | --- |
| 在项目外运行 `anx build` | `error[AX001]`，向上找不到 manifest |
| 依赖 key 为 `renamed`，对方清单名称为 `mylib` | `error[AX005]` |
| 依赖 `kind = "bin"` 的包 | `error[AX015]` |
| 两个包互相依赖 | `error[AX006]`，报告完整环 |
| `app` 使用未声明的 `libc` | compiler `error[E309]`，不是 anx graph 诊断 |
| `from mylib import x` | compiler `error[E310]`；包名不能代替模块路径 |

清单和项目规则见[项目与清单](01.project.md)与[依赖](02.dependencies.md)；实现模型见[开发手册 21](../manual/21.anx_manifest.md)。
