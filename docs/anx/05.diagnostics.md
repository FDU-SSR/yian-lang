# 05 · 诊断目录

anx 的诊断都带一个稳定的码，CLI 渲染成一行文本：

```text
error[AX005]: /path/to/lib/package.anx: Dependency key 'renamed' does not match the package name 'mylib'
  hint: Rename the key to "mylib", or rename the package to "renamed".
```

- **一次性全部报出**：清单/依赖类诊断不在第一个错误处中断，「全部」指所有**可独立发现**的
  诊断；出错的那棵依赖子树会被跳过，其余部分继续加载。
- **顺序稳定**：先按文件路径（无路径的排最前），再按位置起点，最后按码。同一输入下输出一致。
- 只要有一条诊断，`build` / `run` / `check` / `test` 就退出 1，不进入编译。
- 编辑器不必解析文本：`anx graph --json` 的 `diagnostics` 是同样内容的结构化形式
  （`code` / `message` / `path` / `span` / `hint`）。

## 目录

| 码 | 含义 | 产出方 |
| --- | --- | --- |
| `AX001` | 找不到项目根（向上没有 `package.anx`） | anx |
| `AX002` | 清单解析失败，或 `name` / `kind` / `entry` / `version` 的类型/取值非法（`entry` 指向的**文件**不存在是 `AX008`） | anx |
| `AX003` | 依赖的 `path` 不存在 | anx |
| `AX004` | 依赖目录里没有 `package.anx` | anx |
| `AX005` | 依赖键 ≠ 被依赖包清单里的 `name` | anx |
| `AX006` | 依赖环（致命错误，直接以完整环路径报出） | anx |
| `AX007` | 同一个包名被解析到两个不同路径 | anx |
| `AX008` | 入口或目录结构与 `kind` 不符（缺 `src/`；`bin`/`hybrid` 入口缺失、非 `.an`、在源码根之外；`lib` 声明了 `entry` 或含 `src/main.an`） | anx |
| `AX009` | 导入了本包没有声明的包（传递依赖也算） | 编译器 |
| `AX010` | 导入没有解析到 `.an` 文件（含 `from pkg import x` 这种把包当模块的写法） | 编译器 |
| `AX011` | 包名使用了保留名 `std` | anx |
| `AX012` | 未知包名：import 第一段不在包图里 | 编译器 |
| `AX013` | 任意两个包的源码根互相嵌套 | anx |
| `AX014` | 导入了某个包的入口模块 | 编译器 |
| `AX015` | 依赖了 `kind = "bin"` 的包 | anx |

`AX009` / `AX010` / `AX012` / `AX014` 由**编译器**在解析 `import` 时产出，anx 只原样转发
它的输出与退出码——因此它们不会出现在 `anx graph` 的 `diagnostics` 里（那份载荷只反映
项目与清单）。三层（anx CLI、编译器、编辑器会话）共用同一套导入解析规则。

## 常见例子

| 输入 | 输出 |
| --- | --- |
| 在项目外运行 `anx build` | `error[AX001]: no package.anx found in /tmp/x or any parent directory` |
| 依赖键写成 `renamed`，对方是 `mylib` | `error[AX005]: … Dependency key 'renamed' does not match the package name 'mylib'` |
| `app` 只声明了 `libb`，却 `from libc.secret import x` | `error[AX009]: package 'libc' is not a dependency of app; declare it in that package's [dependencies]` |
| `from mylib import x`（把目录当模块） | `error[AX010]: 'from mylib import ...' names a package, not a module; write 'from mylib.<module> import ...'` |
| 依赖了一个 `kind = "bin"` 的包 | `error[AX015]: … Dependency 'tool' has kind 'bin' and cannot be used as a dependency` |
| 两个包互相依赖 | `error[AX006]: Circular dependency: libb → appa → libb` |

## 提示（不是错误）

编译器对「包名遮蔽本包目录」会打印一条 `warning:`：当本包有 `src/dup/foo.an`，同时依赖的
包里有个叫 `dup` 的包时，`from dup.foo import …` 永远解析到依赖包。它不改变退出码，
anx 在**成功路径**上也会转发这条警告。
