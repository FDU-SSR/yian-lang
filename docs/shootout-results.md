# build/bench/shootout-results.md — shootout 基准三态性能实测 (shootout-perf-eval task-3)
> 本版数据: 2026-08-20 param-ref-copy todo 4 三态紧邻重测 (bench 参数 T*→T& 引用化后,
> commit 4b3fcdd 起)。对比上一版 (2026-08-19, edac904 前): storage 改善 (check 2.06×→2.11×
> 但绝对时间 4651→4504 ms, nocheck 2.04×→1.94×), list 劣化 (check 1.86×→2.08×,
> nocheck 1.68×→1.82×) — 归因: list 5 个 Option<Element&>& 参数函数体 `(*src).unwrap()[0]`
> 的 unwrap 由内联 CheckInBounds 变为辅助调用链 (is_none + unwrap 重建胖指针), 参数 40B→24B
> 瘦身的收益被 unwrap 重建开销抵消; 其余 12 基准倍率均在 ±2.4% 内 (噪声带)。详见
> `.omo/evidence/param-ref-copy/task-4.txt`。
## 0) 环境与协议
- 日期: 2026-08-20
- 机器: x86_64 / x86_64 / 28 逻辑核
- Python: 3.12.3 | clang: /usr/bin/clang
  `Ubuntu clang version 20.1.8 (++20250708082409+6fb913d3e2ec-1~exp1~20250708202428.132)`
  `rustc 1.91.1 (ed61e7d7e 2025-11-07)`
- 编译: ②/③ 态 `python3 -m compiler.main -O3 lib bench/shootout/<name>.an` (nocheck 加 `--no-fat-checks`); ①raw 态跨套件编译 `bench/shootout_raw/<name>.an` 加 `--raw-pointers`, 每态运行 5 次取中位数, 报告 IQR/min/max (docs/security-code.md §10.5, 同一机器同一负载)。
- 三态定义: ①raw = 裸 8B 指针 (--raw-pointers, 无锁槽/帧锁/检查, 零安全基线); ②nocheck = 胖 40B 表示但检查关 (--no-fat-checks, 保留锁槽/帧锁); ③check = 完整胖指针 (40B + 全部安全检查)。
- 维度① (raw) 来源: `bench/shootout_raw/` 套件 (T*→T[] 显式 `from_raw_parts`, 因裸模式下隐式 coerce 被拒); 与 ②/③ 同基准、同 runs/pin 协议, 跨套件组合成三态。
- 指标: 端到端墙钟时间 (ms, `time.monotonic()` 包住 `/usr/bin/time -v` 执行) + 峰值常驻内存 (Maximum resident set size, KB)。
- 倍率基准: 各态倍率 = 该态时间中位数 / 该基准 ①raw 态时间中位数 (同基准内相对, 不受机器负载影响); §2 矩阵与 §3 成本分解均以倍率呈现, ΔRSS 保持绝对 MB (内存非相对时间范畴)。
- 基准源: `bench/shootout/*.an` (14 基准, 当前胖指针语法, 迁移自 `bak/old_exp/performance`; 规模调整记录见各基准头部注释与 t1/t2 证据)。
- 降噪: `taskset -c 4` 绑定单核。

## 5) 测量说明
- 每态先 1 次 warmup (确认稳定窗口, 不计入样本), 再测 5 次取中位数。
- 自适应降次: 若某态 warmup 超过 120s, 该态测量次数降到 3。
- 维度① raw 与 `--suite raw` 套件共用同一批二进制 `build/bench/shootout_raw/<name>_raw`, 数据一致。
- 分轮执行: 全量按批次后台运行, 每轮独立落盘, 最终单次全量会话重新生成本文件 (数据一致)。
- 触发记录:
  - list/check: warmup 500.6s > 120s, 测量次数降为 3
  - list/nocheck: warmup 444.0s > 120s, 测量次数降为 3
  - list/raw: warmup 244.3s > 120s, 测量次数降为 3
