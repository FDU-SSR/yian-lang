# YIAN 设计概览

本文概述语言、编译器与工具链的设计。具体规则以
[语法说明](grammar/index.md)、[编译器手册](manual/index.md)、[anx 手册](anx/index.md) 和
[内存安全说明](security.md) 为准。

## 语言与编译器

YIAN 是静态类型语言，支持泛型、trait/impl、闭包、引用、切片和枚举。仓库提供 Python 参考编译器
`compiler/` 和以 YIAN 编写的原生编译器 `bootstrap/compiler/`；两者都实现词法、语法、语义分析、HIR、CFG
与 LLVM IR 阶段，并可生成原生程序。

模块级常量使用 `const NAME: T = expression;` 声明，可通过 `pub` 导出。常量必须标注整数、浮点、布尔、字符
或字符串标量类型（也可以使用这些类型的别名）。初始化表达式经过普通类型检查，并由编译期求值器计算；常量
支持前向引用和模块导入，循环依赖会报错。常量引用在编译期替换为字面量值，不生成运行时存储。初始化表达式
不能依赖运行时状态或函数调用，也不能产生副作用。

编译期求值器服务于常量初始化和 `comptime if`。它处理标量值、`@sizeof`、`IS_RAW_MODE`、标量转换，以及整数、
浮点和布尔运算。`comptime if` 条件必须求值为布尔值；依赖运行时状态、函数调用或副作用的条件会报错。

数组长度和泛型实参支持具体整数表达式，包括一元 `-`、`~`，二元 `+`、`-`、`*`、`/`、`%`、`&`、`|`、`^`、
`<<`、`>>` 以及括号。表达式中的整数常量必须可在编译期确定，数组长度必须非负。未实例化的常量泛型可作为
数组长度或泛型实参直接使用；涉及未实例化常量泛型的算术表达式不受支持。

trait object 使用 `Trait&` 表示。具体类型实现相应 trait 后，具体值的指针或引用可以构造 trait object；
方法调用通过 vtable 动态分派。trait object 的对象安全限制、不同指针模式下的表示与生命周期检查由类型
系统和运行时共同确定。

模式匹配适用于 `match`，也适用于 `let` 绑定、`let ... else`、`if let`、`elif let`、`while let`、`for`
迭代绑定和函数参数。编译器将若干控制流形式归约为 `match` 或普通绑定；模式包括字面量、范围、枚举与
结构体解构、元组、序列、绑定、备选项和通配符等形式。

开发工具包括 `yianc`、`anx`、语言服务器和格式化器。基准分为 C/raw/fat 三态对照，以及与 C 参考无关的
分配器专项；基准结果用于观察性能，不构成回归阈值。

C ABI FFI 允许获准的包以 `ffi fn` 封装 `extern "C"` 符号，使用 C 标量、`cptr<T>` 和受限封送操作。
raw/fat 模式下的 C ABI 一致，外部内存的有效性与资源释放由绑定负责。语言规则见
[FFI 参考](grammar/17.ffi.md)，包的 LLVM 22 链接配置见 [anx 清单](anx/01.project.md)。

fat 模式的指针携带边界与生命周期元数据，并在内存访问时执行运行时检查。raw 模式使用不携带这些运行时
安全元数据的裸指针。YIAN 不执行借用检查或生命周期推断；赋值、参数传递和返回采用浅层值复制，不隐式
释放值。安全机制的适用范围与终止行为见[内存安全说明](security.md)。

## 自举编译器与支持库

`bootstrap/compiler` 是完整的 YIAN 原生编译器，覆盖源码准备、语义分析、HIR 到 CFG、LLVM 代码生成与原生链接；
`bootstrap/anx` 是以 YIAN 编写的原生包管理器。`bootstrap/json`、`bootstrap/toml`、`bootstrap/ffi` 和
`bootstrap/llvm` 提供它们所需的数据、C ABI 与 LLVM 22 支持。

`scripts/install.sh` 先用 Python 参考编译器构建原生 `yianc`，再用该原生编译器构建 `anx`。语言服务器
`lsp/` 单独构建和安装，并使用同一套原生工具链。自举包结构、构建入口与 CLI 见[自举编译器手册](manual/30.bootstrap.md)。

## 内存安全机制的边界

fat 模式以运行时检查拒绝越界、悬垂和已释放对象访问；检查失败会终止进程，不执行栈展开或用户清理。
这些检查不跟踪未初始化数据，也不会在源代码层面排除所有无效访问意图。raw 模式不提供 fat 模式的运行时
指针检查。

静态所有权与生命周期检查、硬件能力指针以及其他生命周期撤销机制属于独立的设计议题，不是 YIAN 现有
保证的一部分。比较这些机制时，需要分别说明其检查时机、边界粒度、释放与复用语义，以及错误发生时的处置
方式。
