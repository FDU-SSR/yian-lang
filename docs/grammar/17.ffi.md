# 17 C ABI FFI

FFI 允许获准的 YIAN 包调用 C 符号。`ffi fn` 是使用 YIAN 调用约定的封装函数；`extern "C"` 声明使用 C 调用约定的外部符号。普通代码通过公开的 YIAN 签名调用封装，不直接操作 C 地址。

## 权限与可见性

包在 `package.anx` 的 `[package]` 中声明 `ffi = true`。直接使用 `yianc` 编译独立源码时传入 `--allow-ffi`。权限属于定义所在的包和函数；导入 FFI 包不会使依赖方获得 FFI 权限，普通函数也不会因调用 `ffi fn` 获得其权限。

| 声明 | 可见性与用途 |
| --- | --- |
| `ffi fn` | 同模块的 FFI 实现；函数体可以调用 C 符号和使用 FFI 内建操作 |
| `pub ffi fn` | 对普通代码公开；参数和返回值不能含 C 专用类型 |
| `pub(ffi) ffi fn` | 仅对获准的 FFI 代码公开；签名可以含 C 专用类型 |
| `extern "C" { fn ...; }` | 默认仅同模块可见；只允许在 `ffi fn` 中直接调用 |
| `pub(ffi) extern "C" { ... }` | 向获准的 FFI 代码导出 C 符号声明 |
| `opaque type Name;` | 声明没有值表示的 C 不完整类型；仅经 `cptr<Name>` 使用 |
| `pub(ffi) opaque type Name;` | 向获准的 FFI 代码导出不完整类型 |

`ffi` 也可用于有函数体的方法，包括 `static pub ffi fn`。`pub(ffi)` 不能与 `pub` 同时出现，重复或不适用的修饰符会报错。`extern "C"` 声明不能泛型化或作为函数值取得；编译期求值也不执行 C 调用。

```yian
extern "C" {
    fn abs(value: c_int) -> c_int;
}

pub ffi fn absolute(value: i32) -> i32 {
    return i32(abs(c_int(value)));
}
```

这个例子采用 [FFI 标量包用例](../../tests/package/ffi_scalar/src/main.an)中的 C 标量转换形式。公开函数仍使用普通 YIAN 类型。普通代码不能在自身签名、局部变量或表达式中构造、隐式转换和操作 C 专用类型；私有 `ffi fn` 与 `pub(ffi) ffi fn` 可以在签名中使用它们。公开结构体可在私有字段中封装 C 句柄，但公开字段不得泄露 C 类型。

## C 类型与外部签名

FFI 支持的目标为 Linux x86-64 LP64。C 标量类型的表示如下：

| 类型 | 表示 |
| --- | --- |
| `c_int` | 32 位有符号整数 |
| `c_uint` | 32 位无符号整数 |
| `c_size` | 64 位无符号整数 |
| `c_char` | 8 位有符号整数 |
| `cptr<T>` | 一个原生指针宽度；不携带 YIAN 的边界或生命周期元数据 |

`extern "C"` 的参数只接受受支持的整数、`f32`、`f64` 或 `cptr<T>`；返回值还可为 `void`。`bool`、`str`、YIAN 引用、切片、结构体和元组不能直接作为 C ABI 参数或返回值。`cptr<T>` 的元素可以是受支持的数值类型、另一 `cptr` 或不完整 C 类型；不完整类型本身不能按值传递。C 头文件中的 `int`、`size_t`、`char` 和 `LLVMBool` 等类型须由绑定作者核对并选择对应声明；编译器不读取 C 头文件验证签名。

`cptr<T>` 可以为空。同类型指针可以比较；只对大小已知的元素类型支持指针加减，偏移量以元素为单位。它不隐式转换成 `T*`、`T&` 或切片，也不自动继承 fat 模式的检查。

## 封送操作

以下内建操作只能在 `ffi fn` 中使用；名称区分大小写。

| 操作 | 结果与约束 |
| --- | --- |
| `@ffi_addr(value: T&)` | 取得 `cptr<T>`；`T` 必须是受支持的 C ABI 元素类型。`T*` 可先转换为引用。 |
| `@ffi_parts(value: T[])` | 取得 `(cptr<T>, u64)`，长度为元素数；`T` 必须是受支持的 C ABI 元素类型。 |
| `@ffi_parts(value: str)` | 取得 `(cptr<u8>, u64)`，长度为 UTF-8 字节数；不添加 NUL。 |
| `@ffi_null<T>()` | 取得空 `cptr<T>`；不完整 C 类型可作 `T`。 |
| `@ffi_ptr_cast<U>(ptr)` | 将 `cptr<T>` 显式转换为 `cptr<U>`，不改变地址或建立有效性保证。 |
| `@ffi_copy_from(dst: u8[], src: cptr<u8>, count: u64)` | 从 C 地址复制到 YIAN 切片。 |
| `@ffi_copy_to(dst: cptr<u8>, src: u8[], count: u64)` | 从 YIAN 切片复制到 C 地址。 |

地址提取会执行当前指针模式适用的 YIAN 侧检查；复制还会检查 YIAN 切片长度。`count == 0` 时不访问任一地址。C 地址的实际范围、对齐和存活期仍由 FFI 实现保证。`@ffi_parts` 返回的地址只在原 YIAN 存储保持有效且不被移动、扩容或释放时可用。需要 C 字符串时，用 `std.ffi.c_string.c_string_bytes` 创建带 NUL 的独立字节缓冲区，并在 C 调用结束后显式释放。

## 资源与支持范围

C 返回的内存不属于 YIAN 分配器。绑定需要按 C API 的所有权规则复制数据、调用对应释放函数，或把 C 句柄封装在私有字段中。YIAN 的浅复制不会复制 C 资源；拥有者只关闭一次，关闭后不得使用其副本或子视图。fat 模式的检查不追踪 `cptr<T>` 指向的外部内存。

FFI 不支持 C 回调、可变参数、C 结构体按值传递、C++ ABI、跨边界异常和外部内存零拷贝接管。原生链接配置见 [anx 清单](../anx/01.project.md)与 [编译器命令行](../compile_script.md)。
