# 13 模块系统

## Import 语法

```yian
// 包名导入（Package 模式）
from myapp.utils.math import add;
from utils.strings import join;

// stdlib 导入
from std.core.option import Option;

// 多符号导入
from std.core.ops import Add, Sub, Mul;

// 带别名
from std.core.vec import Vec as MyVec;
```

- import 语句以 `;` 结尾
- 路径使用 `.` 分隔（`std.core.option`）

## 导入路径解析

### Package 模式（anx 项目）

通过 `anx build` 构建时，第一段路径是包名，编译器从 `package.anx` 和依赖中解析：

```text
from myapp.utils.math import add    →  myapp 包的 src/utils/math.an
from utils.strings import join      →  utils 依赖包的 src/strings.an
from std.core.io import print        →  lib/core/io.an（stdlib）
```

包名→根目录映射由 anx 自动生成 `pkg.json` 并传入 `--packages`。

### Standalone 模式（直接调用编译器）

不传 `--packages` 时，import 按相对路径解析。

## `pub` 可见性

```yian
// lib/core/vec.an
pub struct Vec<T> { ... }       // 外部可访问

impl<T> Vec<T> {
    pub fn push(value: T) { }   // 外部可调用
    fn internal_helper() { }    // 仅模块内可见
}
```

- `pub` 前缀使项对外部模块可见
- 无 `pub` 的项仅在定义模块内可见

来源：`tests/private/pub_import/`、`tests/private/import_err/`

## 私有字段

```yian
pub struct Foo {
    pub x: i32,     // 外部可读写
    y: i32,         // 仅模块内可读写
}
```

来源：`tests/private/field_err/`、`tests/private/pub_field/`

## `std` 命名空间

编译器将 `from std.xxx` 映射到 `lib/` 目录：

```text
from std.core.option    → lib/core/option.an
from std.core.vec       → lib/core/vec.an
from std.collections.x  → lib/collections/x.an
from std.num.u64        → lib/num/u64.an
```

映射逻辑在 `compiler/analysis/passes/global_resolve.py:__build_std_lookup` 中。

## Prelude 自动注入

以下符号自动注入非 `lib/` 文件的编译上下文：

```yian
Option, Result, Vec, String, Range, Ordering, Ptr, Slice, Array, Never
```

无需显式 `import`。逻辑在 `compiler/analysis/passes/prelude.py`。

## 循环依赖

编译器在全局解析阶段检测类型之间的循环依赖：

```yian
// 错误示例 — 来源: tests/error/circular_dependency1.err.an
struct A { b: B, }
struct B { a: A, }      // 编译错误: 循环依赖
```

使用指针可以打破循环：

```yian
struct A { b: B*, }     // OK: 指针不产生循环依赖
struct B { a: A, }
```

来源：`tests/error/circular_dependency3.an`
