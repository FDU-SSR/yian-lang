# 06 控制流

## `if` / `elif` / `else`

```yian
let x: i32 = 10;

if x > 0 {
    return 1;
} elif x < 0 {
    return -1;
} else {
    return 0;
}
```

- 条件必须是 `bool` 类型
- `elif` 可链式使用任意次
- 不使用 `else if` —— Yian 2026 语法统一为 `elif`

来源：`tests/control_flow/`

### `if` 作为表达式

```yian
let x: i32 = 10;
let sign: i32 = if x >= 0 { 1 } else { -1 };
```

- 每个分支必须返回值
- 无 `else` 的 `if` 表达式返回 `void`
- 来源：`tests/expr_oriented/`

## `loop`

无限循环，用 `break` 退出：

```yian
let i: i32 = 0;
loop {
    if i >= 10 { break; }
    i += 1;
}
```

### `loop` 作为表达式

```yian
let i: i32 = 0;
let result: i32 = loop {
    if i >= 5 { break i; }
    i += 1;
};
assert result == 5;
```

`break value` 使 `loop` 返回该值。来源：`tests/expr_oriented/`

## `while`

条件循环：

```yian
let i: i32 = 0;
while i < 10 {
    i += 1;
}
```

`while` 在 desugar 阶段被转换为 `loop { if !cond { break; } body; }`。

## `for`-`in`

遍历实现 `IntoIterator` 的类型：

```yian
// 遍历 range
let sum: i32 = 0;
for i in 0..10 {
    sum += i;
}
assert sum == 45;           // -- 来源: tests/control_flow/for.an

// 遍历数组
let arr: i32[3] = [1, 2, 3];
for elem in arr {
    // elem: i32*
}
```

### `for`-`in` 的 desugar

编译器将 `for item in iterable { body }` 转换为：

```yian
let %iter = iterable.into_iter();
loop {
    match %iter.next() {
        Some(item) => { body },
        None => { break },
    }
}
```

因此 `for`-`in` 可用于任何实现 `IntoIterator` 的类型：range、数组、切片、`Vec`、`HashMap` 等。

来源：`tests/control_flow/forin.an`、`tests/array/forin.an`

### 迭代 Vec 的所有权

```yian
let vec: Vec<i32> = Vec<i32>.new();
// 借引用迭代（不消耗 vec）
for x in &vec { /* x: i32* */ }
```

来源：`tests/std/core/vec/iter.an`

## `break` / `continue`

```yian
for i in 0..100 {
    if i % 2 == 0 { continue; }  // 跳过偶数 — 来源: tests/control_flow/continue_for.an
    if i > 10 { break; }         // 提前退出 — 来源: tests/control_flow/break_for.an
}
```

## `defer`

`defer` 只能作为块中的语句使用，操作之后必须有外层分号。操作可以是一个表达式，也可以是一个块：

```yian
defer file.close();
defer {
    del buffer;
    file.close();
};
```

执行到 `defer` 时只登记操作，不读取其中的变量、接收者或参数；词法作用域退出时才重新求值，因此读取的是退出时的最新值。同一作用域中的操作按登记顺序逆序执行（LIFO），离开嵌套作用域时先执行内层再执行外层。

以下路径会执行当前活动作用域的清理：块自然结束、函数返回、`return`、`break` 和 `continue`。`return` 的返回值以及带值 `break` 的值会先求值并保存，再执行清理。`continue` 只清理本次迭代退出的作用域，`break` 清理至对应循环边界，不会提前清理循环外层作用域。

`panic`、运行时安全错误、`exit()` 以及被调用函数内部的异常终止不会触发清理；首个延迟操作终止程序时，较早登记的操作也不会继续执行。延迟操作中不允许 `return`、`break`、`continue` 或再次登记 `defer`。延迟操作中的变量读取必须在登记点已经 definitely assigned；其中的赋值不会改变后续代码的初始化判断。

## 嵌套控制流

```yian
for i in 0..10 {
    if i % 2 == 0 { continue; }

        j += 1;
    }
}
```

## `panic`

```yian
panic("unreachable");
```

类型为 `never`，可用于任何期望值的位置：

```yian
fn fail() -> i32 {
    panic("not implemented");   // 不需要 return
}
```

`panic` 表示程序显式放弃继续执行，与编译器在非法内存操作前触发的安全错误不同。两者统一使用非零进程退出状态，但通过不同的诊断前缀区分，并且都不会触发栈展开或隐式 `Drop`。完整约定见[运行时错误与安全终止](16.runtime_errors.md)。
