# 14 标准库

Yian 标准库的包根是 `lib/`（清单 `lib/package.anx`），源码根是 `lib/src/`，通过 `std` 包名访问。

## `core::option` — `Option<T>`

可选值：`Some(val)` 或 `None`。

```yian
let some: Option<i32> = Option<i32>.Some(42);
let none: Option<i32> = Option<i32>.None;

assert some.is_some();
assert !none.is_some();
assert *some.unwrap() == 42;
assert *some.unwrap_or(&0) == 42;
assert *none.unwrap_or(&0) == 0;

let borrowed: Option<i32&> = some.as_ref();
assert **borrowed.unwrap() == 42;
assert none.as_ref().is_none();
```

方法：`is_some()`, `is_none()`, `unwrap() -> T&`, `unwrap_or(default: T&) -> T&`, `as_ref() -> Option<T&>`, `take()`, `replace(val)`, `clone()`。

`unwrap`/`unwrap_or` 返回载荷的引用，值上下文用 `*` 取载荷；`unwrap_or` 的 `default` 是引用参数，调用点可写 `&值`。`as_ref()` 把 `Option<T>&` 转成 `Option<T&>`，不复制载荷；通过该引用可直接读写原值。

来源：`lib/src/core/option.an`、`tests/basic/std/core/option.an`

`unwrap` 系列返回载荷的引用；`unwrap_*` 的 `default` 是 `T&`/`E&`。

来源：`lib/src/core/result.an`、`tests/basic/std/core/result.an`

## `core::vec` — `Vec<T>`

动态数组。

```yian
let v: Vec<i32> = Vec<i32>.new();
v.push(1);
v.push(2);
v.push(3);
assert v.len() == 3;
assert v[0] == 1;
assert *v.pop().unwrap() == 3;
```

方法：`new()`, `with_capacity(n)`, `take()`, `push(v)`, `pop()`, `insert(i, v)`, `remove(i)`, `swap_remove(i)`, `extend(other)`, `extend_from_slice(s)`, `truncate(n)`, `clear()`, `reserve(n)`, `spare(n)`, `advance_len(n)`, `shrink_to_fit()`, `as_slice()`, `len()`（经 `Deref<T[]>`）, `capacity()`, `is_empty()`, `clone()`。

`Vec<T>` 的普通赋值是浅复制；`clone()` 只复制 Vec 自己管理的元素缓冲区，元素自己拥有的资源不递归复制。`clear()`、`truncate()` 和显式 `drop()` 只管理 Vec 自身的存储，不会调用元素的 `Drop`；需要释放元素资源时由调用者在元素仍可访问时显式处理。`pop()`、`remove()` 和 `swap_remove()` 返回元素，调用者可自行清理。

`extend(other: Vec<T>&)` 和 `extend_from_slice()` 按字节浅复制元素缓冲区。`v.extend(&v)` 支持自扩展。`extend_from_slice()` 的源切片不得借用接收者的缓冲区。
`take()` 返回当前缓冲区并把接收者置为空 Vec；源值不再管理被取出的缓冲区。

`new()` 与 `with_capacity(0)` 不分配堆块。普通元素的空视图使用 `@dangling<T>()` 的非零对齐地址，可参与零长度的指针算术与传递，实际元素访问会越界。零大小元素只占逻辑长度，容量为 `u64.max()`，不分配元素缓冲区。

`as_slice()` 只覆盖当前长度。`spare(n)` 保证至少还有 `n` 个槽位，并返回第一个剩余槽位的指针。调用者写入元素后用 `advance_len()` 更新长度。重分配或释放缓冲区会使原有视图失效。

实现 `Index<u64, T&>`、`Deref<T[]>`、`Add<Vec<T>, Vec<T>>`、`PartialEq<Vec<T>>`、`From<T[]>`、`Clone`、`Drop`、`Hash<Murmur3Hasher>`。`T: Format` 时 `Vec<T>` 实现 `Format`，切片通过 `Into<Vec<T>>` 转成 Vec。

来源：`lib/src/core/vec.an`、`tests/basic/std/core/vec/`

## `core::str` — `str`

不可变 UTF-8 字符串切片（内置类型）。

```yian
let s: str = "hello";
let bytes: u8[] = s.as_slice();
let chars: CharIter = s.chars();
```

函数/方法：`from_slice(bytes) -> Option<Self>`（带 UTF-8 验证）、`from_slice_unchecked(bytes) -> Self`、`as_slice()`, `chars()`, `char_indices()`, `is_char_boundary(i)`, `starts_with(prefix)`, `starts_with_char(c)`, `ends_with(suffix)`, `ends_with_char(c)`, `find(needle)`, `rfind(needle)`, `contains(needle)`, `contains_char(c)`, `find_char(c)`, `split(sep)`, `trim()`, `parse<T>()`。

`from_slice` 内部用 `is_valid_utf8` 校验，ASCII 段落按 8 字节整字跳过。`chars()` 返回 `CharIter`，其 `rev()` 返回 `RevCharIter`；两者按 UTF-8 序列解码字符，不提供 `len` 成员。`char_indices()` 返回产生 `(u64, char)` 的 `CharIndicesIter`。`split(sep)` 返回实现 `Iterator<str>` 的 `SplitIter`，`sep` 不能为空。

实现 `From<u8[]>`、`Into<u8[]>`、`PartialEq<str>`、`Index<Range<u64>, str>`、`Hash<Murmur3Hasher>`、`Format`。`ToString` 由 `Format` 的统一实现提供。

来源：`lib/src/core/str.an`、`tests/basic/std/core/str.an`

## `core::iter` — 迭代器

```yian
pub trait Iterator<T> {
    fn next() -> Option<T>;
}

pub trait IntoIterator<T> {
    fn into_iter() -> T;
}
```

`IteratorExt<T>` 为实现 `Iterator<T>` 的类型提供适配器，使用时导入该 trait：

| 方法 | 结果与行为 |
|------|------------|
| `peekable()` | `Peekable<I, T>`，`peek()` 与 `peek_next()` 返回前两个缓存元素的引用 |
| `map<F, U>(f)` | `Map<I, T, U, F>`，逐项调用 `f` |
| `enumerate()` | `Enumerate<I, T>`，产生从 0 开始的 `(u64, T)` |
| `take(count)` | `Take<I, T>`，最多产生指定数量的元素 |
| `fold<A, F>(initial, f)` | 持续调用 `f(累积值, 元素)`，返回累积值 |

适配器浅复制迭代器与闭包值；共享的底层资源仍由调用者管理。`Peekable.take_buffered()` 取出两个
缓存 `Option<T>`，便于在提前结束迭代时处理已缓存的资源。

## `core::clone` / `core::drop`

```yian
pub trait Clone { fn clone() -> Self; }
pub trait Drop { fn drop(); }
```

标量类型由标准库显式实现 `Clone`，但不提供空操作的 `Drop`；只有需要释放自身资源的类型才实现 `Drop`。`String`、`Vec<T>` 等类型按自身接口约定复制自己管理的缓冲区并清理自身资源，容器的 `Drop` 不会递归调用元素的 `Drop`。原始指针、切片和 `str` 没有默认 `Clone`。语言不会自动调用 `Drop`。`Clone` 与 `Drop` 均由 prelude 提供，非标准库模块无需显式导入。

来源：`lib/src/core/clone.an`、`lib/src/core/drop.an`

## `core::fmt` — `Format` / `Formatter` / `ToString`

```yian
pub enum Alignment { Default, Left, Right }
pub enum ParameterKind { Width, Precision }
pub enum PaddingKind { Text, Number, SpecialNumber }

pub struct FormatSpec {
    pub alignment: Alignment,
    pub zero_pad: bool,
    pub width: u64,
    pub precision: Option<u64>,
}

impl FormatSpec {
    pub static fn new() -> Self;                       // Default, 不补零, 宽 0, 无精度
    pub fn validate() -> Result<(), IoError>;
    pub fn require_default() -> Result<(), IoError>;
}

pub fn check_signed(value: i64, kind: ParameterKind) -> Result<u64, IoError>;
pub fn check_unsigned(value: u64, kind: ParameterKind) -> Result<u64, IoError>;

pub trait Format {
    fn fmt(out: Formatter&, spec: FormatSpec&) -> Result<(), IoError>;
}

pub struct Formatter { /* writer: Write& */ }

impl Formatter {
    pub fn write_str(text: str) -> Result<(), IoError>;
    pub fn write_value<T>(value: T&, spec: FormatSpec&) -> Result<(), IoError>;
    pub fn write_padded(text: str, spec: FormatSpec&, kind: PaddingKind) -> Result<(), IoError>;
}

pub trait ToString { fn to_string() -> String; }
// impl<T> ToString for T if T: Format
```

类型作者显式实现一次 `fmt`，接收当前字段的规格，写入固定文本并按需递归格式化成员。自定义类型的首版插值只接受无规格；成员使用显式默认规格：

```yian
struct Point { x: i32, y: i32 }

impl Format for Point {
    fn fmt(out: Formatter&, spec: FormatSpec&) -> Result<(), IoError> {
        spec.require_default()?;
        let inner = FormatSpec.new();
        out.write_str("Point(")?;
        out.write_value(&self.x, &inner)?;
        out.write_str(", ")?;
        out.write_value(&self.y, &inner)?;
        out.write_str(")")
    }
}
```

`Formatter` 只借用当前目标，不拥有、不刷新、不关闭外部流，也不保存字段规格。`write_value` 以 `Format` trait 分派，同名的 inherent 方法不会截获成员格式化。`to_string()` 是统一的拥有型便利转换，内部使用默认规格；所有实现 `Format` 的类型都获得该转换。

`validate()` 拒绝超界参数（宽度大于 65535、精度大于 1024）和 `<` 与补零的组合；`require_default()` 先校验，再要求所有字段等于 `FormatSpec.new()`，否则返回 `IoErrorKind.InvalidInput`。`check_signed`/`check_unsigned` 保留原值范围检查并返回 `u64`。`write_padded` 写一个完整字段：`Text` 按 Unicode 标量计宽、默认左对齐、拒绝补零与精度；`Number` 接受已完成转换的 ASCII 数值文本、默认右对齐、支持补零且负号在填充之前；`SpecialNumber` 用于 `NaN`/`inf`/`-inf`，默认右对齐但始终空格填充。填充按固定大小分块写入，不按宽度分配缓冲。

printf 风格的选择由插值规格表达，`tests/basic/fmt/` 中 `f"{value:08.2f}"`、`f"{count:05}"` 等用例覆盖成功路径，`spec_syntax.err.an`、`spec_type.err.an`、`spec_bound.err.an` 与 `ordered.an` 覆盖诊断和失败短路。

格式化入口是语言内建，不需要导入：

```yian
let text: String = f"point={point}";          // 结果是 String
let plain: str = "literal {braces}";
let owned: String = String.from(&"owned");
@append(&buffer, f"point={point}");           // 追加到已有 String
let result: Result<(), IoError> = @write(&stream, f"point={point}");
@print(plain);                                // 等价于 f"{plain}"
@print(owned);                                // 等价于 f"{owned}"
@print(42);                                   // 等价于 f"{42}"
@print("literal {braces}");                   // 字面量模板，花括号原样输出
@println(f"point={point}");
@eprintln("diagnostic");
```

- `@print`/`@println`/`@eprint`/`@eprintln` 的参数如果是 f-string 或普通字符串字面量，就作为模板；其他表达式在前端等价于 `f"{p}"`，因此任何实现 `Format` 的类型（`str`、`String`、数字、容器等）都可以直接传给打印入口。普通字面量中的花括号只作文本。
- `@append`/`@write` 的模板仍必须是 f-string 或普通字符串字面量，不接受其他表达式。
- `@append` 的目标是 `String&`，`@write` 的目标是 `W&`（`W: Write`）、trait object 或已有 `Formatter&`。目标先求值且仅一次。
- `@append` 和四个打印入口返回 `()`；`@write` 返回 `Result<(), IoError>`。没有错误返回类型的入口在写入或最终排出失败时 `@panic`。
- `@write` 不添加隐藏缓冲、不调用目标 `flush()`，部分写入沿用 `Write.write_all` 的规则。四个打印入口使用固定的 1024 字节自有缓冲，满时排出，正常返回前显式排出并检查结果。
- 模板按源码顺序处理；每个位置只在到达时求值并格式化一次，检测到失败后不执行后续位置。非模板参数包装后同样只求值一次。

标准库为以下类型提供 `Format`：

| 类型 | 默认文本 |
|------|----------|
| `u8`/`u16`/`u32`/`u64`、`i8`/`i16`/`i32`/`i64` | 十进制；有符号最小值不经过有符号取负 |
| `f16`/`f32`/`f64` | 对应位宽的最短往返文本；`f16` 按 binary16 自身精度，不先扩宽；负零 `-0`、`NaN`、`inf`、`-inf` |
| `bool` | `true` / `false` |
| `char`、`str`、`String` | 原样输出，不加引号或转义 |
| 数组、切片、`Vec<T>` | `[a, b]`，空为 `[]` |
| 0～4 项元组 | `()`、`(a,)`、`(a, b)`，项间逗号加一个空格 |
| `Option<T>` | `Some(x)` / `None` |
| `Result<T, E>` | `Ok(x)` / `Err(e)` |
| `HashMap<K, V>` / `HashSet<T>` | `{k: v, k2: v2}` / `{x, y}`，空均为 `{}`；沿用现有迭代顺序，不额外排序 |
| `void` | `void`（与空元组类型区分） |

组合类型的每个成员都必须实现 `Format`；缺少实现时在插值位置报告编译错误。`f32`/`f64` 的默认拼写沿用既有实现，科学计数法在指数小于 -6 或大于等于 21 时使用。`HashMap`/`HashSet` 不保证元素顺序。

无规格时上表表示保持不变；非空规格只适用于上表中的整数、浮点、`char`、`str`、`String`，容器的成员始终使用默认规格。浮点在 `precision` 存在时输出精确十进制展开并按最近值取偶舍入；没有 `precision` 时保持最短往返文本。整数拒绝精度。文本按 Unicode 标量计宽，组合字符分别计数，不保证终端列宽。

插值不会自动解引用 `T*` 或 `T&`；这两类值都需要显式 `*`。`@print(reference)` 等价于 `f"{reference}"`，会报告 `type 'i32&' does not implement 'Format'`；`@print(*reference)` 或 `f"{*reference}"` 才格式化引用指向的值。

来源：`lib/src/core/fmt.an`、`lib/src/num/format/ryu.an`、`tests/basic/std/core/fmt/`、`tests/basic/fmt/`

## `core::io` — I/O

```yian
from std.core.io import File, OpenMode;

@print("Hello\n");
@println("Hello");
@eprint("diagnostic\n");
@eprintln("diagnostic");

let file = File.open("/tmp/example.txt", OpenMode.Read).unwrap();
```

来源：`lib/src/core/io.an`、`tests/basic/std/core/io/`

同步 IO 使用 `Result<成功类型, IoError>` 报告错误。`IoError.kind()` 返回 `IoErrorKind`，
`msg()` 返回消息视图，`raw_os_error()` 返回可选的操作系统错误码；错误拥有消息存储，需要显式 `drop()`。

| 接口 | 行为 |
|------|------|
| `Read` | `read(u8[])` 返回实际字节数，`read_exact()` 读满缓冲区，`read_to_bytes()`/`read_to_string()` 读到 EOF |
| `Write` | `write(u8[])` 返回实际字节数，`write_all()`/`write_str()` 写完数据，`flush()` 刷新流 |
| `Seek` | `seek(SeekFrom.Start/Current/End)` 返回新的文件位置 |
| `File` | `open(path, OpenMode)`、`fd()`、`close()`、`metadata()`、`set_len()`、`sync_all()`，实现 `Read`/`Write`/`Seek`/`Drop` |
| `OpenOptions` | 链式设置 `read`、`write`、`append`、`create`、`truncate`、`create_new` 后 `open(path)` |
| `Stdin`/`Stdout`/`Stderr` | `new()` 取得进程标准流包装，不拥有文件描述符 |
| `BufRead` | `read_until(delimiter)` 返回包含分隔字节的 Vec；`read_line()` 返回 `Option<String>`，EOF 为 `None`，保留行末换行 |
| `BufReader<R>` | 借用 `R&`，拥有读取缓冲区，默认容量 8192 字节 |
| `BufWriter<W>` | 借用 `W&`，拥有写入缓冲区；`flush()`/`finish()` 提交缓冲数据 |

`BufReader` 与 `BufWriter` 的 `drop()` 只释放缓冲区，不释放底层流；`BufWriter.drop()` 不自动刷新。
调用者应让底层流覆盖包装器的使用期，并在释放写缓冲区前显式处理 `flush()` 或 `finish()` 的结果。
`File.close()` 将描述符置为失效状态，同一个 File 值重复关闭可成功；浅复制 File 值不能产生独立的描述符所有权。
格式化输出入口 `@print`/`@println`/`@eprint`/`@eprintln` 分别写 stdout/stderr，参数是静态模板，
`println`/`eprintln` 在最后追加单个 LF。它们使用固定的 1024 字节自有缓冲，正常返回前显式排出；写入或排出
失败都会 `@panic`（退出码 1）。失败后不再执行模板中后续的位置。`@write` 面向可失败流并保留
`Result<(), IoError>`，不强制刷新或关闭目标；`@append` 面向已有 `String&` 并返回 `()`。
这些入口是语言内建，不需要导入；`std.core.io` 只提供可失败的 `Write` 流接口，不提供普通打印函数。native 编译器对显式导入 prelude
符号给出 `W502` 警告；警告不阻止编译。错误和警告都使用多行源码片段：

```text
warning[W502]: unnecessary import of 'Option': the prelude already provides it
--> src/main.an:1:29
    from std.core.option import Option;
                                ^^^^^^
```

## `core::fs` / `core::path` — 文件系统与路径

`fs` 提供 `metadata`、`symlink_metadata`、`try_exists`、`create_dir`、`create_dir_all`、
`remove_file`、`remove_dir`、`rename`、`current_dir`、`canonicalize`、`read`、`read_to_string`、
`write`、`write_string`、`write_atomic` 和 `append`。路径参数为 `str`，结果使用 `Result<_, IoError>`。
`write_atomic(path, data)` 在目标目录创建独占临时文件，完整写入并关闭后替换目标；失败保留旧目标并清理
自己的临时文件。调用者负责创建父目录；不承诺 `fsync`。
`metadata` 跟随符号链接，`symlink_metadata` 查询链接本身。

`Metadata` 提供文件类型、长度与 `(秒, 纳秒)` 修改时间。`Directory.open(path)` 打开目录；
`next()` 返回 `Result<Option<DirEntry>, IoError>`，`None` 表示遍历结束；`close()` 或显式 `drop()` 关闭句柄。
`DirEntry` 提供 `name()`、`path()`、`kind()` 与元数据查询，显式 `drop()` 释放名字和路径存储。

`Path.new(str)` 是借用视图，提供 `as_str()`、`is_absolute()`、`file_name()`、`parent()`、
`extension()`、`join()` 与 `with_extension()`；这些方法进行路径文本操作，不访问文件系统。
`PathBuf` 拥有字符串存储，提供 `new()`、`from(str)`、`as_path()`、`as_str()`、`push()`、
`into_string()` 和显式 `drop()`。借用视图不能超出底层字符串的有效期。

来源：`lib/src/core/fs.an`、`lib/src/core/path.an`、`tests/basic/std/core/io/filesystem.an`

## `core::try` — 错误传播

后缀 `?` 通过 `Try<Output, Residual>` 与 `FromResidual<Residual>` 分派。
`TryBranch<Output, Residual>` 的 `Continue` 产生输出，`Break` 使当前函数提前返回。
`Option<T>` 与 `Result<T, E>` 的值形式产生 `T`，引用形式产生 `T&`。
Result 的错误转换要求目标错误类型实现 `From<E>`；Option 与 Result 之间没有自动残差转换。

来源：`lib/src/core/try.an`，语法见[表达式](08.expressions.md)。

## `memcpy` 内建

标准库不提供内存操作模块；`@memcpy` 是编译器提供的受限内建，供标准库内部按字节复制：

```yian
@memcpy(dest: T*, src: U*, count: u64);
```

长度以字节为单位。native fat 模式在复制前检查两端的活性和完整字节跨度，零长度
复制不访问内存。调用方须保证两段非空范围互不重叠。

来源：`yianc/src/analysis/lowering/builtins.an`、`yianc/src/codegen/llvm/pointer/checks.an`

## `collections::arena`

`Arena<T>` 按分配顺序存放元素。`alloc(value)` 返回 `T&`，后续分配保持该引用所指的地址。`get(index)` 从 0 开始按索引读取，越界时返回 `None`。迭代按分配顺序进行。已越过末块的迭代器会跳过追加到该块的元素，并可在后续新块开始时继续。

`clear()` 和 `drop()` 释放 Arena 的块和目录，使已有元素引用及迭代器失效。调用者负责在释放存储前显式清理元素资源。Arena 清空后可重新分配。零大小元素同样计入长度并可通过索引和迭代访问。

来源：`lib/src/collections/arena.an`

## `collections::hash_map` / `hash_set`

```yian
let map: HashMap<MyKey, i64> = HashMap<MyKey, i64>.new();
map.insert(key, 100);
assert **map.get(&key).unwrap() == 100;

let set: HashSet<i64> = HashSet<i64>.new();
set.insert(42);
assert set.contains(&42);
```

哈希容器的 `clear()` 和删除更新控制区及计数，显式 `drop()` 释放自身表存储。元素资源由调用者显式清理。`HashMap<K, V>.clone()` 与 `HashSet<T>.clone()` 复制容器自己管理的控制区和已分配的桶存储，键值仍按浅复制处理。普通赋值共享底层存储。

只在表结构保持稳定时使用元素引用和迭代器。扩表后元素位于新表中，胖指针模式会拒绝通过旧引用访问已释放的非零大小元素。Map 和 Set 的容量构造向上取整到 2 的幂，超过 `2^63` 的请求在分配前报告 R001。

来源：`lib/src/collections/hash_map.an`、`lib/src/collections/hash_set.an`、`tests/basic/std/collections/`
