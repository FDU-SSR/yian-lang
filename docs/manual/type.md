# 类型系统

此文件阐述 `yian` 的类型系统以及与之相关的各种机制

## 类型汇总

### 基本类型

数字类型:

- 有符号整数: `i8`, `i16`, `i32`, `i64`, `i128`(暂未支持)
- 无符号整数: `u8`, `u16`, `u32`, `u64`, `u128`(暂未支持)
- 浮点数: `f32`, `f64`

其他基本类型:

- `void`: 无类型, 目前仅用于函数的返回类型
- `bool`: 布尔类型, 取值为 `true` 或 `false`, 占用 1 字节
- `char`: 字符类型, 表示一个 Unicode 字符, *占用 4 字节*
- `str`: 字符串类型, 是指向字符串的切片, 不可通过该切片修改字符串内容, 占用 16 字节, 包含指向字符串数据的指针和字符串的长度

### 派生类型

#### 数组类型

固定长度的同类型元素的集合, 声明方式为 `T[N]`, 其中 `T` 为数组元素的类型, `N` 为数组的长度, 必须是一个常量. 下面的例子都是合法的:

```text
i32[10]     // 包含 10 个 i32 元素的数组
f64[5]      // 包含 5 个 f64 元素的数组
bool[0]     // 空数组, 不包含任何元素
```

可以使用 `[]` 运算符配合一个索引表达式来访问数组中的元素

1. 数组的索引从 `0` 开始, 到 `N-1` 结束
2. 访问数组时, 索引表达式的值必须在合法范围内, 否则会引发运行时错误
3. 索引表达式必须是正的整数字面量或者 `u64` 类型的变量

#### 元组类型(暂未实现)

不同类型元素的集合, 声明方式为 `(T1, T2, ...)`, 其中 `T1, T2,...` 分别为各个元素的类型. 下面的例子都是合法的:

```text
(i32, f64, bool)    // 包含一个 i32, 一个 f64, 和一个 bool 元素的元组
(char, str)         // 包含一个 char 和一个 str 元素的元组
()                  // 空元组, 不包含任何元素
```

可以使用 `[]` 运算符配合一个索引表达式来访问元组中的元素

1. 元组的索引从 `0` 开始, 到 `N-1` 结束, 其中 `N` 为元组中元素的个数
2. 访问元组时, 索引表达式的值必须在合法范围内, 否则会引发编译时错误
3. 索引表达式必须是正的整数字面量

#### 指针类型

存储另一个值的地址, 声明方式为 `T*`, 其中 `T` 为指针指向的类型, 下面的例子都是合法的:

```text
i32*        // 指向 i32 类型值的指针
(i32, f64)* // 指向 (i32, f64) 类型元组的指针
i8**        // 指向 i8* 类型指针的指针
```

通过解引用运算符 `*` 可以访问指针所指向的值, 解引用运算的结果是一个 `T` 类型的左值

#### 函数指针类型

存储函数地址的指针, 声明方式为 `fn<RT(T1, T2, ...)>`, 其中 `T1, T2,...` 为函数的参数类型, `RT` 为函数的返回类型, 下面的例子都是合法的:

```text
fn<i32(i32, i32)>      // 指向一个接受两个 i32 参数并返回一个 i32 值的函数的指针
fn<void()>             // 指向一个不接受参数且无返回值的函数的指针
```

对一个函数取地址, 可以得到一个对应的函数指针

#### 函数类型

用于表示一个函数的类型, 不存在声明方式, 通过以下方式可以得到一个函数类型变量:

```text
i32 add(i32 a, i32 b) {
    return a + b;
}

main() {
    func = add  // func 为函数类型变量
    fn<i32(i32, i32)> func_ptr = &add  // func_ptr 为函数指针类型变量
}
```

与函数指针的区别:

- 函数类型变量表示一个具体的函数, 而函数指针类型变量表示一个指向函数的指针
- 任意两个不同的函数, 他们对应的函数类型是不同的, 即使它们的参数和返回类型完全相同
- 函数类型变量是函数本身的**零开销引用**, 而函数指针类型变量则需要通过解引用来调用函数, 会有一定的性能开销
- 函数类型的大小为 0 字节, 而函数指针类型的大小为 8 字节(在 64 位系统上)

#### 闭包类型（暂未实现）

闭包是一种可以捕获其定义环境中变量的匿名的函数对象, 不存在声明方式, 通过以下方式可以得到一个闭包类型变量:

```text
closure = |[参数列表]| [-> 返回类型] {
    [函数体]
}  // bys: 再思考一下语法
```

- 参数列表和函数体，和一般的函数调用格式一致
- 返回类型为`void`时，`->`符号也要省略，否则不可省略
- 闭包本质是一个携带其捕获变量的结构体类型实例，结构体中包含一个`call`方法用于执行闭包逻辑
- 任意两个闭包, 即使它们的参数和返回类型完全相同, 他们对应的闭包类型也是不同的

### 自定义类型

#### 结构体类型

由多个字段组成的复合类型, 其可能的取值数量为各字段取值数量的**乘积**, 声明的格式:

```text
[访问限定符] struct 结构体名 {
    [访问限定符] [类型1] [成员1]
    [访问限定符] [类型2] [成员2]
    ...
}
```

- 结构体名: 必须是一个合法的标识符
- 成员: 多个成员之间用**换行符**分隔
- 结构体不能直接或间接的包含自身

#### 枚举类型

由多个变体组成的复合类型, 其可能的取值数量为各变体取值数量的**加和**, 声明的格式:

```text
[访问限定符] enum 枚举名 {
    [变体1]
    [变体2]
    ...
}
```

变体的格式为:

```text
变体名 {
  [类型1] [成员1]
  [类型2] [成员2]
  ...
}
```

- 枚举名: 必须是一个合法的标识符
- 变体: 至少要有一个变体
  - 变体名必须是一个合法的标识符
  - 变体可以选择携带一个负载, 负载的类型为结构体类型
  - 负载可以包含若干个字段声明, 与结构体的字段声明方式一致, 但是不能加访问限定符

#### `trait` 类型

用于定义接口, 声明的格式:

```text
[访问限定符] trait 特征名 {
  [函数声明/函数定义1]
  [函数声明/函数定义2]
  ...
}
```

- 特征名: 必须是一个合法的标识符
- 函数声明/函数定义: *不能包含访问限定符, 因为 trait 中的函数都是公开的*

### 泛型

`yian` 所支持的泛型是**单态化泛型(Monomorphized Generics)**, 即在编译时根据具体的类型参数生成对应的具体类型或函数实例, 而非在运行时进行类型擦除和动态分发.

在以下区域, 允许声明泛型列表:

- 结构体定义
- 枚举定义
- 函数定义
- 方法定义
- trait 定义
- impl 块定义
- 类型别名定义

泛型列表的语法格式为:

```text
<类型参数1, 类型参数2, ...>
```

每个类型参数必须是一个合法的标识符, 并且在同一泛型列表中不能重复

## 类型系统

`yian` 作为静态类型的语言, 一个变量所拥有的信息包括其**类型**和**值**, 类型信息在编译时确定, 值信息在运行时确定. 看下面的例子:

```text
i32[10] arr
```

变量 `arr` 包含的信息如下:

- 编译时确定:
  1. 数组元素的类型是 `i32`
  2. 数组包含 10 个元素
- 运行时确定:
  1. 数组中每个元素的具体值

编译时确定的信息是不需要占用运行时内存的, 因此变量 `arr` 在运行时只需要占用 80 字节(10 个 i32 元素, 每个 i32 占用 4 字节)

基于上面的分析, 我们可以设想一种变量, 它在编译时就确定了所有的信息, 运行时不需要维护任何信息, 那么这种变量在运行时就不需要占用任何内存空间, 这种变量的类型被称为**零大小类型(Zero-Sized Types, ZST)**

通过函数类型与函数指针类型的对比, 我们可以看到零大小的变量在某些场景下是非常有用的, 因为它们可以避免不必要的内存开销和性能损失:

1. 函数指针类型:
   1. 编译时确定:
      1. 函数的参数类型和返回类型
   2. 运行时确定:
      1. 函数的地址
   3. 运行时内存开销: 8 字节(在 64 位系统上)
2. 函数类型:
   1. 编译时确定:
      1. 函数的参数类型和返回类型
      2. 函数的地址
   2. 运行时确定: 无
   3. 运行时内存开销: 0 字节

总体来说, 将越多的信息在编译时确定, 可以带来更好的性能和更低的内存开销; 将越多的信息在运行时确定, 可以带来更高的灵活性和更强的表达能力.

### 零大小类型(Zero-Sized Types)(暂未实现)

零大小类型(Zero-Sized Types, ZST)是指其大小为 0 字节的类型, 这些类型的实例不占用任何内存空间, ZST包括:

- `void` 类型
- 空结构体类型(不包含任何字段, 或者所有字段均为ZST的结构体)
- 空枚举类型(不包含任何变体的枚举, 或者只有一个变体且该变体没有负载或负载为ZST的枚举)
- 空数组类型(长度为 0, 或者元素类型为ZST的数组)
- 指向ZST的指针类型
- 空元组类型(不包含任何元素, 或者所有元素均为ZST的元组)
- 空静态字符串
- 函数类型

针对ZST, yian 有一些特殊的处理规则:

- 可以取ZST实例的地址, 取地址的结果也是ZST类型的值
- 当ZST实例被移动/复制时, 没有任何实际的数据传输
- 任何分配在堆/栈上的ZST实例都不占用任何内存空间
- **ZST可以直接将类型的名字当作其值来使用**

## 类型转换

`yian` 仅允许:

- 浮点数与整数的互相转换:
  - 将浮点数转换成整数时, 会截断小数部分, 如果是将负数转换成无符号整数, 则值会变成 0
  - 将整数转换成浮点数时, 精度可能会丢失, 特别是当整数的值超出浮点数的精度范围时
- 浮点数转换: 浮点数类型之间的转换, 例如 `f32` 转换为 `f64`, 会进行精度提升
- 整数转换: 所有整数类型可以互相转换, 是否进行符号拓展由源类型决定
- 关于字符: 将字符类型转换成其他类型时, 转换规则等同于将 `u32` 转换成对应的类型; 只有 `u8` 可以转换成字符类型
  - 注意: 并非所有的 `u8` 值都能转换成合法的 ASCII 字符

显式转换的语法格式为:

```text
[目标类型](表达式)
```

其他任何类型转换均不被允许, 类型转换的操作也不允许被重载, 用户如果想要进行其他类型转换, 需要通过自定义函数来实现

```text
i32.max  // i32 类型的最大值, 即 2^31 - 1

```

| 类型           | 特殊值       | 描述                     |
| -------------- | ------------ | ------------------------ |
| 有符号整数类型 | min          | 该整数类型的最小值       |
| 有符号整数类型 | max          | 该整数类型的最大值       |
| 无符号整数类型 | max          | 该整数类型的最大值       |
| 浮点数类型     | min          | 该浮点类型的最小值(负数) |
| 浮点数类型     | max          | 该浮点类型的最大值(正数) |
| 浮点数类型     | min_positive | 该浮点类型的最小正数值   |
| 浮点数类型     | inf          | 正无穷大                 |
| 浮点数类型     | neg_inf      | 负无穷大                 |
| 浮点数类型     | nan          | 非数(NaN, Not a Number)  |

## 类型一致化

当使用具体类型的参数去调用泛型函数或方法时, 编译器会根据传入的参数类型来推导出泛型类型参数的具体类型, 这个过程称为**类型一致化(Type Unification)**.

下面是类型一致化的算法描述:

```text
input:  类型参数列表 T = {T1, T2, ..., Tn}, 
        具体类型列表 S = {S1, S2, ..., Sm},
        泛型类型列表 G = {G1, G2, ..., Gm}
output: 类型参数映射 M = {T1 -> U1, T2 -> U2, ..., Tn -> Un} or error

function type_unification(T, S, G) {
    M := empty map
    for i from 1 to m {
        unify(Si, Gi, M)
    }
    return M
}

function unify(S, G, M) {
    if G is a type parameter Ti {
        if Ti in M {
            U := M[Ti]
            if S != U {
                error "Type unification failed"
            }
        } else {
            M[Ti] := S
        }
    } else if G is a concrete type {
        if S != G {
            error "Type unification failed"
        }
    } else if G is a generic type constructor C<G1, G2, ..., Gk> {
        if S is not of the form C<S1, S2, ..., Sk> {
            error "Type unification failed"
        }
        for j from 1 to k {
            unify(Sj, Gj, M)
        }
    } else if G is a derived type {
        if S is not of the same derived type as G {
            error "Type unification failed"
        }
        for each component pair (Si, Gi) in S and G {
            unify(Si, Gi, M)
        }
    }
}

note:
generic type constructor: struct/enum with type parameters
derived type: array, tuple, pointer, function pointer
```
