# 22 项目模型与文件归属

对应源文件：`anx/project.py`

## 数据模型

全部是冻结数据类，且**交给调用方的映射一律是只读视图**（`MappingProxyType`）。
`frozen=True` 只禁止字段重新赋值、不保护容器内容，所以构造时就要包一层：

```python
@dataclass(frozen=True)
class Package:
    name: str; kind: PackageKind; version: str
    root: Path; manifest_path: Path; source_root: Path   # root / "src"
    entry: Path | None                                   # BIN/HYBRID；LIB 为 None
    dependencies: tuple[Dependency, ...]                 # 按 name 排序
    dev_dependencies: tuple[Dependency, ...]

@dataclass(frozen=True)
class Project:
    root_package: str
    packages: Mapping[str, Package]              # 规范名 → 包
    files: Mapping[Path, SourceFile]             # 绝对路径 → 文件归属
    dependencies: Mapping[str, tuple[str, ...]]      # 规范名 → 直接依赖
    dev_dependencies: Mapping[str, tuple[str, ...]]  # 规范名 → dev 依赖
    std_package: str                             # 固定 "std"
```

`Dependency` 与 `SourceFile` 携带的信息都很薄：前者只有「规范名 + 包根」，后者是
「路径 + 所属包 + 模块路径段」。编辑器要的增量失效信息（按包分组、依赖边）从这两个映射就能拿到，
不需要导入图。

`file_of` / `package_of` 是两条常用的查表捷径。

## 文件归属：最长源码根前缀

一个包的源码根是 `<包根>/src`。**路径依赖可以落在另一个包源码根之下**（例如
`app/src/vendor/foo`），父包直接 `rglob("*.an")` 会把子包源码重复收集，既重复编译又破坏归属。
因此索引阶段的规则是：

```python
def __owner_of(path: Path, source_roots: Mapping[str, Path]) -> str:
    """Return the package whose source root is the longest prefix of *path*."""
```

- 每个文件归属到**最深的**那个源码根；
- 扫描某个包时，若某文件的归属不是自己就跳过（`__index_files`）；
- 任意两个源码根互相嵌套时报 `AX013`（`__nested_source_root_diagnostics`），
  但**不阻止加载**：规则 1、2 已经保证「同一文件只属于一个包」。

源码根映射时排除 `std`：标准库在编译器检出里，不是用户项目的同级包。

## 两个文件集合

`Project` 同时提供两条「文件列表」，用途不同：

| 方法 | 内容 | 谁用 |
| --- | --- | --- |
| `files` | **全部**索引到的文件，含 dev 依赖 | `anx test`（要把 dev 依赖编进用例）、编辑器 |
| `build_packages()` | 根包 + 沿 `dependencies`（不含 dev）可达的包 + `std` | — |
| `build_files()` | `files` 中属于 `build_packages()` 的那些，顺序同 `files` | `anx build` / `run` / `check` |

顺序沿用 `files` 的插入序（依赖遍历序 + `std` 最后），因为编译器把**单元编号**与传入顺序绑定，
顺序变了会改变单元名与 IR。

`build_files()` 把 dev 依赖排除在外，是为了让「普通构建不编译 dev 依赖」成为结构上的事实：
即使 dev 依赖的源码里存在语法错误，`anx build` 也不会去读它。

## 导入解析：`resolve_import`

```python
def resolve_import(self, importer: Path, paths: Sequence[str]) -> ImportResolution
```

一个**纯函数**：不读文件、不起进程、不解析源码。输入是导入方文件与已经切好的路径段，
输出 `ImportResolution(target | failure)`，失败原因取 `ImportFailure` 四值之一。
顺序与编译器完全一致：

1. 第一段不在 `packages` 里 → `UNKNOWN_PACKAGE`（`AX012`）；
2. 导入方所属包的可见集合 = `{自身} ∪ 直接依赖 ∪ {std}`（`dev` 依赖**不**在内）；
   第一段不在其中 → `NOT_VISIBLE`（`AX009`）；
3. 只剩一段（`from pkg import x`）或目标文件不在 `files` 索引里 → `NOT_A_MODULE`（`AX010`）：
   **目录不是模块**；
4. 目标是任何包的 `entry`（含导入方自己包的入口）→ `ENTRY_MODULE`（`AX014`）。

这个函数是给编辑器用的规范实现；编译器的 Package 模式（
`compiler/analysis/passes/global_resolve.py::__resolve_package_import`）是另一份实现，
两者由同一批 fixture 固定，详见 [23](23.anx_graph.md)。

## 加载流程

`load(root, *, std_root=None) -> LoadResult` 的顺序：

```python
根清单不可读/不可用/保留名 → LoadResult(None, diagnostics)     # AX001/AX002/AX011
walk(root)                       # 深度优先：两张表各走一遍，逐包校验依赖
__check_cycles(两张表的并集)      # 有环 → 抛 CycleError（AX006）
__build_package × order          # src/ 存在、kind/entry 一致（AX008）
根包不在 built 里 → LoadResult(None, diagnostics)
注入 std；__nested_source_root_diagnostics（AX013）
拼 dependencies / dev_dependencies（只保留真正建成的包）
__index_files                    # 最长前缀归属
Project(...)                     # 只读视图
```

注意几点：

- **`project is None` 当且仅当根包本身不可用**（`AX001`/`AX002`/`AX008`/根名 `AX011`）。
  依赖子树出错只跳过那棵子树，其余部分照常可用，诊断仍然给出。
- 环检测在**读完所有清单之后、收集源码之前**，避免部分加载的中间状态；但它是致命错误，
  不走 `diagnostics` 通道。
- `AX013` 是「警告级事实」——它被当作诊断返回（会让 CLI 退出 1），但加载本身继续。

## 项目发现

```python
def discover(start: Path) -> Path | None
```

从 `start`（若为文件则先取父目录）逐级向上找最近的 `package.anx`。CLI 用它把
`anx build`（不带参数或给了子目录）补全成项目根；`anx test` 也用它。
