# 22 项目模型与文件归属

对应源文件：`bootstrap/anx/src/project/model.an`、`project/load.an`。

## 拥有型数据模型

`Project` 拥有包列表、源文件列表、根包名和标准库包名。`Package` 拥有包名、版本、根路径、manifest 路径、
源码根、可选入口、普通与 dev 依赖名、FFI 权限及可选 LLVM 配置。`SourceFile` 拥有源文件路径、包名和模块路径段。

这些结构用 `String`、`PathBuf`、`Vec` 和 `Option` 保存数据。诸如 `package(index)`、`file(index)`、
`package_by_name(name)` 的接口返回借用视图；Project 拥有列表元素并在 `drop()` 中逐个释放。`LoadReport`
拥有可选 Project 和诊断列表。调用方通过 `take_project()` 转移 Project 所有权，或在报告释放时一并清理。

`Project.build_files()` 返回新建的 `Vec<PathBuf>`，范围为根包、标准库和普通依赖的可达闭包；dev 依赖不在
普通构建输入中。图查看器可以用 `file_count()` / `file(index)` 查询每个文件的包归属和模块名。

## 源文件归属

每个包的源码根固定为其 `<package-root>/src`。项目加载器收集各源码根下的 `.an` 文件，再以**最长源码根前缀**
确定拥有者：路径依赖意外嵌入另一个包的 `src/` 时，文件只归最深的源码根。任意包源码根嵌套会产生 `AX013`；
索引阶段仍按最深根归属，但普通项目操作因存在诊断会停止。

相对源码根去掉 `.an` 扩展名后，剩余路径按 `/` 拆成模块段。例如 `src/math/vector.an` 的模块段为
`math`、`vector`。anx 记录文件归属；import 的可见性与解析由 compiler 根据包映射决定。

## 包布局校验

| `kind` | 布局要求 |
| --- | --- |
| `bin` | 有 `src/`；默认入口为 `src/main.an`，或 `entry` 指向源码根内存在的 `.an` 文件 |
| `hybrid` | 与 `bin` 一样提供入口，同时可以被依赖 |
| `lib` | 有 `src/`，不能声明 `entry`，也不能包含 `src/main.an` |

依赖的 `bin` 包以 `AX015` 拒绝。入口文件必须存在、以 `.an` 结尾且位于 canonical `src/` 根之内；布局不一致
用 `AX008` 报告。

## 加载过程与部分结果

`discover(start)` 从给定文件或目录向上查找最近的 `package.anx`。`load(root, std_root)` 随后：

1. 解析并校验根清单；无根清单、根 manifest 不可用或根包布局无效时不返回 Project。
2. 深度遍历 `[dependencies]` 和 `[dev-dependencies]`，以目标清单声明的规范包名建节点；验证路径、manifest、
   包名、重复包和依赖 kind，并记录诊断。
3. 检查两类依赖边上的环。发现环会生成 `AX006`，且不产生部分 Project。
4. 检查各包 `src/` 与入口，构造可用包和特殊 `std` 包；收集源文件并建立最深根归属。
5. 排序诊断并返回 `LoadReport`。根包可用时，依赖分支上的问题仍可能伴随一个部分 Project 返回。

`driver/support.load_project()` 用于 `build`、`run`、`check`、`test` 和 `fmt`：它打印报告诊断，并在诊断非空时
拒绝后续操作。`graph` 直接序列化报告，因此可用于查看部分图和错误。
