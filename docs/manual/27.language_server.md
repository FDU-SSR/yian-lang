# 27 Language server

The YIAN language server is the native program in `lsp/`. It uses the compiler, package-manager, JSON-RPC, LSP protocol, and standard-library packages from this repository. The cold bootstrap installs `yianc`, `anx`, and shared resources; the warm refresh installs those components together with `yian-lsp` under the selected prefix.

## Install and remove

Cold bootstrap the native YIAN toolchain, then run the warm refresh to build and install the language server with the complete native toolchain:

```bash
conda run --no-capture-output -n yian-env bash scripts/bootstrap_toolchain.sh \
  --prefix "$HOME/.local" --python python

scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" \
  --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"

"$HOME/.local/bin/yian-lsp" --version
```

The warm refresh requires native `anx` and `yianc` seeds, the standard-library and runtime resources, LLVM 22, clang 22, and a native C toolchain. It builds `lsp/` with `anx build -O2 --raw-pointers`, checks the executable, runs a stdio initialization handshake against staged resources, then publishes the full toolchain. The binary is built in raw mode; source analysis defaults to fat-pointer mode.

The server accepts:

| Option | Meaning |
| --- | --- |
| `--stdio` | Use the stdio JSON-RPC transport. |
| `--compiler-root PATH` | Use a checkout root for compiler and standard-library sources. Omit this for an installed toolchain. |
| `--raw-pointers` | Analyze workspace sources in raw-pointer mode. |
| `--log-level {DEBUG,INFO,WARNING,ERROR}` | Set the server's stderr log threshold. |
| `--log-file PATH` | Append server logs to a file as well as stderr. |
| `--version` | Print the installed server version. |

The extension starts `yian-lsp` by default. It can also use a configured absolute path. The server writes protocol frames to stdout and logs to stderr or the configured log file.

Remove only the language server while keeping the shared toolchain, or remove the complete managed installation:

```bash
scripts/uninstall.sh --lsp-only --prefix "$HOME/.local"
scripts/uninstall.sh --prefix "$HOME/.local"
```

`--lsp-only` removes only a `yian-lsp` binary whose digest matches its install record and leaves `share/yian` untouched. The default uninstaller removes the managed compiler tools, language server, and shared resources; it retains resources needed by a preserved or unmanaged server binary.

Server removal also deletes digest-matching `.build-info` and its install record, then removes the empty `share/yian-lsp` directory. Modified, unrecorded or symlinked build information is preserved with its install record and causes a nonzero uninstall status. Other files in that directory are retained.

When compatible native `anx` and `yianc` commands are already available, `scripts/refresh_toolchain.sh` rebuilds and installs the compiler, package manager, shared resources, and the raw/O2 language server in one transaction. It verifies the server against staged resources before publishing and does not start Python or fall back to the cold path:

```bash
scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"
```

## Features

The server supports diagnostics, definition, hover, document symbols, semantic tokens, references, document highlights, document synchronization, and watched-file updates. It does not declare completion, signature help, prepare-rename, rename, code actions, or document formatting. Requests for those methods return `MethodNotFound` (`-32601`) without starting analysis. Capabilities are negotiated during `initialize`; server identity is reported as `yian-lsp` with its version.

A navigation result requires the current complete analysis input to pass strict frontend and semantic analysis. Inputs include open document text, standard-library sources, package dependencies and the package map. A missing `main` does not fail analysis. Any preparation, type, constant, coverage or definite-assignment error makes the current analysis unit fail: the server publishes the first root diagnostic and does not serve navigation from the previous version. Another independently analyzed unit is unaffected. Fixing the input triggers a fresh analysis automatically.

While the failed state is current, definition and hover return `null`, document symbols return an empty array, references and highlights return an empty array, and semantic tokens return `{"data": []}`. Pending requests may wait for the current analysis; an outdated response is rejected with `-32801` and a client cancellation with `-32800`. Internal index failures are reported as service errors and never rewritten as a source diagnostic.

The server keeps open-document contents and versions, reloads package inputs when manifests or source topology change, and discards results for outdated document revisions. Package workspaces use their `package.anx` metadata. Standalone workspaces analyze open source files with the standard library. Unsaved editor text takes precedence over disk contents.

The native compiler performs one strict analysis per input version. The language server then parses the same frozen text once more without desugaring to build its source view, and constructs declaration, import, type, local-binding, member and reference indexes in `lsp/src/analysis/`. Compiler symbol, definition, member and HIR results supply semantic targets; index and query code never re-runs type inference. Semantic identities are valid only for the snapshot that owns the analysis session.

LSP positions use UTF-16 code units. Compiler source positions use Unicode scalar columns; the protocol boundary converts between them using the current source text.

## Manual editor verification

The automated protocol checks do not replace testing in the editor. Build the extension package with `npm run package` from `ide-support/vscode/`; the generated file is `ide-support/vscode/yian-language-support-0.7.0.vsix`. Install that VSIX manually. Set `yian.languageServer.command` to the absolute path of the installed binary, for example:

```json
{
  "yian.languageServer.command": "/home/you/.local/bin/yian-lsp",
  "yian.languageServer.args": []
}
```

Then verify the installed binary:

1. Open both a standalone `.an` file and a package workspace. Check the YIAN output channel for a matching server version and confirm diagnostics appear.
2. Make an unsaved edit. Check definition, hover, references, document highlights and semantic highlighting against the current buffer.
3. In a multi-file project, check definitions and references across files. Confirm that completion, rename and formatting requests are rejected and that no stale navigation survives an intentionally invalid edit.
4. Type continuously, save, add and remove a source file, and repair a temporarily invalid manifest. Confirm current diagnostics replace old ones and no stale result appears after a newer edit.
5. To check raw analysis, set `yian.languageServer.args` to `["--raw-pointers"]`, restart the server, and repeat representative queries.
6. Close the workspace and confirm the server and its worker have exited. For example, inspect `ps -eo pid,ppid,args | grep '[y]ian-lsp'` and ensure no process for that workspace remains.

Build the extension package without starting the editor:

```bash
cd ide-support/vscode
npm ci
npm run compile
npm run package
```

The package command writes a `.vsix` in `ide-support/vscode/`. Install it manually in the editor for the interaction checks above.

## Automated protocol checks

The minimal navigation probe opens one two-file fixture and checks retained capabilities, closed methods, definition/reference/hover/symbols/tokens, the valid to invalid to repaired transition, and UTF-16 positions. It uses only `StdioSession` and does not run the protocol matrix:

```bash
PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/probe_lsp_navigation.py
```

The Python protocol script is a test and measurement client; it starts only the installed native service. It supports protocol replay, benchmarking, native event-trace profiling, and infrastructure checks:

```bash
PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode check

PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode benchmark

PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode profile
```

The infrastructure mode requires an existing native `yianc`, `anx`, `yian-lsp`, and shared resources. It does not install or refresh tools; missing components produce an explicit cold/warm setup hint. When prerequisites exist, it runs bootstrap package tests, all unit tests, formatter checks, and runtime normal/sanitized checks. This is a broad infrastructure run; repository verification must inspect those indirect effects and use an explicitly authorized scope. It does not start VS Code.

`--mode check` runs the protocol scenarios (standalone, JSON project, and compiler project by default) in both fat and raw modes; it does not run the infrastructure command list above. This is six protocol combinations by default. Repository checks should select the exact scenario and pointer mode; the full matrix requires explicit authorization. Benchmark and profile modes are measurements rather than default local acceptance checks.
