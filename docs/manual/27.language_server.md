# 27 Language server

The YIAN language server is the native program in `lsp/`. It uses the compiler, package-manager, JSON-RPC, LSP protocol, and standard-library packages from this repository. The cold bootstrap installs `yianc`, `anx`, and shared resources; the warm refresh installs those components together with `yian-lsp` under the selected prefix.

## Install and remove

Cold bootstrap the native YIAN toolchain, then run the warm refresh to build and install the language server with the complete native toolchain:

```bash
conda run --no-capture-output -n yian-env bash scripts/bootstrap_toolchain.sh \
  --prefix "$HOME/.local" --python python

scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" \
  --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"

"$HOME/.local/bin/yian-lsp" --version
```

The warm refresh requires native `anx` and `yianc` seeds, the standard-library and runtime resources, LLVM 22, clang 22, and a native C toolchain. It builds `lsp/` with `anx build -O2 --raw-pointers`, checks the executable, runs a stdio initialization handshake against staged resources, then publishes the full toolchain. The binary is built in raw mode; source analysis defaults to fat-pointer mode.

The server accepts:

| Option | Meaning |
| --- | --- |
| `--stdio` | Use the stdio JSON-RPC transport. |
| `--compiler-root PATH` | Use a checkout root for compiler and standard-library sources. Omit this for an installed toolchain. |
| `--raw-pointers` | Analyze workspace sources in raw-pointer mode. |
| `--log-level {DEBUG,INFO,WARNING,ERROR}` | Set the server's stderr log threshold. |
| `--log-file PATH` | Append server logs to a file as well as stderr. |
| `--version` | Print the installed server version. |

The extension starts `yian-lsp` by default. It can also use a configured absolute path. The server writes protocol frames to stdout and logs to stderr or the configured log file.

Remove the server separately from the shared toolchain:

```bash
scripts/uninstall_lsp.sh --prefix "$HOME/.local"
scripts/uninstall.sh --prefix "$HOME/.local"
```

`uninstall_lsp.sh` removes only a binary whose digest matches its install record. It leaves `share/yian` untouched. The general uninstaller retains shared resources while an LSP installation still uses them; after removing the server, run the general uninstaller to remove the remaining toolchain if desired.

When compatible native `anx` and `yianc` commands are already available, `scripts/refresh_toolchain.sh` rebuilds and installs both compilers, the package manager, shared resources, and the raw/O2 language server in one transaction. It verifies the server against staged resources before publishing and does not start Python or fall back to the cold path:

```bash
scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"
```

## Features

The server supports diagnostics, definition, hover, document symbols, semantic tokens, completion, signature help, references, document highlights, prepare-rename and rename, import code actions, formatting, document synchronization, and watched-file updates. On incomplete or invalid buffers, read-only queries can use reliable local semantic facts; results may be partial, and rename is refused when the reference set is incomplete. Capabilities are negotiated during `initialize`; server identity is reported as `yian-lsp` with its version.

The server keeps open-document contents and versions, reloads package inputs when manifests or source topology change, and discards results for outdated document revisions. Package workspaces use their `package.anx` metadata. Standalone workspaces analyze open source files with the standard library. Unsaved editor text takes precedence over disk contents.

LSP positions use UTF-16 code units. Compiler source positions use Unicode scalar columns; the protocol boundary converts between them using the current source text.

## Manual editor verification

The automated protocol checks do not replace testing in the editor. Build the extension package with `npm run package` from `ide-support/vscode/`; the generated file is `ide-support/vscode/yian-language-support-0.7.0.vsix`. Install that VSIX manually. Set `yian.languageServer.command` to the absolute path of the installed binary, for example:

```json
{
  "yian.languageServer.command": "/home/you/.local/bin/yian-lsp",
  "yian.languageServer.args": []
}
```

Then verify the installed binary:

1. Open both a standalone `.an` file and a package workspace. Check the YIAN output channel for a matching server version and confirm diagnostics appear.
2. Make an unsaved edit. Check completion, hover, definition, signature help, and semantic highlighting against the current buffer.
3. In a multi-file project, check references and rename across files. Apply an import quick fix and format a file; confirm the resulting edits are correct.
4. Type continuously, save, add and remove a source file, and repair a temporarily invalid manifest. Confirm current diagnostics replace old ones and no stale result appears after a newer edit.
5. To check raw analysis, set `yian.languageServer.args` to `["--raw-pointers"]`, restart the server, and repeat representative queries.
6. Close the workspace and confirm the server and its worker have exited. For example, inspect `ps -eo pid,ppid,args | grep '[y]ian-lsp'` and ensure no process for that workspace remains.

Build the extension package without starting the editor:

```bash
cd ide-support/vscode
npm ci
npm run compile
npm run package
```

The package command writes a `.vsix` in `ide-support/vscode/`. Install it manually in the editor for the interaction checks above.

## Automated protocol checks

The Python script is a test and measurement client; it starts only the installed native service. It supports protocol replay, benchmarking, native event-trace profiling, and infrastructure checks:

```bash
PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode check

PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode benchmark

PATH="$HOME/.local/bin:$PATH" \
  conda run --no-capture-output -n yian-env python scripts/check_lsp.py --mode profile
```

The infrastructure mode requires an existing native `yianc`, `anx`, `yian-lsp`, and shared resources. It does not install or refresh tools; missing components produce an explicit cold/warm setup hint. When prerequisites exist, it runs the configured protocol, package, formatter, unit, and runtime checks. It does not start VS Code.
