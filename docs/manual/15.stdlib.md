## 标准库参与编译

`lib/src/` 下的 `.an` 文件与用户源文件一同经历完整的编译管线：lex → parse → desugar → resolve → type_check。它们不是预编译的，而是每次编译时作为普通源文件处理。

## Vec 的存储

`std.core.vec` 内部用私有的非泛型 `RawVec` 保存字节指针、元素容量和元素长度。`Vec<T>` 按目标布局传入元素步长，共用分配、扩缩容和批量搬移。读取和写入元素时恢复 `T*`，元素 trait 仍按 `T` 分派。零大小元素只有逻辑长度，跳过缓冲区的分配与复制。

非重叠的批量复制使用 `@memcpy`，插入和删除的重叠移动使用模块内的 libc `memmove` 包装。胖指针模式下，包装在交出两个地址前校验精确字节视图的跨度与活性。填充未初始化槽位使用公开的 `spare()` 和 `advance_len()`。

## std 命名空间

`from std.xxx.yyy import ZZZ` 解析到标准库源码根（`lib/src`）下的 `xxx/yyy.an`。
实现上不拼接路径，而是在全局解析开始时先按「相对于源码根的路径」建一张查找表：

```python
# global_resolve.py
def __build_std_lookup(self) -> None:
    for unit in self.__ctx.unit_datas.values():
        if not unit.is_stdlib:
            continue
        relative = unit.path.resolve().relative_to(self.__stdlib_root)
        key = ("std",) + relative.parts[:-1] + (unit.path.stem,)
        self.__std_lookup[key] = unit

# Resolving imports in standalone mode.
target = self.__std_lookup.get(tuple(paths))
```

只有**本次命令行传入**、且被 `build_source_trust(stdlib_root)` 按路径判定为标准库的文件才会
进表；因此「文件在磁盘上存在但没传给编译器」一样解析不到（`Cannot resolve import path`）。

## Prelude 自动注入

`yianc/src/analysis/resolution/imports.an` 对非 `lib/src/` 源文件自动注入以下 import；Python 恢复编译器的对应实现位于
`python/yianc/analysis/passes/prelude.py`：

```python
Option, Result, Vec, String, Range, Ordering, Clone, Ptr, Slice, Array, Never, Drop, exit
```

native 编译器对非标准库模块显式导入这些符号给出 `W502` 警告；警告不阻止编译：

```text
warning[W502]: unnecessary import of 'Option': the prelude already provides it
--> src/main.an:1:29
    from std.core.option import Option;
                                ^^^^^^
```

使用别名（例如 `Vec as MyVec`）会建立不同的绑定，不产生该警告；标准库 `lib/src/` 内部不受此规则影响。

## Intrinsic Types

编译器预分配固定 type_id 给标准库 trait。当 `lib/src/core/ops.an` 定义 `pub trait Add` 时，`alloc_trait("Add")` 通过 `intrinsic_mapping` 匹配到预分配 ID (`add_id=50`)，而非自动递增分配。这确保了编译器内部代码中引用的 type_id 与 lib 中定义的类型一致。
