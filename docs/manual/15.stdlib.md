## 标准库参与编译

`lib/src/` 下的 `.an` 文件与用户源文件一同经历完整的编译管线：lex → parse → desugar → resolve → type_check。它们不是预编译的，而是每次编译时作为普通源文件处理。

## std 命名空间

`from std.xxx.yyy import ZZZ` 解析到标准库源码根（`lib/src`）下的 `xxx/yyy.an`。
实现上不拼接路径，而是在全局解析开始时先按「相对于源码根的路径」建一张查找表：

```python
# global_resolve.py
def __build_std_lookup(self) -> None:
    for unit in self.__units.values():
        if not unit.is_stdlib:
            continue
        relative = unit.path.resolve().relative_to(self.__stdlib_root)
        key = ("std",) + relative.parts[:-1] + (unit.path.stem,)
        self.__std_lookup[key] = unit

# Standalone 模式解析 import 时
target = self.__std_lookup.get(tuple(paths))
```

只有**本次命令行传入**、且被 `build_source_trust(stdlib_root)` 按路径判定为标准库的文件才会
进表；因此「文件在磁盘上存在但没传给编译器」一样解析不到（`Cannot resolve import path`）。

## Prelude 自动注入

`compiler/analysis/passes/prelude.py` 对非 `lib/src/` 源文件自动注入以下 import：

```python
Option, Result, Vec, String, Range, Ordering, Clone, Ptr, Slice, Array, Never
```

## Intrinsic Types

编译器预分配固定 type_id 给标准库 trait。当 `lib/src/core/ops.an` 定义 `pub trait Add` 时，`alloc_trait("Add")` 通过 `intrinsic_mapping` 匹配到预分配 ID (`add_id=20`)，而非自动递增分配。这确保了编译器内部代码中引用的 type_id 与 lib 中定义的类型一致。
