# 15 标准库架构

## 目录结构

```text
lib/
├── core/              # 核心类型与 trait
│   ├── option.an      # Option<T>
│   ├── result.an      # Result<T, E>
│   ├── vec.an         # Vec<T>
│   ├── string.an      # String
│   ├── str.an         # str 方法 + CharIter
│   ├── slice.an       # T[] 方法 + SliceIter
│   ├── range.an       # Range<T>
│   ├── ops.an         # 运算符 trait (28 个)
│   ├── iter.an        # Iterator, IntoIterator
│   ├── drop.an        # Drop trait
│   ├── convert.an     # From, Into
│   ├── fmt.an         # ToString
│   ├── hash.an        # Hash, Murmur3Hasher
│   ├── io.an          # print, IoError, sys_read/write
│   ├── mem.an         # memcpy
│   ├── pointer.an     # T* 的 Index impl
│   ├── array.an       # T[N] 方法
│   └── raw_vec.an     # RawVec<T> (底层缓冲区)
├── collections/
│   ├── hash_map.an    # HashMap<K, V>
│   └── hash_set.an    # HashSet<T>
└── num/
    ├── u8.an ... u64.an   # 无符号整数 Hash + 扩展方法
    ├── i8.an ... i64.an   # 有符号整数 Hash
    ├── f32.an, f64.an     # 浮点数 Hash + From<str>
    └── bool.an            # bool Hash
```

## 标准库参与编译

`lib/` 下的 `.an` 文件与用户源文件一同经历完整的编译管线：lex → parse → desugar → resolve → type_check。它们不是预编译的，而是每次编译时作为普通源文件处理。

## std 命名空间

编译器将 `from std.xxx.yyy import ZZZ` 映射为 `lib/xxx/yyy.an`：

```python
# global_resolve.py
if paths[0] == "std":
    lib_path = ROOT / "lib"
    for seg in paths[1:]:
        lib_path /= seg
```

## Prelude 自动注入

`compiler/analysis/passes/prelude.py` 对非 `lib/` 源文件自动注入以下 import：

```python
Option, Result, Vec, String, Range, Ordering, Ptr, Slice, Array, Never
```

## Intrinsic Types

编译器预分配固定 type_id 给标准库 trait。当 `lib/core/ops.an` 定义 `pub trait Add` 时，`alloc_trait("Add")` 通过 `intrinsic_mapping` 匹配到预分配 ID (`add_id=20`)，而非自动递增分配。这确保了编译器内部代码中引用的 type_id 与 lib 中定义的类型一致。
