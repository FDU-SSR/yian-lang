# 03 AST 去糖

`python/yianc/analysis/passes/desugar.py` 通过 AST visitor 与 rewriter 将语法糖展开为基本结构。

## 遍历与职责

`Desugar.run()` 处理函数、方法与闭包的参数绑定，并执行控制流、表达式和错误传播重写。
`AstVisitor` 与 `AstRewriter` 负责遍历嵌套节点。参数模式使用合成输入名；解构记录在函数体的
`parameter_bindings` 中，由语义检查器绑定。

| 重写器 | 处理内容 |
|--------|----------|
| `_ControlFlowRewriter` | `for`、`while`、`if let`、`while let`、`assert` 与 `elif` |
| `_ExprDesugarRewriter` | 范围与成员测试 |
| `_TryRewriter` | 后缀 `?` 的 trait 调用、分支与提前返回 |

## 变换规则

| 原始 | 展开为 |
|------|--------|
| `for item in iterable { body }` | `let %iter = iterable.into_iter(); loop { match %iter.next() { Some(item) => { body }, None => { break } } }` |
| `while cond { body }` | `loop { if !cond { break; } body }` |
| `assert cond: msg` | `if !cond { @panic(msg) }` |
| `if a { } elif b { } else { }` | `if a { } else { if b { } else { } }` |
| `a..b` | `Range(a, b)` |
| `x in y` | `y.contains(x)` |

`if let` 展开为带成功模式和兜底分支的 `match`；`while let` 在循环中匹配，失败时退出。
模式的合法性与绑定类型由 `PatternChecker` 检查，穷尽性与不可达模式由 `MatchCoverage` 检查。

## 后缀 `?`

`value?` 通过 `std.core.try` 的 `Try.branch` 得到 `TryBranch`。`Continue` 分支产生载荷，
`Break` 分支调用当前返回类型的 `FromResidual.from_residual` 并提前返回。相关 trait import 由去糖注入。
函数、方法与闭包之外的 `?` 在去糖时报告错误。

去糖后的提前返回使用普通 AST `return`；CFG 下降沿返回路径展开活动的 `defer`。
直接借用的 `(&value)?` 保留引用输出。`comptime if` 保留为 AST 条件表达式，其分支选择属于
类型检查时的 AST → HIR 下降。
