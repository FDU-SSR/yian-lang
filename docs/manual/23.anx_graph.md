# 23 依赖图与 v2/v3 包图

对应源文件：`anx/src/project/load.an`、`project/model.an`、`project/graph.an`、
`project/package_map.an`；消费端为 `yianc/src/package/`。

## 依赖图

项目加载器以目标 manifest 中的 `[package].name` 为规范节点名，分别读取 `dependencies` 和
`dev-dependencies`。相对路径按声明清单的位置解析；每条边校验目标目录、清单、包名和 kind。名称不匹配会产生
`AX005`，但仍以目标规范名记录边；同名包指向不同路径产生 `AX007`；依赖 `bin` 包产生 `AX015`。

普通依赖与 dev 依赖分别保存在 `Package` 中。环检测检查两类边；环报告完整 `AX006` 并使项目不可用。
`Project.build_files()` 沿普通依赖闭包，再加根包和 `std`；它不把 dev 依赖源码作为普通构建输入。

## v2/v3 compiler package map

`anx` 通过 `project/package_map.an::package_map_json()` 生成 `build/pkg.json`：

```json
{
  "format": 2,
  "root": "app",
  "packages": {
    "app": {
      "sourceRoot": "/work/app/src",
      "kind": "bin",
      "entry": "/work/app/src/main.an",
      "dependencies": ["mathlib"],
      "ffi": false
    },
    "mathlib": {
      "sourceRoot": "/work/mathlib/src",
      "kind": "lib",
      "dependencies": [],
      "ffi": false
    },
    "std": {
      "sourceRoot": "/checkout/lib/src",
      "kind": "lib",
      "dependencies": [],
      "ffi": true
    }
  }
}
```

每个包都有 `sourceRoot`、`kind`、`dependencies` 和 `ffi`；可执行 kind 另有 `entry`。声明 `[native.llvm]`
时，映射增加 `nativeLLVM`，包含 `major`、`components` 和相对包根的 C shim `sources`。声明 `[native.c]`
时映射升级为 v3，并在所属包记录中增加 `nativeC`：`sources`、`includeDirs`、`archives` 都是相对包根的路径数组。
顶层 `nativeRoots` 是可选包名数组，只扩展 native 输入闭包，不改变源模块可见性。普通构建图未声明 `native.c` 时仍用
v2，所以既有 LLVM 包图保持原格式；`anx test` 为带 native 输入的 `bin` 根保留链接输入时也会使用 v3。标准库以特殊的
`std` 包加入图。anx 写入 JSON 后，仅在文本变化时重写文件。

包映射顶层没有 dev 依赖字段。普通映射只把普通依赖写入每个包的 `dependencies`；`anx test` 另造
`__anx_test` 根包，把根包（仅 `lib`/`hybrid`）、普通依赖和 dev 依赖列为测试根的依赖。若原项目根是 `bin`
且声明 native 输入，测试图通过 `nativeRoots` 保留它的链接输入，不把它加入语言依赖。根包 FFI 标志与其他包
各自的 `ffi` / `nativeLLVM` / `nativeC` 元数据保持原值；FFI 权限不沿依赖传递。

`format` 是版本号；native compiler 接受 v2/v3 并校验字段类型、包种类、入口、依赖、FFI 和 native 配置。v2
不得出现 `nativeC` 或 `nativeRoots`。不要把
`anx graph --json` 当成该编译契约的替代品：graph 输出包根、manifest、源码根、入口、普通和
dev 依赖、文件归属及诊断，不含 `ffi`、`nativeLLVM` 或 `nativeC`。

## compiler 如何使用映射

`yianc` 读取 anx 生成的 v2/v3 包图。包图 按源码根前缀确定文件归属，并用根包入口确定程序入口；
包的导入可见性是“自身、直接普通依赖和 `std`”。dev 依赖只通过 `anx test` 的合成测试根向测试代码开放。
入口模块不可导入；未知包、不可见依赖、包名直接作为模块和缺失模块分别由 compiler 生成 `E308`、`E309`、
`E310`、`E304` 等源码诊断。

FFI 权限来自当前文件所属包的 `ffi` 值，不沿依赖传递。普通依赖闭包和 `nativeRoots` 中可达包的
`nativeLLVM` / `nativeC` 声明由 compiler 校验，并在生成可执行目标时加入对应 shim 与归档；dev 依赖只从
测试合成根可达。generic C 输入不会触发 `llvm-config`。

## graph 输出

`anx graph --json` 输出 `root`、`std`、`packages`、`files`、`dependencies`、`devDependencies`、
`diagnostics`。文件项包括绝对路径、所属包和模块段。无可用 Project 时仍输出空包图和诊断；有部分 Project 时
保留可用节点。该命令总是尝试打印图，诊断存在或 Project 不可用时返回非零状态。
