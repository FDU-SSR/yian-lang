# 23 依赖图与 v2 包图

对应源文件：`anx/project.py`（图构建）、`compiler/analysis/package_map.py`（消费）、
`compiler/analysis/passes/global_resolve.py`、`compiler/analysis/passes/type_check.py`

## 依赖图的构建

以**规范名**（被依赖包自己的 `[package].name`）为节点，`load()` 里用一次深度优先遍历建图：

```python
def walk(name: str, path: Path, manifest: Manifest) -> None:
    order.append(name)
    adjacency[name] = walk_edges(name, path, manifest.dependencies)
    dev_adjacency[name] = walk_edges(name, path, manifest.dev_dependencies)
```

`walk_edges` 对每个依赖做四件事：

| 检查 | 结果 |
| --- | --- |
| `path` 目录不存在 | `AX003`，跳过这条边 |
| 目录里没有 `package.anx` | `AX004`，跳过 |
| 对方清单不可用 / 保留名 | 由 `read_manifest` 报 `AX002`/`AX011`，跳过 |
| 依赖键 ≠ 对方 `name` | `AX005`，**仍然建边**（用规范名建），否则依赖自身的自导入会断 |
| 规范名已出现过且路径不同 | `AX007`，跳过 |
| 规范名已出现过且路径相同 | 复用（菱形依赖） |
| 对方 `kind == "bin"` | `AX015`，跳过子树 |

`AX005` 的处理值得注意：键不匹配时**不丢弃这条依赖**，而是按对方的规范名入图。理由是包名
同时是导入名，依赖包内部会写 `from <自己的名字>.… import …`；如果按错误的键建图，那份自导入
就会解析失败——「能用但自相矛盾」比「报错」更糟。

dev 边记在另一张表里。**环检测用两张表的并集**：穿过 dev 边的环仍然是环。

图的方向与用途：

```text
Project.dependencies       规范名 → 直接依赖        → 决定「项目代码能看见谁」
Project.dev_dependencies   规范名 → dev 依赖         → 决定「测试能看见谁」
Project.build_packages()   沿 dependencies 的闭包    → 决定「普通构建编译谁」
```

## v2 包图：`build/pkg.json`

anx 把模型渲染成编译器消费的文档（`Project.compiler_package_map()`）：

```json
{
  "format": 2,
  "root": "app",
  "packages": {
    "app": {
      "sourceRoot": "/abs/app/src",
      "kind": "bin",
      "entry": "/abs/app/src/main.an",
      "dependencies": ["mathlib"]
    },
    "mathlib": { "sourceRoot": "/abs/lib/src", "kind": "lib", "dependencies": [] },
    "std":     { "sourceRoot": "/abs/yian/lib/src", "kind": "lib", "dependencies": [] }
  }
}
```

设计要点：

- **单一 `packages` 表 + 顶层 `root`**：每个包一条、一条里自洽，不会出现「某个包只出现在其中
  一张表」。
- **每个包只有一个 `sourceRoot`**（固定 `<包根>/src`），可见性从「文件落在哪个源码根之下」
  推导，因此**嵌套源码根必须排除**（[22](22.anx_project.md)）。
- **没有 dev 字段**：dev 依赖不是包对外的一部分。只有 `anx test` 生成的合成测试包会把它们
  列进自己的 `dependencies`（[25](25.anx_tests.md)）。
- `format` 不是 2 时编译器**直接报错**，不做版本猜测；仓库内没有被跟踪的 `pkg.json`。
- 内容不变时 anx 不重写这个文件（`__write_package_map` 比较新旧文本）——它是纯函数式产物，
  可以安全比较。

`Project.package_specs()` 单独暴露「规范名 → 一条 v2 记录」，就是为了让 `anx test` 能在不改
模型的前提下追加自己的合成包。

## 编译器怎么消费

`PackageMap.parse(path)` 校验并收窄文档，得到：

| 方法 | 含义 | 用在哪 |
| --- | --- | --- |
| `package_of(file)` | 文件所属的包（最长 `sourceRoot` 前缀） | 可见性判断 |
| `visible_from(pkg)` | `{pkg} ∪ 直接依赖 ∪ {std}` | 导入第一段是否合法 |
| `entry_paths()` | 所有包的入口文件集合 | 入口不可导入（`AX014`） |
| `root` / `packages[root].entry` | 程序入口 | 类型检查的种子 |
| `packages["std"].sourceRoot` | 标准库源码根 | `build_source_trust`（受限内建权限） |

`GlobalResolve.__resolve_package_import` 的判定顺序（与 `Project.resolve_import` 一致）：

```text
未知包名            → AX012
不在可见集合里      → AX009
只剩一段 / 查不到 .an → AX010
目标是某个包的 entry → AX014
否则返回目标 unit
```

`PackageMap.visible_from(None)` 对「不属于任何源码根的文件」是宽松的（返回全部包）。
这是为命令行手工调用留的口子；`anx` 生成的文档里每个文件都属于某个包，因此正常路径不会走到它。

## 程序入口与检查根

`TypeCheck` 从包图里读两件事：

- **程序入口**：`packages[root].entry` 对应的 unit，必须有唯一的 `main`。这样依赖包里
  自带的 `main` 只是一个普通函数，不会撞「多个 main」。`entry` 为 `None`（`lib` 根）时：
  `-t none` 允许（只做分析），`-t exe` 报「没有程序入口」。
- **检查根**：根包的全部顶层定义（`__is_root_unit` 用 `package_of` 判定；未实例化的泛型体
  跳过）。生成集合仍然是「`main` 可达闭包」，只喂给 CFG/LLVM——两集合分离，所以**打开全量
  检查不会改变代码生成**。

入口在 LLVM 层按 **`type_id`** 认（`LLModule.__init__(entry_type_id=…)`），不按函数名
`main` 判断：否则依赖包里同名的 `main` 会和程序入口抢 LLVM 符号。

## 单元命名

`compiler/main.py::__build_unit_names` 按「文件 → 包归属」生成 LLVM 单元名：
`<包名>_<模块路径>`（源码根之外的文件退回文件 stem）。包归属来自 `PackageMap.package_of`
的最长源码根前缀，因此不同路径不会算出同名。
