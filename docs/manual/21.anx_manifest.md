# 21 清单解析与诊断

对应源文件：`anx/manifest.py`、`anx/diagnostics.py`

## 两条不变量

1. **解析器不抛用户错误**。`read_manifest(path) -> (Manifest | None, diagnostics)`：
   只有「清单整体不可用」才返回 `None`（读不了、TOML 语法错、`name`/`kind` 不可用），
   其余问题（`entry`/`version` 类型、单个依赖条目）只丢弃对应部分，manifest 照常返回。
   这样 `load()` 才能在一次遍历里收齐**所有可独立发现的诊断**。
2. **诊断是数据，不是文本**。`Diagnostic` 是冻结数据类，CLI 才把它渲染成一行字。

```python
@dataclass(frozen=True)
class Diagnostic:
    code: str                        # "AX003"
    message: str
    path: Path | None
    span: tuple[int, int] | None
    hint: str | None
```

## TOML 收窄

`tomllib.load()` 返回 `dict[str, Any]`，在 pyright strict 下会污染整段校验逻辑。
因此所有取值都经过一个收窄助手：

```python
def __as_table(value: object) -> dict[str, object] | None:
    """Return *value* as a string-keyed table, or None when it is not one."""
```

`read_manifest` 只做三件事：收窄 → 逐字段校验 → 组装。字段规则：

| 字段 | 校验 | 失败码 |
| --- | --- | --- |
| `name` | 非空、`[A-Za-z_][A-Za-z0-9_]*` | `AX002` |
| `name` 是保留名 | `RESERVED_PACKAGE_NAMES`（当前只有 `std`） | `AX011` |
| `kind` | 只能是 `bin`/`lib`/`hybrid`，缺省 `bin` | `AX002` |
| `entry` | 非空字符串（**是否存在**由项目加载器判，见 [22](22.anx_project.md)） | `AX002` |
| `version` | 可解析的版本串，缺省 `0.1.0`；只做格式校验 | `AX002` |
| `[dependencies]` / `[dev-dependencies]` | 每个条目 `{ path = "…" }` | `AX002` |

`name` 或 `kind` 不可用 → 返回 `None`，调用方跳过整棵子树；其余问题降级为「丢掉这一项」。

## 两张依赖表

两个表走同一个解析函数 `__read_dependencies(data, path, table)`，产出的都是
`tuple[DependencySpec, ...]`（`key` + 已 resolve 的绝对 `path`）。它们的**区别只在消费者**：

- `dependencies` → 项目代码可见、普通构建会编译；
- `dev_dependencies` → 只有 `anx test` 生成的合成测试包可见，普通构建不编译。

「键 == 被依赖包的规范名」这条跨清单的校验不在这里，而在依赖图遍历里（`AX005`，见
[23](23.anx_graph.md)）——解析单个清单时还看不到对方的 `name`。

## 诊断目录与排序

`anx/diagnostics.py` 一处声明全部码，避免到处写字面量：

```python
AX_NO_PROJECT_ROOT = "AX001"      AX_ENTRY_MISMATCH = "AX008"        AX_NESTED_SOURCE_ROOTS = "AX013"
AX_BAD_MANIFEST = "AX002"         AX_UNDECLARED_DEPENDENCY = "AX009" AX_IMPORT_ENTRY_MODULE = "AX014"
AX_DEPENDENCY_PATH_MISSING = …    AX_IMPORT_NOT_A_MODULE = "AX010"   AX_BIN_AS_DEPENDENCY = "AX015"
…
```

排序固定为 **path（`None` 最前）→ span 起点 → code → message**：

```python
def __sort_key(diagnostic: Diagnostic) -> tuple[int, str, int, str, str]:
    has_path = diagnostic.path is not None
    path = str(diagnostic.path) if diagnostic.path is not None else ""
    span_start = diagnostic.span[0] if diagnostic.span is not None else -1
    return (1 if has_path else 0, path, span_start, diagnostic.code, diagnostic.message)
```

把 `code` 放在 `message` 前面，是为了让「同一位置的多个问题」按码的字典序稳定，
而不是按消息文本（消息里含路径，会随机器变化）。`sort_diagnostics()` 保证同一输入下的
输出可以直接写进期望文件比对。

## 渲染与结构化输出

- `format_diagnostic(d)` → `error[AX005]: <path>: <message>`，有 `hint` 时另起一行 `  hint: …`。
  这是 CLI 唯一的输出形式（`anx/main.py`）。
- `diagnostic_payload(d)` → `{"code", "message", "path", "span", "hint"}`，即
  `anx graph --json` 载荷里 `diagnostics` 数组的元素。编辑器消费这个形状，不必解析文本。

一个例外是依赖环（`AX006`）：它不是收集型诊断，而是 `CycleError` 异常（有环时没有可用的
部分图）。CLI 用同一套渲染把它变成 `error[AX006]: Circular dependency: a → b → a`，
`anx graph` 则把它写进载荷的 `diagnostics` 里。
