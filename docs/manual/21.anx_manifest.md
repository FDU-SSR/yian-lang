# 21 清单解析与诊断

对应源文件：`anx/src/manifest/load.an`、`manifest/model.an`、`diagnostics/model.an`。
TOML 语法树由 `bootstrap/toml/` 提供。

## 解析结果与所有权

`read_manifest(path)` 返回 `ManifestReport`：可选的 `Manifest` 加诊断向量。无法读取、TOML 语法错误、缺少
`[package]`、名称无效或 `kind` 无效时没有可用 manifest。其他字段错误会记录诊断并以安全缺省值或丢弃无效项，
让调用方保留同一清单中可继续处理的数据。项目命令随后检查报告；只要存在诊断，就不会继续编译或格式化。

`Manifest`、`DependencySpec`、`NativeLLVM` 和 `Diagnostic` 都是原生 YIAN 拥有型结构。字符串、`PathBuf`、
`Vec` 和可选子结构由对象的 `drop()` 释放；报告的 `drop()` 释放剩余 manifest 与诊断。访问器返回借用视图，
调用方不能在拥有者释放后继续使用这些视图。解析 TOML 文档和临时值在作用域退出时通过 `defer` 清理。

诊断结构包含 `code`、`message`、可选 `path` 和可选 `hint`。它没有独立 span 字段；TOML 语法错误的行列号
被写进消息文本。`anx graph --json` 输出的 `span` 因而固定为 `null`。

## 字段规则

| 字段 | 规则 | 失败诊断 |
| --- | --- | --- |
| `[package].name` | 非空标识符，以 ASCII 字母或 `_` 开头，后接字母、数字或 `_`；`std` 保留 | `AX002` / `AX011` |
| `[package].kind` | `bin`、`lib` 或 `hybrid`，缺省 `bin` | `AX002` |
| `[package].entry` | 可选非空字符串；路径、扩展名和源码根边界由项目加载器检查 | `AX002` / `AX008` |
| `[package].version` | 缺省 `0.1.0`；数字点分段，可带 `-` 或 `+` 后缀 | `AX002` |
| `[package].ffi` | 布尔值，缺省 `false` | `AX002` |
| `[dependencies]`、`[dev-dependencies]` | 表项 key 是包标识符；每项必须是带非空字符串 `path` 的表 | `AX002` |
| `[native.llvm]` | `major = 22`、非空组件名；可选 `.c` 相对路径数组；要求 `ffi = true` | `AX002` |

`[native]` 只支持 `llvm` 子表；`[native.llvm]` 只接受 `major`、`components`、`sources` 字段。shim 源码
必须留在包根目录内，不能使用绝对路径或 `..` 路径段。anx 校验并记录链接元数据，不执行清单中提供的命令。

依赖路径相对声明该依赖的 `package.anx` 所在目录解析。名称是否与目标包清单里的 `[package].name` 一致，
要等依赖遍历读取对方清单后才能检查（`AX005`）。

## 诊断收集和排序

字段错误使用 `AX002`；依赖加载和项目布局错误使用独立 `AX` 码。多个可独立发现的问题会保留在报告中；
损坏的依赖分支可能被跳过，其他分支继续检查。诊断稳定按路径（无路径排最前）、码、消息排序。包管理器
命令对任何加载诊断都返回失败；`graph` 则把可用的部分图和诊断一起输出。

| 码 | 含义 | 产出位置 |
| --- | --- | --- |
| `AX001` | 向上找不到项目根 | 项目加载/CLI |
| `AX002` | 清单读取、TOML 解析或字段错误 | manifest loader |
| `AX003` | 依赖目录不存在 | 项目加载 |
| `AX004` | 依赖目录没有 `package.anx` | 项目加载 |
| `AX005` | 依赖 key 与目标包规范名不一致 | 项目加载 |
| `AX006` | 依赖环；项目不可用 | 项目加载 |
| `AX007` | 同名包解析到不同路径 | 项目加载 |
| `AX008` | `src/`、`kind` 或入口文件布局错误 | 项目加载 |
| `AX011` | 使用保留包名 `std` | manifest loader |
| `AX013` | 包源码根彼此嵌套 | 项目加载 |
| `AX015` | 依赖 `kind = "bin"` 的包 | 项目加载 |

`E304`、`E307`–`E310` 是 compiler 的 import 诊断，不是 anx 的 `AX` 诊断，也不会被项目图 loader 收集。
anx 将 compiler 作为子进程调用；`graph` 的 `diagnostics` 只包含清单和项目加载问题。
