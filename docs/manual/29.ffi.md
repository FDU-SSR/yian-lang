# 29 FFI 编译与链接

FFI 的语义检查由编译器完成；`anx` 负责把包的 FFI 权限和 LLVM 原生依赖写入 v2 包图。普通 `ffi fn` 使用 YIAN ABI，`extern "C"` 保留未修饰的 C 符号名和 C 调用约定。公开封装与 C 边界的语言规则见[语言参考](../grammar/17.ffi.md)。

## 解析与语义检查

- `compiler/frontend/` 解析 `ffi fn`、`pub(ffi)`、`extern "C"`、`opaque type`、C 标量、`cptr<T>` 和六个 `@ffi_*` 操作。
- `compiler/analysis/passes/global_resolve.py` 根据源文件归属包判断权限，检查修饰符、导出签名与外部 C 签名；`compiler/analysis/lowering/call_dispatcher.py` 仅允许获准的 `ffi fn` 直接调用外部函数或 FFI 专用函数。
- `compiler/analysis/lowering/builtin_dispatcher.py` 检查封送操作的类型和实参数量。`ffi` 权限按函数定义判定，不从调用者传入；泛型函数具体化时仍按定义处检查。
- `AnalysisSession` 从包图中取得各包的 `ffi` 值。独立编译使用显式 `--allow-ffi`；包模式按每个文件所属包分别判断，依赖关系不传递权限。LSP 使用同一包映射与分析会话。

不完整 C 类型只有经 `cptr<T>` 才有运行时表示。编译期求值不执行 `extern "C"` 调用。

## CFG 与 LLVM

CFG 为外部函数保留符号名和 C ABI 属性，普通 FFI 函数仍按 YIAN 函数生成。LLVM lowering 把 C 标量映射到目标机器整数，把 `cptr<T>` 映射成单个原生指针；raw/fat 模式下 C 调用边界的表示相同。`compiler/codegen/llvm/emitters/ffi.py` 处理地址提取、切片拆包、空指针、指针转换和字节复制。

地址提取先执行当前模式可用的 YIAN 来源检查。复制检查 YIAN 一侧的切片范围，C 一侧的地址有效性由绑定承担。FFI 操作不把 C 地址伪装成 YIAN 胖指针，也不开放修改胖指针元数据的通道。

## 包图与原生链接

`anx/project.py` 为每个包写入 `ffi: bool`，有 `[native.llvm]` 时再写入 `nativeLLVM`（`major`、`components`、`sources`）。`compiler/analysis/package_map.py` 再次校验这些值及 C shim 的包内路径。`anx test` 的合成包映射也保留依赖包的权限和原生元数据。

`compiler/native_link.py` 对构建可达包收集 LLVM 组件和 C shim，核对 Linux x86-64 LP64、`llvm-config` 的主版本 22 及链接器目标。构建命令使用参数数组；清单不会作为 shell 命令执行。`-t exe` 编译 shim 后链接运行时、LLVM 组件及系统库；`-t obj` 把 shim 与运行时合并为可重定位对象，外部 LLVM 符号留待最终链接；`-t ll`、`-t bc`、`-t asm` 不执行最终链接。独立编译的 `--link-lib` 和 `--link-search` 只在生成可执行文件的链接步骤使用。

`bootstrap/ffi` 提供 C 字节复制辅助函数；`bootstrap/llvm` 使用 LLVM C API 构建结构化 IR。其公开 `Module` 拥有 context、module、builder 和目标机资源，`Builder`、`Function`、`Global` 以及 IR 类型、值和基本块是非拥有视图。调用者显式关闭 `Module` 一次，并停止使用其副本和子视图；外部句柄没有自动生命周期检查。LLVM 返回的消息和缓冲区先复制到 YIAN 存储，再按 LLVM API 释放。

## 验证边界

`tests/package/ffi_*` 覆盖权限、签名、标量/输出参数、封送、包间导入及 LLVM IR、bitcode、object 生成；项目测试在 raw/fat 模式运行。测试通过不能证明手写 C 声明与头文件一致，也不能证明外部地址的范围或资源释放正确。FFI 绑定本身属于可信代码边界。
