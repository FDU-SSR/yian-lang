# 04 全局符号解析

`compiler/analysis/passes/global_resolve.py` — 跨文件符号与类型解析，使用本次分析的共享 `SemanticState`。

## 三阶段解析

```
Phase 1: collect  — 收集所有单元的顶层符号
Phase 2: import   — 解析跨文件 import
Phase 3: resolve  — 解析类型定义（字段、方法签名）
```

## Import 解析

`from std.core.option import Option` 映射为 `lib/src/core/option.an`。

在 Standalone 模式下，`from adder import adder` 相对于导入文件的父目录查找 `adder.an`。

在 Package 模式下（`--packages`），第一段路径被作为包名解析，余下各段在包的源码根下查找 `.an` 文件：

```text
from myapp.utils.math import add    →  {myapp.sourceRoot}/utils/math.an
from std.core.io import print        →  {std.sourceRoot}/core/io.an
```

包图由 `--packages pkg.json` 传入，遵循 v2 契约：顶层 `format: 2` 与 `root`，外加一张
`packages` 表，每个包带 `sourceRoot`、`kind`、`entry`、`dependencies`（见
[23 依赖图与 v2 包图](23.anx_graph.md)）：

```json
{
  "format": 2,
  "root": "myapp",
  "packages": {
    "myapp": { "sourceRoot": "/path/to/myapp/src", "kind": "bin",
               "entry": "/path/to/myapp/src/main.an", "dependencies": ["utils"] },
    "utils": { "sourceRoot": "/path/to/yian-utils/src", "kind": "lib", "dependencies": [] },
    "std":   { "sourceRoot": "/path/to/yian/lib/src", "kind": "lib", "dependencies": [] }
  }
}
```

`compiler/analysis/package_map.py` 负责解析与校验这份文档，未知 `format` 直接报错。实现见
`__resolve_import_path()`、`__resolve_package_import()` 和 `PackageMap`。

## 符号上下文

`SymbolCtx` — 每个编译单元的符号作用域栈。`add_symbol(name, kind, type_id)` 注册，`lookup(name)` 查找。
`TypeCtx` 保存类型定义和 impl 查询结构；AST 过程体由独立的 `ProcedureRegistry` 关联到 callable type ID，
不存放在 `TypeCtx` 中。trait 默认方法通过 impl 校验后，把源方法过程体关联到具体实现方法。

`SemanticState` 是本次分析共享的可变状态，组合 `TypeCtx`、`ProcedureRegistry`、`NameReferences`、
`TypeResolver`、包配置和编译单元。`DefinitionState` 则由类型检查器逐 definition 使用，保存当前符号作用域、
局部变量和控制流遍历状态。

## 类型解析与名称引用

`compiler/analysis/resolution/types.py` 的 `TypeResolver` 接收 `TypeCtx` 和当前 `SymbolCtx`，把 AST 类型
转换为类型 ID。解析出的源码名称记录在 `compiler/analysis/facts/names.py` 的 `NameReferences` 中；它按
路径、行、列去重并忽略合成位置。类型解析与名称引用记录不属于 `TypeCtx` 的接口。

## 类型定义解析

`__resolve_struct` / `__resolve_enum` / `__resolve_trait` / `__resolve_impl` 将 AST 类型定义转为 `TypeCtx` 中的类型对象。

## Impl 条件解析

`impl<T> Foo for T if T: Bar` 中的 `if T: Bar` 解析为 `conditions = {T_generic_id: [Bar_trait_type_id]}`，存储在 `Impl.conditions`。
