# 20 anx 概览

`anx` 是仓库的 YIAN 包管理器，源码位于 `anx/`，以 YIAN 编写并作为原生程序安装。日常命令严格选择
native `yianc`；Python 恢复编译器位于 `python/yianc/`，只服务显式冷启动兼容性。用户视角的命令见
[anx 用户指南](../anx/index.md)。

## 职责

`anx` 提供七个子命令：`new` 创建项目；`build`、`run`、`check` 编译或检查项目；`test` 运行项目测试；
`fmt` 格式化根包源码；`graph` 展示项目、文件归属、依赖和诊断。

包管理器读取 `package.anx`，解析依赖并索引 `.an` 源文件，再写入编译器使用的 v2 包映射
`<root>/build/pkg.json`。构建时它以参数数组调用 `yianc`，传入该映射、普通依赖闭包中的源文件和受支持的
编译选项。日常调用只选择 native compiler，不回退到 Python；源码解析、类型检查和代码生成由 native `yianc` 完成。

## 原生模块地图

| 文件 | 职责 |
| --- | --- |
| `anx/src/main.an` | 命令分发、`std.cli` 参数解析、退出码 |
| `manifest/load.an`、`manifest/model.an` | TOML 文档读取、字段校验、拥有型清单数据 |
| `diagnostics/model.an` | `Diagnostic` 数据及显式释放 |
| `project/load.an`、`project/model.an` | 依赖遍历、布局检查、源码索引和项目所有权 |
| `project/package_map.an` | 写入 compiler 消费的 v2 `pkg.json` |
| `project/graph.an` | 文本及 JSON 项目图 |
| `project/paths.an` | 解析标准库源码根 |
| `driver/build.an` | 构建、检查、运行及 compiler 子进程 |
| `driver/test.an` | 项目测试发现、合成包映射、逐用例编译与比较 |
| `driver/profile.an` | 可选的命令计时、compiler 报告关联、聚合和 JSON/文本输出 |
| `driver/fmt.an`、`driver/new.an` | 根包格式化和项目脚手架 |

实现使用 `bootstrap/toml` 解析清单，使用 `bootstrap/json` 写图与包映射；编译器进程及源码收集来自
`lib/src/` 和 `yianc/`。原生语言服务器直接导入 `anx` 的项目加载模块。

## 一次 `anx build` 的数据流

```text
discover(start)                   向上找最近的 package.anx
  → standard_library_root()       YIAN_LIB → YIAN_ROOT/lib/src → 安装关联资源
  → load(root, std_root)          读取根清单及 dependencies/dev-dependencies
  → 依赖遍历与环检测              收集 AX 诊断；环返回 AX006
  → 检查 src/、kind、entry        为每个可用包建立布局
  → 收集 .an 并按最深源码根归属   建 Project.files
  → 写 build/pkg.json             不改变 v2 contract
  → 启动 YIANC 或 PATH 上的 yianc  传入普通依赖闭包；build/run 用 -t exe，check 用 --check；profile 启用时附加独立报告路径
```

项目加载返回拥有型 `LoadReport`，其中包含可选 `Project` 与诊断向量。`build`、`run`、`check`、`test` 和
`fmt` 打印诊断，并在存在任何诊断时停止；`graph` 仍可打印部分项目及诊断，退出码表示是否有诊断或项目不可用。

`check` 以 `--check` 调用 compiler，只做前端与中端检查，不生成产物；`build` 和 `run` 生成 `build/app`，`run` 编译成功后启动程序。
`build_files()` 只包含根包、`std` 和普通依赖的可达闭包，dev 依赖留给 `anx test`。

`build`、`run`、`check`、`test` 的 `--profile` 默认关闭。启用后每次命令使用唯一的
`build/profile/<run-id>/`，子进程报告按调用顺序独立保存并由 anx 关联到测试路径和指针模式。compiler
等待计入编译总耗时，子进程内部 pass 用于解释该等待区间而不重复相加；`run` 和 `test` 启动测试程序后的
时间不计入构建总计。

## 与 compiler 的契约边界

| anx 写入/选择 | compiler 校验/执行 |
| --- | --- |
| 包名、`kind`、入口与源码根 | 程序入口及 `main` 签名 |
| 普通依赖边与每个包的源文件 | import 可见性及模块解析 |
| 每包 `ffi`、可选 `nativeLLVM` | FFI 操作权限、LLVM shim 编译与链接 |
| `format: 2` 的 `build/pkg.json` | v2 schema、包归属、入口和权限 |
| `-O`、`--release`、`--raw-pointers` | 具体编译选项及目标生成 |

`graph --json` 是项目检查/浏览数据，包含包根、依赖、dev 依赖、文件和诊断；它不等同于 `pkg.json`，不提供
完整的 `ffi` 与 `nativeLLVM` 编译配置。版本不为 2 的包映射由 compiler 拒绝。

## 测试与工具矩阵

`scripts/run_tests.py` 仅使用安装的 native compiler。`--pointer-mode both|fat|raw` 默认选择 fat 与 raw 两种目标模式；
`safety` 的 raw 项标为 N/A 并显示原因。兼容参数 `--implementation native` 仍可使用；旧值
`python` 和 `both` 在工具选择前报错。`package` 和 `bootstrap` 套件都经由同一个安装的原生 `anx` 驱动，
`YIANC` 指向检查过身份的 native compiler。运行器只检查 prefix 中已有的工具，不会安装或刷新；缺工具时需
显式运行 cold bootstrap 或 warm refresh。

仓库 package fixtures 位于 `tests/package/`，期望位于 `tests/output/package/`，命令选择位于
`tests/input/package/`。项目自己的测试则由 `anx test` 读取 `<project>/tests/`。测试布局和映射细节见
[25 anx 项目测试与仓库 fixtures](25.anx_tests.md)。`anx test` 默认运行 Both，runner 调用它时会显式指定单一模式。
