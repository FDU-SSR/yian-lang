# 24 CLI 与标准库定位

对应源文件：`anx/src/main.an`、`driver/build.an`、`driver/fmt.an`、`driver/new.an`、
`driver/test.an`、`project/paths.an`。

## 命令与参数

原生 CLI 通过标准库 `std.cli.ArgumentParser` 定义参数；命令分发和参数处理都在 `main.an`。用法为：

```text
anx new <name> [--kind {bin,lib,hybrid}] [--lib]
anx build [project] [-O {0,1,2,3}] [--release] [--raw-pointers]
anx build profile [project] [-O {0,1,2,3}] [--release] [--raw-pointers] [--profile-dir PATH]
anx run   [project] [-O {0,1,2,3}] [--release] [--raw-pointers] [-- program-args...]
anx run profile [project] [-O {0,1,2,3}] [--release] [--raw-pointers] [--profile-dir PATH] [-- program-args...]
anx check [project] [-O {0,1,2,3}] [--release] [--raw-pointers]
anx test  [project] [-O {0,1,2,3}] [--release] [--pointer-mode {both,fat,raw} | --raw-pointers]
anx fmt   [project] [--check]
anx graph [project] [--json]
```

项目参数默认是当前目录；`build`、`run`、`check`、`test`、`fmt` 和 `graph` 从给定位置向上查找最近的
`package.anx`。`new` 的 `--lib` 是 `--kind lib` 的简写。参数解析失败打印 usage 并返回 2；未知命令返回 2。

`run` 在 `--` 处分开 anx 选项与程序参数，后半部分原样作为参数数组传给产物程序。`build`/`run` 产生
`<root>/build/app`；`check` 以 `--check` 调 compiler，不生成可执行文件。`lib` 根包不能用 `build` 或 `run`
生成可执行产物，只能 `check` 或作为依赖。`--release` 在没有显式 `-O` 时映射为 `-O 3`，显式 `-O` 优先。

`profile` 是 `build` 与 `run` 的子命令，项目参数放在其后。`build profile` 只编译并写编译统计，
产物仍为 `<root>/build/app`，不运行程序。`run profile` 使用 `--runtime-profile-dir` 触发插桩构建，
把本次产物写到 `<root>/build/runtime-profile-artifacts/<run-id>/app`，运行该产物并写运行时统计；
普通 `build/app` 不被覆盖。两个命令都接受 `--profile-dir PATH`，相对路径以项目根解析，缺省根分别为
`<root>/build/profile` 与 `<root>/build/runtime-profile`，每次调用使用唯一 run 目录。

`build profile` 的报告包含 anx 项目加载、package map、compiler 等待、compiler pass、runtime/C shim
编译和链接阶段；compiler 等待区间已经包含子进程计时。`run profile` 的报告只统计程序运行：按实际进入
逐次计数，使用 `CLOCK_MONOTONIC` 经过时间，包含子调用累计与扣除直接子调用后的自身耗时，并按完整调用
路径保留调用树。函数身份包含包、模块、源码行列、类别、方法所属类型和具体泛型实参。递归下累计耗时
可以重叠，不能把父子值相加当作程序总时间；报告不校正插桩开销，也不展开 C/系统库。

只有 `main` 自然返回并正常收尾且 profiling 无故障时保证 `run profile` 的双报告；`exit`、panic、
安全错误、信号或崩溃不保证报告。采集、时钟、分配或报告 I/O 故障属未定义行为，不承诺部分数据。
四个旧的 `--profile` 参数在编译前作为参数错误退出 2，并提示 `anx build profile`；`run` 的 `--`
之后内容原样传给程序。

构建 driver 将参数逐项传给 compiler，不经 shell：`--packages <root>/build/pkg.json`、目标、输出路径、选项和
普通依赖闭包的源文件。工作目录设为项目根。非零 compiler 状态使包命令失败；`run` 在编译后直接返回程序状态，
启动时被中断对应 130。

## compiler 选择

`driver/build.an` 与 `driver/test.an` 选择 compiler 的优先级相同：非空 `YIANC`，否则 `PATH` 上的 `yianc`。
原生 anx 没有 Python compiler 回退。仓库测试 runner 只使用已安装的 native compiler，并在调用 package
commands 前把 `YIANC` 设为规范化后的 native 路径。

## 标准库定位

`project/paths.an::standard_library_root()` 按以下顺序选择标准库源码根：

1. 非空 `YIAN_LIB`：该路径本身就是标准库源码根。
2. 非空 `YIAN_ROOT`：使用 `<value>/lib/src`。
3. 与安装的 compiler/toolchain 关联的 checkout 或资源根，再取 `lib/src`。

指定路径不存在或无法解析时会报告错误。anx 将找到的根写入 package map 的特殊 `std` 包；compiler 在 package
mode 下据此检查来源与信任边界。anx CLI 不提供 `--compiler-root` 参数。

## 其他命令

- `anx graph --json` 输出机器可读的项目、依赖、源文件归属和诊断。即使有诊断也尝试输出；有诊断或项目不可用时
  返回 1。
- `anx fmt` 只格式化根包自己的索引源文件。默认写回；`--check` 列出需格式化文件并在有差异时返回 1。
- `anx new` 创建 `package.anx`、`src/main.an`（`lib` 除外）、通过的 `tests/smoke.an`、期望输出和 `.gitignore`。
  目标目录已存在时失败，不覆盖原目录。
- `anx test` 使用根包的 `tests/`，默认运行 fat 与 raw 两种指针模式；`--pointer-mode` 选择两种或单种模式，
  `--raw-pointers` 是 raw 别名，两者不能同时使用。测试发现和合成 package-map 见[25](25.anx_tests.md)。
