# 26 分析接口

`yianc` 在前端处理完成后把 `FrontendSession` 交给 `MiddleEndDriver`，由 `AnalysisSession` 持有源码、单元、符号、类型和 HIR。分析会话按准备、分析中和完成或失败的顺序转换。会话内 ID 的有效范围是该会话；诊断跨越会话生命周期时使用拥有路径的位置记录。

`AnalysisOptions` 控制入口检查、恢复模式、HIR 验证和目标布局查询。`MiddleEndDriver.run(options)` 返回 `AnalysisReport`。驱动提供分析输出的借用和所有权转移入口。释放分析会话之前先释放引用其记录的输出。

## 命令行与编辑器

`yianc --check` 从磁盘输入运行前端和语义检查，输出文本诊断。LSP 使用 `lsp/src/analysis/compiler.an` 将编辑器文档交给 `FrontendDriver.prepare_documents`，再运行严格语义分析，并在快照中维护编辑器查询需要的索引和独立位置。

LSP 接收 UTF-16 代码单元列坐标，使用标准库的 `LineIndex` 转换至编译器源码坐标。文档覆盖层、调度、协议和快照范围见[语言服务器](27.language_server.md)。包模式的源码归属与可见性见[依赖图与包图](23.anx_graph.md)。
