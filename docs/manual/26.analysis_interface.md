# 26 分析接口

`python/yianc/analysis/` 提供 Python 编译器的分析会话和协议无关查询接口。原生语言服务器使用
`bootstrap/yianc/` 中对应的编辑器分析 API，并由根目录 `lsp/` 负责协议适配
（[27 语言服务器](27.language_server.md)）。

对应源文件：`python/yianc/analysis/session.py`、`documents.py`、`facts/names.py`、`package_map.py`、
`queries/context.py`、`queries/index.py`、`queries/view.py`、`queries/navigation.py`、
`queries/completion.py`、`queries/refactor.py`、`diagnostics.py`、`source_provenance.py`、
`python/yianc/frontend/lex/position.py`、`python/yianc/interop/positions.py`

## 分层与依赖方向

| 层 | 位置 | 内容 | 消费者 |
| --- | --- | --- | --- |
| Python 语言引擎 | `python/yianc/analysis/` | Python 编译器的会话、名字引用、声明索引和查询接口 | Python 编译器 CLI 与分析工具 |
| 原生语言引擎 | `bootstrap/yianc/src/analysis/` | 自举编译器会话、编辑器事实、诊断与查询 | 原生 `yianc`、`lsp/` |
| 协议坐标 | `python/yianc/interop/positions.py`、`bootstrap/lsp_protocol/` | LSP UTF-16 坐标、URI 与协议模型 | Python 编译器诊断、原生 `lsp/` |
| 项目模型 | `python/anx/`、`bootstrap/anx/` | 项目发现、依赖与导入规则、v2 包图 | 对应版本的 `anx`、`lsp/` |
| 协议服务 | `lsp/` | 原生协议适配、进程形态、文档版本与请求调度 | 所有 LSP 客户端 |

原生依赖方向为 `lsp/ → bootstrap/yianc/ + bootstrap/anx/ + bootstrap/jsonrpc/ + bootstrap/lsp_protocol/`。
编译器语义层不依赖 LSP 协议；项目模型不依赖编译器语义层。Python 与原生编译器分别提供自己的
`AnalysisSession` 与查询 API。

## 分析阶段

`AnalysisSession.analyze()` 有语法分析与完整分析两种模式。语法分析在去糖后返回；完整分析继续运行：

```text
lex
→ parse
→ desugar
→ prelude 注入
→ 受限操作检查
→ 全局解析（GlobalResolve）
→ type_ctx.finalize()
→ 类型检查（TypeCheck，包含编译期分支选择）
→ 模式覆盖检查（MatchCoverage）
→ 确定赋值分析
```

**不跑**的部分：闭包具体化、CFG 下降、LLVM 下降与生成。因此一次分析不会调用 clang、不会链接、不产生
任何构建产物。语法分析模式仅运行 lex、parse、desugar，适用于编辑期间的轻量诊断。

`TypeCtx` 在 `GlobalResolve` 之后封闭类型与 impl 注册，`finalize()` 启用依赖完整注册集合的查询缓存。

## 文档与会话

分析读**文档**（覆盖层优先，未被打开的文件回落到磁盘）：

```python
@dataclass(frozen=True)
class Document:
    path: Path
    text: str
    version: int | None = None

class DocumentStore:
    def add(self, document: Document) -> None: ...
    def remove(self, path: Path) -> None: ...
    def text(self, path: Path) -> str: ...        # Prefer overlays, otherwise read disk.
    def version(self, path: Path) -> int | None: ...
```

`DocumentStore` 是「内存文本盖在磁盘之上」的覆盖层：编辑器打开的缓冲区进覆盖层，标准库和未被
打开的依赖仍从磁盘读。`collect_an_files(paths, overlay=…)` 把路径展开成文件列表——`.an` 文件按原样
接受，目录递归搜索，只存在于覆盖层里的新 `.an` 文件也被接受。存在的非 `.an` 文件被忽略；
不存在且不在覆盖层里的路径抛 `FileNotFoundError`。

```python
class AnalysisSession:
    def __init__(self, *, compiler_root: Path | None = None,
                 packages: PackageMap | None = None,
                 raw_pointers: bool = False,
                 type_size_factory: TypeSizeFactory) -> None: ...

    @property
    def std_root(self) -> Path: ...

    def analyze(self, paths: Sequence[Path], *,
                documents: DocumentStore | None = None,
                require_entry: bool = False,
                syntax_only: bool = False,
                entry_optional: bool = True,
                recover: bool = True,
                capture_ast_dump: bool = False) -> AnalysisResult: ...

```

- 会话很便宜：标准库根、包映射与指针模式在构造时解析一次，之后每次 `analyze()` 都从文本重新开始。
- `packages` 给出 `PackageMap` 时进入包模式，标准库根取 `packages["std"].source_root`；否则用
  `resolve_stdlib_root(compiler_root)`（见「项目模型与包映射」）。
- `require_entry=True` 才要求包声明程序入口；编辑器默认 `False`。`entry_optional` 控制完整分析是否接受
  缺少或重复的 `main`；`recover=True` 时可恢复的定义级错误会收集并继续检查其他定义。
- `type_size_factory` 提供 comptime 求值所需的目标布局查询；`capture_ast_dump` 控制是否附带 AST dump。

## AnalysisResult 与查询上下文

`AnalysisResult` 保存一次分析产生的诊断、源码文本、词法 token、分析单元、符号与类型事实、别名信息、名字引用、
导入边和阶段耗时。它提供 `ok()` 与 `formatted()`，但不保存声明索引、文档版本或快照键。
Python 会话每次都从输入文本重新运行分析。原生语言服务器在 `lsp/src/workspace/documents.an` 管理打开文档，
并在协议服务中维护修订、同步输入和当前分析快照。

完整分析结果由 `QueryContext` 包装。它根据 `import_edges` 创建可选的 `LazyIndex`，让查询层按需取得
声明数据；未生成导入边的早期失败结果没有索引。`AnalysisResult` 是可变数据对象，查询约定只读取其中的
事实；工作区使用自己的快照修订号拒绝过期结果。

失败信息通过 `failed_stage` 和 `diagnostics` 表达。普通编译会话的词法与语法阶段在第一个错误处停止；完整分析启用
`recover=True` 时，检查器会收集可恢复的定义级诊断并继续处理其他定义。`def_points` 记录类型检查器
处理过的定义，重命名据此识别未检查的泛型体。编辑器专用的局部恢复与查询可用性见下文。

### syntax_only

`syntax_only=True` 只运行 lex、parse 与 desugar：

- 成功时 `diagnostics` 为空，且结果没有类型空间、导入边或查询索引；
- 前端失败返回带源码位置的诊断；词法成功后发生的失败也保留 token；
- 完整分析还运行 prelude 注入、受限操作检查、全局解析、类型检查及编译期分支选择、模式覆盖与确定赋值分析。

## 编辑器错误恢复与查询完整性

编辑器入口为仍在输入的文档提供只读查询，因此它会单独处理不完整或有错误的源文件。Python 与原生编辑器
分析都会保留可解析的文档和互不依赖的声明，并在快照中记录语法完成状态、恢复区域、词法停止位置和整体
语义完整性。严格编译入口仍会对错误源文件报告失败；编辑器恢复不会把这些文件变成可编译程序。

查询完整性按查询位置和所需语义事实判断，而不只看整份分析是否成功：补全、签名帮助、文档符号和语义 token
可以使用仍然可靠的局部事实；若光标位于不可恢复区域，或成员查询缺少可靠的接收值类型，查询会标记为
partial 或 unavailable，而不会猜测类型与候选。一个文件的错误也不必使其他文件中独立且可靠的查询全部失效。

重命名会要求完整的引用信息。若语法或语义恢复使引用集合不完整，`prepare rename`/rename 会拒绝编辑；
只读查询可在部分信息上继续工作，不代表可以安全地批量修改源码。

## 位置模型

编译器内部的位置使用 `SrcPosition(row 0 基, col 0 基、按 Unicode 代码点计数, Path)`，`SrcSpan` 由两个
`SrcPosition` 组成。编辑器说 LSP：行 0 基、字符按 UTF-16 代码单元、`file://` uri。

Python 编译器的 `python/yianc/interop/positions.py` 转换这两套坐标；原生协议实现使用
`std.core.text.LineIndex` 与 `bootstrap/lsp_protocol/` 中的位置模型：

```python
def utf16_length(text: str) -> int: ...
def to_lsp_position(row: int, line_text: str, col: int) -> dict[str, int]: ...
def to_compiler_column(line_text: str, character: int) -> int: ...
def to_lsp_range(span: SrcSpan, text: str) -> dict[str, dict[str, int]]: ...
def path_to_uri(path: Path) -> str: ...
def uri_to_path(uri: str) -> Path: ...
```

列转换需要整行文本，因为 UTF-16 代码单元和代码点在第一个非 BMP 字符之后就不同。`to_lsp_range`
使用**文档当前文本**，所以未保存缓冲区的范围仍然准确。编译器诊断、名字引用与查询参数都使用内部
坐标；LSP 消息和 `yianc --analyze --json` 在输出边界转换为 LSP 位置。

## 名字引用表

导航、补全、语义高亮、查找引用/重命名都基于两张表，而不是重新从文本里猜：

| 表 | 生产者 | 内容 |
| --- | --- | --- |
| 名字引用 | 语义检查通过 `NameReferences.record(span, target, expression_type=None)` 记录，结果保存在 `AnalysisResult.name_refs` | `NameRef(span, target, expression_type)`，`target` 是 `Symbol \| AliasSymbol \| StructField \| EnumVariant \| int`（`int` 是类型 id） |
| 声明索引 | `QueryContext` 在完整分析结果上创建 `LazyIndex`；读取索引属性时调用 `build_index(...)` | 每个声明的名字 span、种类、容器、可见性 |

`NameReferences.record` 对同一文件、行、列只保留首次解析结果，并忽略合成 span。`AnalysisResult.name_refs`
按首次记录顺序保存这些事实。引用表负责「这个名字用在哪、指的是谁」，声明索引负责「这个名字在哪声明」。

## 查询模块

查询层只读**事实**：`AnalysisView` 是唯一接触编译器内部（`TypeCtx` 与声明索引）的只读层，
`Navigator` 在它之上只加一件事——把位置解析成声明。其余查询模块（补全、引用、重命名）都经过这两
者，不直接访问 `TypeCtx`（生产者 `session.py`、`index.py` 例外，它们本来就在构建这些结构）。

```python
class AnalysisView:                       # python/yianc/analysis/queries/view.py

    def has_declarations(self, path) -> bool: ...  # Whether this result contains a declaration index.

    def module_file(self, dotted: str) -> Path | None: ...
    def package_names(self) -> tuple[str, ...]: ...
    def module_names(self) -> tuple[str, ...]: ...
    def dependents_of(self, path) -> tuple[Path, ...]: ...
    def import_statements(self, path) -> tuple[SrcSpan, ...]: ...

    def name_refs(self) -> tuple[NameRef, ...]: ...

    def references_of(self, path) -> tuple[NameRef, ...]: ...
    def reference_in_span(self, span) -> NameRef | None: ...
    # Units, symbols, and definition bodies.
    def unit_of(self, path) -> UnitData | None: ...
    def unit_path(self, unit_id: int) -> Path | None: ...
    def has_symbols(self, path) -> bool: ...

    def symbol_named_in(self, path, name: str) -> Symbol | AliasSymbol | None: ...
    def alias_info(self, symbol: AliasSymbol) -> AliasInfo | None: ...
    def alias_signature(self, symbol: AliasSymbol) -> str | None: ...
    def def_points(self) -> Mapping[int, DefPoint]: ...

    @property

    def type_of(self, type_id) -> Type.Ty | None: ...

    def methods_of(self, type_id) -> tuple[tuple[str, int], ...]: ...
```

它只读不写，答不出来就返回 `None` 或空元组（未知类型 id、没解析过的名字、parser 没见过的 span），
绝不给一个看起来合理的默认值。视图按请求创建，因此它的有效期和它基于的快照一样长。

### Navigator

```python
class Navigator:
    def __init__(self, context: QueryContext, *, std_root: Path | None = None) -> None: ...
    @property
    def view(self) -> AnalysisView: ...
    def text_of(self, path: Path) -> str: ...
    def tokens_of(self, path: Path) -> tuple[Token, ...]: ...
    def declarations_in(self, path: Path) -> tuple[Declaration, ...]: ...
    def declarations_by_name(self, name: str) -> tuple[Declaration, ...]: ...
    def module_of(self, path: Path) -> str | None: ...
    def enclosing_definition_name(self, path: Path, row: int, col: int) -> str | None: ...
    def resolve(self, path: Path, row: int, col: int) -> Resolution | None: ...
    def reference_starting_at(self, path: Path, row: int, col: int) -> NameRef | None: ...
    def declaration_starting_at(self, path: Path, row: int, col: int) -> Declaration | None: ...
    def target_of(self, target: NameTarget) -> Target | None: ...
    def target_of_declaration(self, declaration: Declaration, path: Path) -> Target | None: ...
    def all_references(self) -> tuple[NameRef, ...]: ...
    def reference_in_span(self, span: SrcSpan) -> NameRef | None: ...
```

`resolve()` 是核心：先在引用表里找覆盖该位置的最内层名字，找不到再退到声明索引（声明处是「名字
被引入」而不是「被使用」）。它返回 `Resolution(target, expression_type)`——`target` 回答跳转，
`expression_type` 回答悬停里的表达式类型。位置在注释、空白或分析没检查过的定义里时返回 `None`，
而不是跳到无关位置。

`Target` 携带名字、`DeclarationKind`、名字 span、渲染后的类型或签名、容器名，以及 `stdlib` 标志；
签名是从实例化后的类型渲染的，所以 `Pair<f64>.of` 显示 `f64` 而不是声明处的 `T`。

`Navigator(context, ...)` 内部的事实读取全部委托给视图（`navigator.view`），自己负责位置解析；
它与查询上下文共享同一份分析结果。

定义体的范围是 parser 记下的事实：`AST.Block.span` 只有开括号（错误信息指那里），所以 parser 另外
记录 `end`（闭括号之后），`full_span()` 给出整段；`AST.Import` 同理记录语句的结束位置。上层据此判断
「某个引用是否在某个定义体内」。

### 声明索引

```python
class DeclarationKind(Enum):
    MODULE, IMPORT, FUNCTION, METHOD, STRUCT, ENUM, TRAIT,
    ALIAS, CONSTANT, FIELD, VARIANT, PARAMETER, VARIABLE

@dataclass(frozen=True)
class Declaration:
    name: str
    kind: DeclarationKind
    path: Path
    span: SrcSpan | None      # Name span; None for modules and synthesized declarations.
    container: str | None = None
    type_name: str | None = None
    module: str | None = None
    public: bool = False

def build_index(units, type_ctx, import_edges=None, packages=None, def_points=None) -> Index: ...
```

`Index` 提供 `in_file(path)`、`by_name(name)`、`dependents_of(path)`（直接导入该文件的所有文件），
以及声明元组 `declarations` 和 `imports`、`packages`、`modules` 映射。索引覆盖整个被分析的文件集合，
包括 `main` 不可达的库函数。

`QueryContext` 为包含完整导入边的结果创建**未构建**索引（`LazyIndex`）：它是 `units`、类型空间、
导入边与包映射的投影，在读取索引属性时构建并缓存；`built` 表示缓存是否已经生成。`yianc --analyze`
不读取这个索引。原生语言服务器通过自举编译器的编辑器查询接口使用声明索引。`build_index(...)` 是立即构建
索引的入口，可供需要同步取得索引的一次性调用使用。

类型空间里才有的东西（结构体字段、枚举成员）从类型空间取，它们的 span 是声明时登记的；函数体内的
`let`、`for` 变量、match 载荷绑定、闭包参数与捕获也进索引，统一挂在所在函数名下（块级嵌套不建模）。

### 语义高亮与呈现层

原生 LSP 在 `lsp/src/worker/service.an` 中把自举编译器提供的语义事实转换为 token 分类、编辑范围和
协议结果。Python 查询 API 返回候选、参数名与语义事实数据。

### 补全与签名提示

```python
def complete(context: QueryContext, path: Path, row: int, col: int, *,
             std_root: Path | None = None) -> CompletionResult: ...
def signature_help(context: QueryContext, path: Path, row: int, col: int, *,
                   std_root: Path | None = None) -> SignatureInfo | None: ...
```

补全从 token 流判断位置期望什么：`value`（可见符号、局部变量、基本类型）、`member`（`.` 左侧表达式
的静态类型，先自动解引用再列字段与方法）、`type`、`import_path`（包与模块名）、`import_name`
（目标模块的 `pub` 声明）。局部变量遮蔽模块名，同名项按先到者胜出去重。分析没走到符号表时
（语法错误在前端就停了），退化为「文件里出现过的标识符」，不带种类与类型，只求可用。

可调用项的 `detail` 是渲染好的签名，`parameters` 是参数名列表；插入什么文本（`name(${1:x})` 这样的
snippet）由 `lsp/` 协议层决定。

### 引用、重命名与快速修复

```python
def find_references(context: QueryContext, path: Path, row: int, col: int, *,
                    include_declaration: bool = True,
                    std_root: Path | None = None) -> ReferenceResult | None: ...
def rename(context: QueryContext, path: Path, row: int, col: int, new_name: str, *,
           std_root: Path | None = None) -> RenameResult: ...
```

全部基于**符号身份**：引用算数当且仅当它和当前位置解析到同一个声明，所以不同作用域的同名符号
不会混在一起。重命名会拒绝而不是做一半：

- 新名字不是合法标识符、位置没有可重命名的东西；
- 目标是标准库符号；
- 分析没检查过的定义（例如从未实例化的泛型体）里出现了同名的名字——无法保证引用集合完整。

拒绝时 `RenameResult(refusal=…)`，原生 LSP 把它变成 `RequestFailed`（`-32803`）。别名导入只改导入语句
里的原名，使用处写的是别名，保持不动。

删除无效 import 的快速修复由 `lsp/src/worker/service.an` 根据语句范围和词法 token 生成编辑。

## 项目模型与包映射

- 项目发现、加载、导入规则来自 `anx`：`anx.project.discover` / `anx.project.load`（模块级函数）、
  `Project.files`（只读映射字段）、`Project.resolve_import`。
- `PackageMap.from_document(raw, *, source=…)` 直接接收 `Project.compiler_package_map()` 的 v2 载荷，
  不需要写文件再读回；`PackageMap.parse(path)` 读 `--packages` 文件。两种入口共用同一份校验，未知
  版本直接报错。
- 标准库根用 `resolve_stdlib_root(compiler_root=None)` 定位，优先级是 `--compiler-root`（检出根）、
  `YIAN_LIB`（源码根本身）、`YIAN_ROOT`（检出根），最后回退到本模块所在的检出（editable 安装走这
  一条）。包模式下以 `packages["std"].source_root` 为准。根**从不**从输入路径推断。

## 最小用法

直接用 `AnalysisSession` 对一段未保存文本做一次分析，再取该文件的声明：

```python
from pathlib import Path

from yianc.analysis.queries.context import QueryContext
from yianc.analysis.queries.navigation import Navigator
from yianc.analysis.documents import Document, DocumentStore
from yianc.analysis.session import AnalysisSession
from yianc.target_layout import type_size_provider

source = """\
pub struct Point {
    x: i32,
    y: i32,
}

pub fn origin() -> Point {
    return Point(0, 0);
}
"""

scratch = Path("scratch.an")
documents = DocumentStore([Document(path=scratch, text=source, version=1)])

session = AnalysisSession(type_size_factory=type_size_provider)
result = session.analyze([Path("lib/src"), scratch], documents=documents)
print("ok:", result.ok(), "diagnostics:", len(result.diagnostics))
queries = QueryContext(result)
if queries.index is not None:
    navigator = Navigator(queries)
    for declaration in navigator.declarations_in(scratch):
        print(declaration.kind.value, declaration.qualified_name)
```

输出（在仓库根运行，`lib/src` 是标准库源码根）：

```text
ok: True diagnostics: 0
module scratch
struct scratch.Point
field scratch.Point.x
field scratch.Point.y
function scratch.origin
```

`scratch.an` 只存在于覆盖层，磁盘上没有这个文件；标准库仍从磁盘读取。声明通过 `QueryContext` 与
`Navigator` 查询；一次 `AnalysisResult` 不包含工作区修订或缓存键。

命令行有一个同源的出口：`yianc --analyze [--json] <路径…>` 用同一个 `AnalysisSession` 跑一次前缀，
不开代码生成、不写 `build/`。`--json` 时 stdout 只有一个 JSON 对象（位置已经是 LSP 形状），其余
情况把诊断渲染到 stderr；退出码只区分成功与失败。它是调试与验收手段，不是第二套分析实现。
