# 18 错误处理

## 错误类型层次

```text
Exception
  ├── CompilerError          # compiler/error.py — 内部编译器错误（无 span）
  └── ValueError
        ├── LexError         # compiler/frontend/lex/lexer.py — 词法错误
        ├── ParseError       # compiler/frontend/parse/error.py — 语法解析错误
        ├── AnalysisError    # compiler/analysis/error.py — 语义分析错误
        └── CodegenError     # compiler/codegen/error.py — 代码生成错误
```

`CompilerError` 只有 message；其余四个都携带 `span: SrcSpan`。

## SrcSpan — 源位置追踪

```python
class SrcPosition:
    row: int        # 0-indexed
    col: int        # 1-indexed
    path: Path      # 源文件路径

class SrcSpan:
    start: SrcPosition
    end: SrcPosition
```

每个 token 和 AST 节点携带 `span`，用于错误定位；`SrcSpan.empty()` 给出无位置的零宽 span。

## 诊断渲染

`compiler/analysis/diagnostics.py` 把异常转成结构化 `Diagnostic`（code + severity + message + span + recovered）：

```python
def diagnostic_from_error(error, *, stage=None, recovered=False) -> Diagnostic
def format_source_error(diagnostic: Diagnostic, text: str) -> str
```

`diagnostic_from_error` 按异常类型与 `stage` 选择错误码（E1xx 词法、E2xx 语法、E3xx 名字/导入/可见性、E4xx 类型、E5xx 其他编译期检查），无法归类的异常落到 `E599`，不以 traceback 逃出。`format_source_error` 用调用方传入的当前文本渲染 `error[Exxx]: message` 与源码行定位。

`compiler/main.py::__report_error` 是 CLI 的统一出口：把错误渲染到 stderr 后抛出内部 `_CompilationFailed`，由 `main()` 转成退出码 1。

## 各阶段错误传播

| 阶段 | 错误类型 | 处理方式 |
|------|---------|---------|
| Lex | `LexError` | `__report_error` → 渲染到 stderr → 退出码 1 |
| Parse | `ParseError` | 同上 |
| Desugar | — | 不产生新错误 |
| RestrictedOps | `AnalysisError` | `__report_error` |
| Resolve | `AnalysisError` | `__report_error` |
| TypeCheck | `AnalysisError` / `CompilerError` | `__report_error` / 打印后返回 1 |
| ComptimeIf | `AnalysisError` | `__report_error` |
| DefiniteAssignment | `AnalysisError` | `__report_error` |
| CFG | `CodegenError` | `__report_error` |
| LLVM | `CodegenError` | `__report_error` |
| Emit | `RuntimeBuildError` / llvmlite 异常 | 打印原因并退出 1；其他 llvmlite 异常以 traceback 结束 |
