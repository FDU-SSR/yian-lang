# 05 类型系统

类型系统由 `compiler/analysis/ty/` 目录下的模块实现。

## 架构

```text
TypeCtx (context.py)         ← 外部接口
  ├── TypeSpace (space.py)   ← 类型 ID 分配与存储
  ├── TypeResolver           ← 类型表达式解析
  ├── TypeFormatter          ← 类型名格式化
  └── ImplRegistry (impl.py) ← impl 注册与查找
```

## TypeCtx

`compiler/analysis/ty/context.py` — 编译器全局单例，持有所有类型信息的中央注册表。

```python
class TypeCtx:
    def __getitem__(self, type_id: int) -> Type.Ty  # 按 ID 查询类型
    def get_name(self, type_id: int) -> str           # 人类可读类型名
    def alloc_pointer(self, pointee: int) -> int      # 分配指针类型
    def alloc_slice(self, element: int) -> int         # 分配切片类型
    def method_lookup(self, ...) -> LookupResult       # 方法查找
```

**预分配类型 ID**：基础类型在 `TypeSpace.__add_intrinsic_types` 中预分配固定 ID：

```python
i32_id = 4, u64_id = 11, bool_id = 2, str_id = 3, ...
```

**Intrinsic Custom Types**：运算符 trait 等自定义 intrinsic 类型也有预分配 ID：

```python
add_id = 20, partial_eq_id = 39, index_id = 43, ...
add_assign_id = 90, ...
```

这些 ID 与 `alloc_trait` 中的 `intrinsic_mapping` 对应，确保 lib 中定义的 trait 拿到正确的预分配 ID。

## TypeSpace

`compiler/analysis/ty/space.py` — 类型 ID 分配器。

- `__next_id` 从 500 开始（0-499 为 intrinsic 预留）
- 各类缓存：指针缓存、切片缓存、数组缓存、元组缓存、函数指针缓存、实例缓存
- `__add_intrinsic_types()` 在 `__init__` 中调用，注册所有基础类型

## Ty 类型层次

`compiler/analysis/ty/ty.py` — 所有类型的 dataclass 定义。

```python
Ty = VoidType | NeverType | BoolType | CharType | StrType
    | IntType | FloatType | IntLiteralType | FloatLiteralType
    | PointerType | NullPtrType | SliceType | ArrayType | TupleType
    | StructType | EnumType | TraitType | AliasType
    | MethodType | FunctionType | FunctionPointerType
    | GenericType | ConstGenericType | LiteralValueType
```

### IntType

```python
@dataclass
class IntType:
    type_id: int
    size: int       # 字节: 1, 2, 4, 8
    signed: bool
```

### PointerType

```python
@dataclass
class PointerType:
    type_id: int
    pointee_type: int  # 指向的类型的 ID
```

### StructType / EnumType

```python
@dataclass
class StructType:
    type_id: int
    custom_def: StructDef     # 包含字段列表、泛型参数
    generic_args: list[int]

@dataclass
class EnumType:
    type_id: int
    custom_def: EnumDef       # 包含变体列表
```

### TraitType / MethodType

```python
@dataclass
class TraitType:
    type_id: int
    custom_def: TraitDef      # 包含方法声明、泛型参数

@dataclass
class MethodType:
    type_id: int
    custom_def: MethodDef     # 包含 receiver_type、parameters、return_type、is_static
    generic_args: list[int]
```

### FunctionType 与 FunctionPointerType

- `FunctionType`（函数项）——具名函数的**按定义唯一**类型，包裹特定 `FunctionDef`。
  两个签名相同的函数拥有**不同**的 `FunctionType`。它是 **ZST**（`is_zst` 对其返回
  `True`）：函数身份编码在类型里，值不携带运行期比特。`let f = foo` 得到的即是此类型。
- `FunctionPointerType`（函数指针 `fn(...)->...`）——派生的指针类型，按签名相同则相同，
  **非** ZST（携带地址），经 `&foo` 或标注获得。

LLVM 侧：函数项作为**值**擦除为 `{}`（空结构体），但函数**自身签名**仍需真实的
`ir.FunctionType` 来声明/调用，故 `LLTypeCtx.get_ll_func_type` 绕过 ZST 擦除单独构建签名
（方法一并走此路径）。详见 `12.llvm_codegen.md`。

## 泛型推断

`compiler/analysis/ty/generic_inference.py` — `GenericInference` 类。

```python
class GenericInference:
    def constrain(self, a: int, b: int) -> None   # 约束 a = b
    def substitutions(self) -> dict[int, int]       # 解出泛型 → 具体映射
    def instantiate(self, type_id: int) -> int      # 应用 substitution
```

约束求解在 `__solve()` 中完成，绑定分辨率按泛型 ID 确定性顺序处理。

## 简单类型

早期版本用 `is_simple_type()`（`TypeCtx`）区分简单/非简单类型，用于强制非简单类型在赋值前显式复制（move/clone 调用）。该机制已于 2026-08-23 随赋值约束一并移除——现在所有类型赋值均为按位复制，无简单/非简单之分。

`type_ops.py` — 类型统一、子类型检查、`default_literals`（将 `IntLiteralType` / `FloatLiteralType` 消解为默认具体类型）。
