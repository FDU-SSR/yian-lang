# 02 前端

前端将 `.an` 源文件转换为 AST。分为词法分析（Lexer）和语法分析（Parser）两个阶段。

## Lexer

`compiler/frontend/lex/lexer.py`

### CharStream

```python
class CharStream:
    def __init__(self, path: Path)     # 读取源文件
    def peek(self, offset=0) -> str     # 查看当前字符
    def advance(self) -> str            # 消费并前进
    def at_end(self) -> bool            # 是否到文件尾
```

逐字符扫描，维护当前行列位置用于 `SrcSpan`。

### Lexer

```python
class Lexer:
    def __init__(self, path: Path)
    def lex(self) -> None              # 执行词法分析
    def export(self) -> list[Token]    # 导出 token 列表
```

**主循环** (`lex()`):

```python
while True:
    prev_was_ws = self.__skip_ignored()   # 跳过空白/注释
    token = self.__next_token(prev_was_ws) # 识别下一个 token
    self.__tokens.append(token)
    if token is EOF: break
```

**`__next_token(prev_was_ws)`** 逐字符识别 token 类型：
- 字母/下划线开头 → 标识符或关键字
- 数字开头 → 整数字面量（支持 `0x` 十六进制、类型后缀）
- `"` 开头 → 字符串字面量
- `'` 开头 → 字符字面量
- `b'` 开头 → 字节字面量
- 标点符号 → 运算符或分隔符

### 空白敏感性

Yian 的关键设计：通过空白上下文区分歧义 token。

```python
if prev_was_ws:
    # '<' → Less (小于), '>' → Greater (大于), '>>' → GreaterGreater (右移)
else:
    # '<' → LAngle (泛型括号), '>' → RAngle, '>>' → 两个 RAngle
```

这一设计消除了 parser 层面的 C++ 式 `>>` 歧义。

### Token 类型

`compiler/frontend/lex/token.py`

```python
Token = Keyword | Identifier | Punctuator | Literal

# Keyword: if, else, fn, struct, ...
# Identifier: 用户定义名称
# Punctuator: +, -, {, }, [, ], ...
# Literal: IntLiteral, FloatLiteral, CharLiteral, StrLiteral, BoolLiteral, NullptrLiteral
```

每个 token 携带 `span: SrcSpan` 用于错误定位。

## Parser

`compiler/frontend/parse/parser.py` + `parser_expr.py` + `parser_type.py`

### 架构

```text
Parser (parser.py)          ← 顶层声明: fn, struct, enum, trait, impl, import
  └── ExprParser            ← 表达式 (Pratt parser)
  └── TypeParser            ← 类型表达式
```

### Parser — 顶层声明

```python
class Parser:
    def parse(self) -> AST.Program:
        while not at_end:
            match peek():
                case Import | From → parse_import()
                case Fn           → parse_func_def()
                case Struct       → parse_struct()
                case Enum         → parse_enum()
                case Trait        → parse_trait()
                case Impl         → parse_impl()
                case Typedef      → parse_alias()
```

### ExprParser — Pratt Parser

```python
class ExprParser:
    def parse_expr(self) -> AST.Expr:
        return self.__parse_expr_bp(min_bp=1)

    def __parse_expr_bp(self, min_bp: int) -> AST.Expr:
        lhs = self.__parse_prefix()           # 前缀: 字面量, 标识符, (, if, loop, ...
        while True:
            op = BinaryOperator.try_from_token(peek())
            if op is None or op.lbp < min_bp: break
            advance()
            rhs = self.__parse_expr_bp(op.rbp) # 右结合力
            lhs = AST.Binary(op, lhs, rhs)
        return lhs
```

**优先级表** (`operator.py`):

| 优先级 | 运算符 |
|--------|--------|
| 14 | `*` (Deref), `&` (AddrOf) |
| 13 | `-` (Neg), `~`, `!` |
| 11-12 | `*`, `/`, `%` |
| 10-11 | `+`, `-` |
| 9-10 | `<<`, `>>` |
| 8-9 | `<`, `>`, `<=`, `>=` |
| 7-8 | `==`, `!=` |
| 6-7 | `&` |
| 5-6 | `^` |
| 4-5 | `\|` |
| 3-4 | `&&` |
| 2-3 | `\|\|` |
| 1 | `=`, `+=`, `-=`, ... |

### TokenStream

`compiler/frontend/parse/stream.py` — parser 的 token 消费接口。

```python
class TokenStream:
    def peek(self) -> Token           # 查看当前
    def advance(self) -> Token        # 消费并前进
    def consume_punctuator(kind)      # 期望特定标点
    def consume_keyword(kind)         # 期望特定关键字
    def consume_identifier()          # 期望标识符
    def at_end(self) -> bool          # 是否到 EOF
```

## AST

`compiler/frontend/parse/ast.py` — 所有 AST 节点为 `@dataclass`。

顶层声明 (`ProgramItem`)：`FuncDef`、`StructDef`、`EnumDef`、`TraitDef`、`Impl`、`Import`、`AliasDef`。

表达式 (`Expr`)：`Binary`、`Unary`、`Call`、`MethodCall`、`FieldAccess`、`VarDecl`、`If`、`Loop`、`For`、`While`、`Match`、`Return`、`Break`、`Continue`、`Block`、`Literal`、`Identifier` 等。

## AST Export

`compiler/frontend/parse/ast_export.py` — 将 AST 树形打印为文本。`export_program()` 递归遍历全部节点，用于 `build/ast.txt` 输出。
