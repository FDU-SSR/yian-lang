# 02 前端

## 源码与会话

`FrontendDriver.new(config, trace)` 加载可选包图，确定标准库根和源码信任规则，收集命令行输入并将文件内容读入 `FrontendSession`。`FrontendDriver.run()` 从会话中的内容完成以下阶段。LSP 使用 `prepare_documents` 将内存文档装入会话，再运行同一组阶段。

`new` 和 `prepare_documents` 保存调用者提供的 `CompilerTrace` 非拥有引用，调用者须保证它在 driver 使用期间有效。命令行共享按配置构造的实例；LSP 使用禁用的实例。前端转储由 `--dump` 独立控制。

## Lexer

`yianc/src/frontend/lex/lexer.an` 的 `Lexer` 生成带源码范围的 token。token 的种类和载荷定义位于 `frontend/lex/token.an`。词法错误由 `LexError` 返回。

## Parser

`frontend/parse/state.an` 的 `Parser` 管理 token 消费、诊断及 AST 分配，`frontend/parse/items.an::parse_program` 解析顶层声明。表达式、类型和模式的解析分别位于 `frontend/parse/expr.an`、`type.an` 和 `pattern.an`。

## AST 与脱糖

`frontend/ast/` 定义 AST 节点、遍历和存储。会话按整个输入集合完成词法、语法和[脱糖](03.desugar.md)阶段。每个单元保存 token 和脱糖后的 AST，`take_session()` 将该会话交给中端。

`--dump` 通过 `driver/dump.an` 写出 token 和脱糖后的 AST。文件阶段错误的结构及位置所有权见[错误处理](18.error_handling.md)。
