# 02 前端

前端将 `.an` 源文件转换为 AST。分为词法分析（Lexer）和语法分析（Parser）两个阶段。

## Lexer

`compiler/frontend/lex/lexer.py`

### CharStream

```python
class CharStream:
    def __init__(self, path: Path, text: str | None = None)  # Read the source file when text is omitted.
    def peek(self) -> str | None        # Inspect the current character.
    def next(self) -> str               # Consume and advance.
    def advance(self) -> None           # Consume and advance without returning a value.
    def at_end(self) -> bool            # Whether at end of file.
```

逐字符扫描，维护当前行列位置用于 `SrcSpan`。

### Lexer

```python
class Lexer:
    def __init__(self, path: Path, text: str | None = None)
    def lex(self) -> None              # Run lexical analysis.
    def export(self) -> list[Token]    # Export the token list.
```

**主循环** (`lex()`):

```python
while True:
    prev_was_ws = self.__skip_ignored()   # Skip whitespace/comments.
    token = self.__next_token(prev_was_ws) # Identify the next token.
    self.__tokens.append(token)
    if token is EOF: break
```

**`__next_token(prev_was_ws)`** 逐字符识别 token 类型：
- 字母/下划线开头 → 标识符或关键字
- 数字开头 → 整数字面量（支持 `0x` 十六进制、类型后缀）
- `"` 开头 → 字符串字面量
- `'` 开头 → 字符字面量
- `b'` 开头 → 字节字面量
- 标点符号 → 运算符或分隔符

### 空白敏感性

Yian 的关键设计：通过空白上下文区分歧义 token。

```python
if prev_was_ws:
    # '<' -> Less, '>' -> Greater, '>>' -> GreaterGreater (right shift).
else:
    # '<' -> LAngle (generic delimiter), '>' -> RAngle, '>>' -> two RAngles.
```

这一设计消除了 parser 层面的 C++ 式 `>>` 歧义。

### Token 类型

`compiler/frontend/lex/token.py`

```python
Token = Keyword | Identifier | Punctuator | Literal | FStrStart | FStrLiteral | FStrExprBegin | FStrExprEnd | FStrEnd

# Keyword: if, else, fn, struct, ...
# Identifier: user-defined name.
# Punctuator: +, -, {, }, [, ], ...
# Literal: IntLiteral, FloatLiteral, CharLiteral, StrLiteral, BoolLiteral
```

每个 token 携带 `span: SrcSpan` 用于错误定位。

## Parser

`compiler/frontend/parse/parser.py` + `parser_expr.py` + `parser_type.py`

### 架构

```text
Parser (parser.py)          ← 顶层声明: fn, struct, enum, trait, impl, import, const, extern, opaque
  └── ExprParser            ← 表达式 (Pratt parser)
  └── TypeParser            ← 类型表达式
```

### Parser — 顶层声明

```python
class Parser:
    def parse(self) -> AST.Program:
        while not at_end:
            attrs = consume_attrs()
            match peek():
                case Import | From → __parse_import()
                case Typedef      → __parse_alias(attrs)
                case Impl         → __parse_impl()
                case Struct       → __parse_struct(attrs)
                case Enum         → __parse_enum(attrs)
                case Trait        → __parse_trait(attrs)
                case Fn           → __parse_func_def(attrs)
                case Const        → __parse_const_def(attrs)
                case Extern       → __parse_extern_block(attrs)
                case Opaque       → __parse_opaque_type(attrs)
```

### ExprParser — Pratt Parser

```python
class ExprParser:
    def parse_expr(self) -> AST.Expr:
        return self.__parse_expr_bp(min_bp=1)

    def __parse_expr_bp(self, min_bp: int) -> AST.Expr:
        lhs = self.__parse_prefix()           # Prefixes: literals, identifiers, (, if, loop, ...
        while True:
            op = BinaryOperator.try_from_token(peek())
            if op is None or op.lbp < min_bp: break
            advance()
            rhs = self.__parse_expr_bp(op.rbp) # Right binding power.
            lhs = AST.Binary(op, lhs, rhs)
        return lhs
```

**优先级表** (`operator.py`):

| 优先级 | 运算符 |
|--------|--------|
| 14 | `*` (Deref), `&` (AddrOf) |
| 13 | `-` (Neg), `~`, `!` |
| 11-12 | `*`, `/`, `%` |
| 10-11 | `+`, `-` |
| 9-10 | `<<`, `>>` |
| 8-9 | `<`, `>`, `<=`, `>=` |
| 7-8 | `==`, `!=` |
| 6-7 | `&` |
| 5-6 | `^` |
| 4-5 | `\|` |
| 3-4 | `&&` |
| 2-3 | `\|\|` |
| 1 | `=`, `+=`, `-=`, ... |

换行不是表达式或语句终止符。由于 `&` 和 `*` 同时是前缀与二元运算符，紧跟在块表达式
（例如 `if`）后的独立行如果以它们开头，Pratt parser 会把它们作为前一表达式的续接运算符。
用分号结束前一个块表达式，或让新语句以 `return` 等关键字开始：

```yian
if condition { do_work(); };
&value.field

if condition { do_work(); }
return &value.field;
```

### TokenStream

`compiler/frontend/parse/stream.py` — parser 的 token 消费接口。

```python
class TokenStream:
    def peek(self) -> Token           # Inspect the current token.
    def advance(self) -> None         # Consume and advance.
    def consume_punctuator(kind)      # Expect specific punctuation.
    def consume_keyword(kind)         # Expect a specific keyword.
    def consume_identifier()          # Expect an identifier.
    def at_end(self) -> bool          # Whether at EOF.
```

## AST

`compiler/frontend/parse/ast.py` — 所有 AST 节点为 `@dataclass`。

顶层声明 (`ProgramItem`)：`FuncDef`、`StructDef`、`EnumDef`、`TraitDef`、`Impl`、`Import`、`Alias`、`ConstDef`、`ExternBlock`、`OpaqueTypeDef`。

表达式 (`Expr`)：`Binary`、`Unary`、`Call`、`Builtin`、`MethodCall`、`FieldAccess`、`VarDecl`、`If`、`ComptimeIf`、`Loop`、`For`、`While`、`Match`、`Return`、`Break`、`Continue`、`Block`、`Literal`、`Identifier` 等。
所有 `@name` 指令统一使用 `AST.Builtin`，保存 `kind`、类型实参 `type_args` 与值实参 `args`；
`@sizeof`、`@undef`、`@alloc` 等同样使用这个节点。

`PatternLet`、`PatternParam`、`LetCondition` 和结构化 `Pattern` 节点表示解构与条件模式；
`MatchArm` 保存可选守卫。`TryExpr` 表示后缀 `?`，`TraitCall` 保存显式 trait 限定调用。
`BuiltinKind` 定义在 `compiler/builtins.py`，前端和 lowering 共用该枚举。

## AST Export

`compiler/frontend/parse/ast_export.py` — 将 AST 树形打印为文本。`export_program()` 递归遍历全部节点，用于 `build/ast.txt` 输出。
