# 12 LLVM 代码生成

`compiler/codegen/llvm/` — 将 CFG IR 翻译为 LLVM IR，再输出目标文件。

## 模块结构

```text
base/             模块、类型、值与 intrinsic 声明
function/core.py  单函数上下文、指令流、控制流与基础 LLVM 操作
pointer/          指针表示、安全检查、指针运算与分配
emitters/         聚合、调用、内存、系统操作和值发射
pipeline/         LLTranslator、LLBuilder 组合根与 Emitter
```

`LLBuilder` 组合单函数的 `FunctionCore`、`FatSafety`、指针表示和各类 emitter。指针安全机制位于
`pointer/safety.py`，与普通 LLVM 指令发射分离；各 emitter 通过 core 与表示层访问 LLVM builder。

## LLTranslator

以下签名和分派片段说明阶段接口与 emitter 归属；省略号表示未展开的分支。

```python
class LLTranslator:
    def run(self, functions: dict[int, CFG_IR.Function]):
        for function in functions.values():
            self.__module.declare(function)   # 先声明全部函数 → LLFunction
        for function in functions.values():
            self.__build(function)            # 再逐个翻译

    def __build(self, func):
        for block in func.blocks:
            for stmt in block.stmts:
                self.__translate(builder, stmt)
```

### __translate — CFG IR → LLVM IR

```text
def __translate(self, builder, stmt):
    match stmt:
        case IR.VarPtr():                builder.memory.var_ptr(...)
        case IR.FieldPtr():              builder.memory.gep(...)
        case IR.Load():                  builder.memory.load(...)
        case IR.Store():                 builder.memory.store(...)
        case IR.Malloc():                builder.allocation.malloc(...)
        case IR.Realloc():               builder.allocation.realloc(...)
        case IR.Delete():                builder.allocation.delete(...)
        case IR.Call():                  builder.calls.call_func(...)
        case IR.Invoke():                builder.calls.call_value(...)
        case IR.TraitObjectConstruct():  builder.calls.trait_object_construct(...)
        case IR.TraitObjectInvoke():     builder.calls.trait_object_call(...)
        case IR.Binary():                builder.values.binary(...)
        case IR.Unary():                 builder.values.unary(...)
        case IR.MemCopy():               builder.memory.mem_copy(...)
        case IR.MemSetPattern():         builder.memory.mem_set_pattern(...)
        case IR.Sqrt():                  builder.system.sqrt(...)
        case IR.Sin():                   builder.system.sin(...)
        case IR.Cos():                   builder.system.cos(...)
        ...
```

以下是 emitter 路由示意，不是可执行代码；终结符经 `builder.flow` 发射，具体访问检查经 `builder.safety` 发射。
`LLTranslator` 不在 `LLBuilder` 上直接合并这些接口。

`@dangling<T>()`（`builder.dangling_value`）给出的地址取 `align_of::<T>()`（恒非零）：raw 模式为裸地址；
fat 模式补全为 `⟨data=align, word=字面量锁槽, index=0, size=0⟩`；指向 ZST 的指针本身是 ZST，
寄存器里放该 ZST 的空值。

## LLTypeCtx

Yian 类型 → LLVM IR 类型映射。

```python
class LLTypeCtx:
    def get_ll_type(self, type_id: int) -> LLType
```

映射规则：
- `void` / `never` → 值位置使用 `{}`；函数签名返回位置使用 `void`
- `bool` → SSA 值为 `i1`，内存存储表示为 `i8`（读写时转换）
- `char` → `i32`
- `str` → fat 模式 `{ptr, i64, i64}`（`data`, `word`, 字节长度，24B）；raw 模式 `{ptr, i64}`（16B）
- `IntType(size)` → `i{8*size}`
- `FloatType(4)` → `float`, `FloatType(8)` → `double`
- `PointerType` → fat 模式 `{ptr, i64, i32, i32}`（`data`, `word`, `index`, `size`，24B；`word` 打包锁槽位置与键，`index`/`size` 是 32 位元素数）；raw 模式为裸 8B 指针
- `RefType` → fat 模式 `{ptr, i64}`（`data`, `word`，16B）；raw 模式为裸 8B 指针
- `TraitObjectType` → fat 模式 `{ptr, i64, ptr}`（数据地址、存活性 word、vtable，24B）；raw 模式 `{ptr, ptr}`（16B）
- `SliceType` → fat 模式 `{ptr, i64, i64}`（`data`, `word`, 元素数，24B）；raw 模式 `{ptr, i64}`（16B）
- `ArrayType` → `[elem x N]`
- `StructType` → identified struct
- `EnumType` → 对满足 niche 条件的二变体枚举使用 payload 本身的布局；其他枚举使用 `{i32, [ceil(pad/4) x i32]}`，其中 `pad = align_up(max_size, max_align)` 是最大变体 payload 的对齐后大小；枚举尺寸/对齐为 `align_up(4 + payload_size, 4)` / 4
- `FunctionPointerType` → 带函数签名的函数指针；其 ABI 为裸 8B 地址

所有 ZST 在普通值位置使用空结构体 `{}` 表示；在函数返回位置，ZST 签名擦除为 `void`。`bool`
在 LLVM SSA 与函数 ABI 中使用 `i1`，`MemoryEmitter` 以 `i8` 读写布尔值，并在 load/store 边界转换。

这里的 fat/raw 分支由编译器的 `--raw-pointers` 选项选择；默认模式是 fat。fat
聚合的 `data` 字段都是不透明地址（LLVM opaque pointer，不携带 pointee 类型），`word` 是打包了
32 位锁表下标与 32 位对象身份的 64 位字，检查时读锁表项并与身份作 32 位比较。

Niche 枚举必须有一个 unit 变体，另一个变体必须只有一个匿名 payload 字段，且该字段是编译器能够证明不会取全零值的非 ZST 指针、引用、函数指针、非 ZST 元素切片或 `str`。unit 变体编码为 payload 类型的全零值，带 payload 的变体直接使用字段值；匹配时根据是否全零选择分支。该判定不依赖枚举名称。

### Trait object 调用

`TraitObjectType` 是独立的动态类型。具体引用转换由 `TraitObjectConstruct` 产生 trait object 值，LLVM 模块
为每个具体类型与 trait 实例建立只读 vtable，并用 thunk 适配 trait 方法 ABI。`TraitObjectInvoke` 读取
vtable 槽并执行间接调用；fat 模式在调用前检查对象引用的存活状态。具体语法、可转换来源和对象安全
条件见 trait object 语言说明。

## ZST (Zero-Sized Type) 抹除

`is_zst(type_id)` 定义在 `compiler/analysis/ty/type_ops.py`：递归判定 void/never/长度 0
数组/ZST 元素数组/ZST 字段 struct 与 tuple/单变体无载荷或 ZST 载荷 enum/pointee 为 ZST
的指针与引用，以及函数项（`FunctionType`）。

### LLTypeCtx 入口

- `__get_raw_type`：`is_zst(type_id)` 先拦截 → `ir.LiteralStructType([])`（空结构体 `{}`），
  直接返回，不进入 per-type lowering。ptr-to-ZST 不产生 LLVM pointer。
- `__stable_layout`：同上，ZST → `(0, 1)`。
- `__build_function_type`：ZST 返回 → `void`；ZST 参数（含 ptr-to-ZST receiver）剔除。

### LLBuilder 守卫

| 操作 | ZST 行为 |
|---|---|
| `alloca` | 分配 `{}` (0 字节，合法) |
| `load` | 返回 undef，不 emit `load` |
| `store` | 直接 return，不 emit `store` |
| `gep` | 初始或最终 pointee 为 ZST → 返回 undef，不 emit `gep` |
| `element_ptr` | pointee 为 ZST → 返回 undef |
| `malloc` | 返回 ptr-to-ZST undef，不 emit `malloc` |
| `delete` | 直接 return，不 emit `free` |
| `cast` (Pointer→Pointer) | dst pointee 为 ZST → 返回 undef，不 emit `bitcast` |
| `__cmp_impl` | ZST 比较 → 编译期常量 `true`/`false` |
| `construct_enum_variant` | ZST payload → 跳过 payload store |
| `unpack_enum_payload` | ZST payload → 直接 return |

### Lowering 守卫

- `op_builder`：Eq/Neq/Lt/Gt/Leq/Geq 对 ZST → 编译期 `HIR.BoolLiteral`

### 库适配

| 库 | 适配 |
|---|---|
| `slice.an` SliceIter / RevSliceIter | 加 `n: u64` 计数字段，`next()` 用 `n==0` 终止 |
| `array.an` IntoIterator | 传 `n=N` |
| `ops.an` | ZST 比较在 op_builder 内置（不依赖 PartialEq trait） |
| `hash.an` | `Hash<Murmur3Hasher>` impl for void (no-op) |
| `drop.an` | `void::new()` 静态构造子 |

## Emitter

```python
class Emitter:
    def emit_module(self, llvm_module, output_dir, kind, stem,
                    intermediate_dir=None, opt_level=0) -> str
    def emit_ll(self, llvm_module, path)         # LLVM IR 文本
```

- `target="ll"` → `.ll` 文件
- `target="obj"` → `.o` 文件（`-t obj` 还会用 `clang -r -nostdlib` 并入运行时对象）
- `target="exe"` → 先 `.o`，再 clang 链接为可执行文件（并链接 `build/runtime/libyian_rt.a`）

## 运行时边界

热路径检查不进运行时库：访问路径的锁字 load + 比较、`active_size` 守卫加载、帧锁进入与退出、键计数器递增、胖指针构造与字段提取都由编译器内联发射，必须能被 LLVM 内联与提升。运行时库（`runtime/` 的 C 源码）承担其余部分：

| 项 | 说明 |
| --- | --- |
| 进程级对象 | `argc`/`argv` 全局、字面量锁与环境锁、堆/栈键计数器、帧锁影子栈与深度 |
| 失败路径 | `__yian_runtime_fail` 与 `__yian_panic`：只写 stderr 后 `_exit(1)`，不分配内存、不返回 |
| C 入口包装 `main` | 校验参数 ABI 后写入参数全局，调用编译器生成的 `__yian_main` |
| 堆 | `__secl_pool_alloc`、`__secl_pool_alloc_class`、`__secl_pool_release` |

这些符号在 LLVM 模块里都是外部声明（见 `base/module.py`）；`-t exe` 与 `-t obj` 由 clang 把运行时库链接进来，`-t ll`/`bc`/`asm` 保持未定义，需要自行链接（见 `docs/compile_script.md` 的运行时库章节）。
