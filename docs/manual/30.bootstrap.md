# 30 自举编译器与原生工具链

`bootstrap/yianc/` 是以 YIAN 编写的完整原生编译器，实现源码准备、语义分析、HIR 到 CFG 下降、
LLVM 代码生成和原生链接。它与 Python 参考编译器支持相同的 `.an` 到可执行文件流程。
安装后的 `yianc` 由该包构建；`bootstrap/anx/` 提供同样以 YIAN 编写的原生包管理器。

`--frontend-json` 仍是一个只观察 tokens、AST 或 desugared AST 的轻量 CLI 模式；它不代表编译器其余阶段的能力。
用户可见的编译器参数见[编译器命令行手册](../compile_script.md)，原生分析服务见[语言服务器](27.language_server.md)。

## 包与依赖

| 包 | kind | 职责 |
|----|------|------|
| `bootstrap/yianc` | `hybrid` | 原生编译器与前端库；依赖 `json`、`llvm` |
| `bootstrap/json` | `lib` | JSON 值、解析与写入，不依赖编译器 |
| `bootstrap/jsonrpc` | `lib` | JSON-RPC 消息支持；依赖 `json` |
| `bootstrap/lsp_protocol` | `lib` | LSP 协议模型；依赖 `json`、`jsonrpc` |
| `bootstrap/ffi` | `lib`，`ffi = true` | 字节与 C ABI 支持 |
| `bootstrap/llvm` | `lib`，`ffi = true` | LLVM 22 C API 绑定，依赖 `ffi` |
| `bootstrap/toml` | `lib` | TOML 解析，供原生包管理器使用 |
| `bootstrap/anx` | `hybrid` | 原生包管理器；依赖 `yianc`、`json`、`toml` |

LLVM 包通过 `[native.llvm]` 声明 LLVM 22 组件和 `native/target.c` shim。编译器包本身还声明
`core` 组件及 `native/host.c` shim；包图会把各自的原生依赖传给链接器。

## 完整编译管线

原生编译器把所有编译阶段连在一个驱动入口中：

```text
.an → tokens → AST → desugared AST → HIR → CFG → LLVM IR → native output
```

`bootstrap/yianc/src/` 按职责分为 `frontend/`、`analysis/`、`codegen/`、`driver/`、
`package/`、`diagnostics/` 和 `format/`。`analysis/` 包含类型、符号、HIR、常量求值、AST 到 HIR
检查与分析 passes；`codegen/` 负责 CFG、LLVM lowering 和指针安全检查；`driver/` 处理 CLI、
输出、运行时及 LLVM 原生链接。

两个有意区分的入口是：`--analyze` 运行到语义分析与 HIR 检查，不进入 CFG/LLVM；`-t none`
继续做 CFG 下降，但不发射 LLVM。其他编译目标可以生成 LLVM IR、bitcode、目标文件、汇编或可执行文件。

## 构建与前端观察

完成原生工具链安装后，可用安装的 `anx` 和 native `yianc` 构建 checkout 中的编译器包：

```bash
PATH="$HOME/.local/bin:$PATH" YIAN_ROOT="$PWD" YIAN_LIB="$PWD/lib/src" anx build bootstrap/yianc -O2
bootstrap/yianc/build/app --frontend-json tokens tests/basic/array/access.an
bootstrap/yianc/build/app --frontend-json ast tests/basic/array/access.an
bootstrap/yianc/build/app --frontend-json desugared tests/basic/array/access.an
bootstrap/yianc/build/app --analyze --json --compiler-root . lib/src tests/basic/array/access.an
bootstrap/yianc/build/app --compiler-root . -O2 -o build/access lib/src tests/basic/array/access.an
```

`--frontend-json` 接受 `tokens`、`ast`、`desugared` 三种阶段和一个以上输入路径。
目录递归收集 `.an` 文件，输入根保持命令行顺序，每个目录内的文件按路径排序。
目录遍历不递归进入符号链接目录；指向文件的符号链接可作为源文件。

stdout 是单个 JSON 对象，包含 `version: 1`、阶段、文件观察结果与 `diagnostic`。
成功时 `diagnostic` 为 `null`；IO、词法或语法失败时包含诊断并退出 1。无效命令行在 stderr
打印用法并退出 2。该命令不做跨文件名称解析，因此观察前端时无需把标准库列作输入。

Python 参考编译器也提供同名的观察入口：

```bash
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json tokens tests/basic/array/access.an
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json ast tests/basic/array/access.an
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json desugared tests/basic/array/access.an
```

两种实现各自输出自身的前端结构；文本格式与诊断呈现不要求严格一致。完整 CLI 的编译目标和语义选项
见[编译器命令行手册](../compile_script.md)。

## 安装原生工具链

冷启动脚本 `scripts/bootstrap_toolchain.sh` 按固定的七包闭包和 Python 参考编译器生成临时 seed `anx`。seed `anx` 配合 Python 参考编译器构建 `yianc`，再配合刚构建的 native `yianc` 构建最终 `anx`。它不调用 PATH 上已有的 native 工具，也不构建 LSP。构建及帮助检查成功后，脚本以可回滚的发布步骤安装命令、标准库和运行时资源，并写入源码与产物摘要：

```bash
conda run --no-capture-output -n yian-env bash scripts/bootstrap_toolchain.sh \
  --prefix "$HOME/.local" --python python
"$HOME/.local/bin/yianc" --help
"$HOME/.local/bin/anx" --help
```

语言服务器位于仓库根目录 `lsp/`，单独由原生 `anx` 与 `yianc` 构建和安装，细节见
[语言服务器手册](27.language_server.md)。安装后的 `yianc` 和 `anx` 是原生程序，运行时不需要 Python。

已有可运行的原生 `anx` 和 `yianc` 时，可使用纯原生 warm 流程刷新完整工具链。它依次用旧工具构建新编译器、由新编译器构建包管理器、最后构建 raw/O2 LSP；只有 staging 资源上的初始化握手成功才发布：

```bash
scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"
```

warm 流程不启动 Python，也不隐式退回 cold 流程。seed 与当前源码不兼容时会失败；需要新 seed 时，显式执行上面的 cold 入口。

## 前端数据与资源

`frontend/source.an` 的 `SourceManager` 拥有路径和源码字符串，`SourceFile` 提供借用视图。
`Position` 使用从 0 开始的行列；`Span.write_json(Writer&)` 在打开的 JSON 对象中写入
`start` 与 `end` 坐标数组。

`frontend/lex/` 实现 token 与词法器，`frontend/parse/` 实现递归下降语法分析。
`frontend/ast/` 保存 AST arena、遍历、重写和观察格式；`frontend/desugar.an` 执行语法糖展开。
源码、token、AST 与 JSON writer 的清理由各自显式的释放接口完成；浅复制不产生独立资源所有权。

## JSON 库

`json.value.Value` 支持 null、布尔、数字、字符串、数组和对象；数字分别保存 `i64`、`u64` 与 `f64`。
`Object` 保持成员插入顺序，查找线性扫描成员表。替换成员时 `insert()` 返回原值，原值的清理由调用者负责。
`Value.clone()` 与 `Object.clone()` 递归复制所拥有的 JSON 存储；显式 `drop()` 递归释放这些存储。

`json.parse` 解析文本并报告结构化错误。`json.write.Writer` 提供标量写入、对象 key、数组与对象
开始/结束接口，记录首次错误；`finish()` 返回 `Result<String, WriteError>` 并取出输出存储。
writer 默认最大嵌套深度为 128，可用 `with_max_depth()` 指定；前端观察使用 512。

## 现有测试

```bash
conda run --no-capture-output -n yian-env python scripts/run_tests.py --suite bootstrap --implementation both
conda run --no-capture-output -n yian-env python scripts/run_tests.py --all -q
```

第一条命令使用同一个安装的原生 `anx` 驱动 Python 与原生编译器，在 raw/fat 两种指针模式下运行 `bootstrap/yianc`、
`bootstrap/json`、`bootstrap/toml`、`bootstrap/jsonrpc` 和 `bootstrap/lsp_protocol` 的包级测试。编译器包的单元测试覆盖源码位置、词法、语法、AST、
去糖和常量；集成测试覆盖源码收集、分析会话、编辑器查询与资源生命周期。JSON/TOML 包测试覆盖各自的
解析与写入接口。第二条命令运行 basic、safety、package 和 bootstrap 四个套件，验证 Python 与原生
编译器的端到端行为；package/bootstrap 均由共享的原生 `anx` 驱动，运行器会先刷新安装前缀中的原生工具。
