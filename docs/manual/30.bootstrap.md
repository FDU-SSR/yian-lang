# 30 自举编译器与原生工具链

`yianc/` 是以 YIAN 编写的原生编译器，实现源码准备、语义分析、HIR 到 CFG 下降、
LLVM 代码生成和原生链接，是日常工作的权威编译器。Python 恢复编译器仅为冷启动保留必要兼容性，
不要求与 native 功能对等。
安装后的 `yianc` 由该包构建；`anx/` 提供同样以 YIAN 编写的原生包管理器；`fmt/` 提供复用 `yianc` 前端的独立格式化器 `yian-fmt`。

native `yianc` 提供 `--check`（前端+中端检查）与默认原生产物两种编译模式；`--dump` 可写出前端、HIR、CFG 与 IR 观察文件。Python recovery CLI 保留 `--frontend-json`、`--analyze` 与 `--json`。
用户可见的编译器参数见[编译器命令行手册](../compile_script.md)，原生分析服务见[语言服务器](27.language_server.md)。

## 包与依赖

原生编译器、包管理器和格式化器分别位于仓库根目录 `yianc/`、`anx/`、`fmt/`；共享支持库位于 `bootstrap/`。

| 包 | kind | 职责 |
|----|------|------|
| `yianc` | `hybrid` | 原生编译器与前端库；依赖 `json`、`llvm` |
| `fmt` | `hybrid` | 独立格式化实现与 `yian-fmt` 命令；依赖 `yianc` |
| `bootstrap/json` | `lib` | JSON 值、解析与写入，不依赖编译器 |
| `bootstrap/jsonrpc` | `lib` | JSON-RPC 消息支持；依赖 `json` |
| `bootstrap/lsp_protocol` | `lib` | LSP 协议模型；依赖 `json`、`jsonrpc` |
| `bootstrap/ffi` | `lib`，`ffi = true` | 字节与 C ABI 支持 |
| `bootstrap/llvm` | `lib`，`ffi = true` | LLVM 22 C API 绑定，依赖 `ffi` |
| `bootstrap/toml` | `lib` | TOML 解析，供原生包管理器使用 |
| `anx` | `hybrid` | 原生包管理器；依赖 `yianc`、`json`、`toml` |

LLVM 包通过 `[native.llvm]` 声明 LLVM 22 组件和 `native/target.c` shim。编译器包本身还声明
`core` 组件及 `native/host.c` shim；包图会把各自的原生依赖传给链接器。

新 clone 的开发环境需要 Python 3.12+、`python/requirements.txt` 中的 Python 依赖、LLVM 22 命令行工具和原生 C 构建工具。LLVM 工具链安装脚本本身不依赖 Python；默认运行时会使用 sudo 从系统仓库安装缺少的 C 构建工具，并通过官方 `apt.llvm.org` 仓库安装缺少的 LLVM 22 软件包。传入 `--check` 时只报告状态，不执行安装。脚本不会重复安装 requirements 中的 Python 包：

```bash
conda create -n yian-env python=3.12 -y
conda activate yian-env
python -m pip install -r python/requirements.txt
bash scripts/setup_llvm_toolchain.sh
export YIAN_CC=/usr/lib/llvm-22/bin/clang
```

## 完整编译管线

原生编译器把所有编译阶段连在一个驱动入口中：

```text
.an → tokens → AST → desugared AST → HIR → HIR address-storage normalization → CFG → LLVM IR → native output
```

`yianc/src/` 按职责分为 `frontend/`、`analysis/`、`codegen/`、`driver/`、
`package/`、`diagnostics/` 和 `format/`。`analysis/` 包含类型、符号、HIR、常量求值、AST 到 HIR
检查与分析 passes；`codegen/` 负责 CFG、LLVM lowering 和指针安全检查；`driver/` 处理 CLI、
输出、运行时及 LLVM 原生链接。

native 编译只有两种选择：`--check` 运行到语义分析与 HIR 检查，不进入 CFG/LLVM 或产物发布；
默认编译生成原生产物，`-t` 可选择 `exe`、`ll` 或 `bc`。Python recovery CLI 仍保留
`--analyze` 与 `-t none` 等恢复入口。

每个具体过程完成类型检查和结果上下文转换后，原生分析会在 HIR 中把数据右值地址、实例方法
receiver、比较/索引的借用实参、数组读取基底和闭包环境地址规范化为已有存储或局部 place block，
然后运行 HIR verifier、覆盖性与确定赋值检查。HIR verifier 在同一次运行内复用已成功完成的相同
具体类型根验证、相同具体 callable 签名和相同 trait 的动态方法表；失败查询不缓存。局部初始化
留在原控制流位置；LLVM 为过程 locals
在入口分配栈槽，循环执行时重写槽位。CFG 地址 lowering 只处理这些已有 place，不再为任意右值
创建临时局部或 Store；函数地址和通过 slice 指针得到的元素地址保留各自路径。

带显式 tag word 与 payload 区的 tagged enum 使用枚举专用 place 操作：直接初始化在目标存储上写
tag 与字段，按值匹配复制一份独立快照，引用匹配从原 place 读取当前 tag 与字段。ZST 与 niche
表示沿用值操作。相关 CFG 操作、下降与不变量见[原生 LLVM 代码生成](12.llvm_codegen.md#native-yianc-的-enum-place-下降与-linkage)。

原生 `yianc` 为模块内普通生成函数使用 `internal` 链接性，入口 `__yian_main`、`extern "C"` 声明与
运行时符号保留外部名称；该分类对所有 LLVM 输出目标一致。

## 构建与前端观察

完成原生工具链安装后，可用安装的 `anx` 和 native `yianc` 构建 checkout 中的编译器包：

```bash
PATH="$HOME/.local/bin:$PATH" YIAN_ROOT="$PWD" YIAN_LIB="$PWD/lib/src" anx build yianc -O2
yianc/build/app --check --compiler-root . lib/src tests/basic/array/access.an
yianc/build/app --dump --compiler-root . lib/src tests/basic/array/access.an
yianc/build/app --compiler-root . -O2 -o build/access lib/src tests/basic/array/access.an
"$HOME/.local/bin/yian-fmt" --check yianc/src/main.an
```

`--check` 只做前端与中端检查，不要求 `main`，不生成编译器产物。`--dump` 在编译模式写
`tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`；在 `--check` 模式只写 tokens、AST
和成功分析时的 HIR。目录递归收集 `.an` 文件，输入根保持命令行顺序，每个目录内的文件按路径排序。
目录遍历不递归进入符号链接目录；指向文件的符号链接可作为源文件。无效命令行在 stderr 打印用法
并退出 2。

Python 恢复编译器保留自己的前端观察与分析入口；这些命令只属于恢复路径：

```bash
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json tokens tests/basic/array/access.an
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json ast tests/basic/array/access.an
conda run --no-capture-output -n yian-env env PYTHONPATH=python python -m yianc.main --frontend-json desugared tests/basic/array/access.an
```

恢复入口输出自身的前端结构；不要求它与 native 的文本格式或诊断呈现一致。完整 CLI 的编译目标和语义选项
见[编译器命令行手册](../compile_script.md)。

## 安装原生工具链

冷启动脚本 `scripts/bootstrap_toolchain.sh` 使用 Python 恢复编译器和固定五包闭包构建 raw `yianc`，再由 staged native `yianc` 分别按固定七包闭包构建 raw `anx`、按固定六包闭包构建 raw `yian-fmt`。它不调用 PATH 上已有的 native 工具，也不构建 LSP。三个阶段构建、帮助检查与 formatter stdin 冒烟成功后，脚本以可回滚的发布步骤安装三个命令、标准库和运行时资源，并写入构建来源、模式、源码与产物摘要：

# 以下冷启动与热刷新会编译原生工具链；执行前需要明确授权并使用隔离或指定的安装前缀。
```bash
conda run --no-capture-output -n yian-env bash scripts/bootstrap_toolchain.sh \
  --prefix "$HOME/.local" --python python
"$HOME/.local/bin/yianc" --help
"$HOME/.local/bin/anx" --help
"$HOME/.local/bin/yian-fmt" --version
```

语言服务器位于仓库根目录 `lsp/`，单独由原生 `anx` 与 `yianc` 构建和安装，细节见
[语言服务器手册](27.language_server.md)。安装后的 `yianc`、`anx` 和 `yian-fmt` 是原生程序，运行时不需要 Python。

已有可运行的原生 `anx` 和 `yianc` 时，可使用纯原生 warm 流程刷新完整工具链。它依次用旧工具构建 raw/O2 编译器、由新编译器构建 raw/O2 包管理器和格式化器、最后构建 raw/O2 LSP；只有 staging formatter 冒烟与资源上的初始化握手成功才发布：

```bash
scripts/refresh_toolchain.sh --anx "$HOME/.local/bin/anx" --yianc "$HOME/.local/bin/yianc" --prefix "$HOME/.local"
```

warm 流程不启动 Python，也不隐式退回 cold 流程。seed 与当前源码不兼容时会失败；需要新 seed 时，显式执行上面的 cold 入口。

## 前端数据与资源

`frontend/source.an` 的 `SourceManager` 拥有路径和源码字符串，`SourceFile` 提供借用视图。
`Position` 使用从 0 开始的行列；`Span.write_json(Writer&)` 在打开的 JSON 对象中写入
`start` 与 `end` 坐标数组。

`frontend/lex/` 实现 token 与词法器，`frontend/parse/` 实现递归下降语法分析。
`frontend/ast/` 保存 AST arena、遍历、重写和观察格式；`frontend/desugar.an` 执行语法糖展开。

`matches` 是保留关键字：表达式 parser 在 `==` 同级读取左侧表达式，再用 `parse_binding_pattern`
读取右侧模式，生成 `ExprData.Matches`。`frontend/desugar/control.an` 把它展开为带
`MatchArmOrigin.Condition` 成功分支和 `MatchArmOrigin.Synthetic` 兜底分支的普通 `Match`；
HIR、CFG 与 LLVM 不包含独立的 `Matches` 指令。
源码、token、AST 与 JSON writer 的清理由各自显式的释放接口完成；浅复制不产生独立资源所有权。

## JSON 库

`json.value.Value` 支持 null、布尔、数字、字符串、数组和对象；数字分别保存 `i64`、`u64` 与 `f64`。
`Object` 保持成员插入顺序，查找线性扫描成员表。替换成员时 `insert()` 返回原值，原值的清理由调用者负责。
`Value.clone()` 与 `Object.clone()` 递归复制所拥有的 JSON 存储；显式 `drop()` 递归释放这些存储。

`json.parse` 解析文本并报告结构化错误。`json.write.Writer` 提供标量写入、对象 key、数组与对象
开始/结束接口，记录首次错误；`finish()` 返回 `Result<String, WriteError>` 并取出输出存储。
writer 默认最大嵌套深度为 128，可用 `with_max_depth()` 指定；前端观察使用 512。

## 现有测试

# 以下命令分别选择全部 bootstrap 包测试和四个完整仓库 suite；执行前需核对嵌套 package tests 并取得明确范围授权。
```bash
conda run --no-capture-output -n yian-env python scripts/run_tests.py --suite bootstrap --implementation native
conda run --no-capture-output -n yian-env python scripts/run_tests.py --all -q
```

第一条命令使用安装的原生 `anx` 和 native `yianc`，在 raw/fat 两种指针模式下运行 `yianc`、
`bootstrap/json`、`bootstrap/toml`、`bootstrap/jsonrpc` 和 `bootstrap/lsp_protocol` 的包级测试。编译器包的单元测试覆盖源码位置、词法、语法、AST、
去糖和常量；集成测试覆盖源码收集、分析会话、编辑器查询与资源生命周期。JSON/TOML 包测试覆盖各自的
解析与写入接口。第二条命令运行 basic、safety、package 和 bootstrap 四个套件，验证 native
编译器的端到端行为；package/bootstrap 均由共享的原生 `anx` 驱动。运行器要求所选原生工具已安装，缺少时不会自动刷新。
