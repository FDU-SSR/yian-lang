# 30 自举编译器

`bootstrap/` 包含以 YIAN 编写的前端和支持库。`bootstrap/compiler` 的可执行程序支持源码收集、
词法分析、语法分析和 AST 去糖；它没有语义分析、HIR/CFG 下降或目标代码生成入口，不能编译自身。
完整的原生编译入口是 Python 实现的 `yianc`。

## 包与依赖

| 包 | kind | 职责 |
|----|------|------|
| `bootstrap/compiler` | `hybrid` | 前端库与 JSON 观察命令；依赖 `json` |
| `bootstrap/json` | `lib` | JSON 值、解析与写入，不依赖编译器 |
| `bootstrap/ffi` | `lib`，`ffi = true` | 字节与 C ABI 支持 |
| `bootstrap/llvm` | `lib`，`ffi = true` | LLVM 22 C API 绑定，依赖 `ffi` |

LLVM 包通过 `[native.llvm]` 声明 `core`、`analysis`、`bitwriter`、`target`、`nativecodegen`、
`passes` 组件及 `native/target.c` shim。Python 编译器负责构建这些 YIAN 包，并在需要时链接原生依赖。
LLVM 绑定包的存在不表示前端已经提供 LLVM 代码生成。

## 构建与前端观察

从仓库根目录执行：

```bash
anx build bootstrap/compiler
bootstrap/compiler/build/app --frontend-json tokens tests/basic/array/access.an
bootstrap/compiler/build/app --frontend-json ast tests/basic/array/access.an
bootstrap/compiler/build/app --frontend-json desugared tests/basic/array/access.an
```

`--frontend-json` 接受 `tokens`、`ast`、`desugared` 三种阶段和一个以上输入路径。
目录递归收集 `.an` 文件，输入根保持命令行顺序，每个目录内的文件按路径排序。
目录遍历不递归进入符号链接目录；指向文件的符号链接可作为源文件。

stdout 是单个 JSON 对象，包含 `version: 1`、阶段、文件观察结果与 `diagnostic`。
成功时 `diagnostic` 为 `null`；IO、词法或语法失败时包含诊断并退出 1。无效命令行在 stderr
打印用法并退出 2。该命令不做跨文件名称解析，因此观察前端时无需把标准库列作输入。

Python 前端提供同名的观察入口：

```bash
yianc --frontend-json tokens tests/basic/array/access.an
yianc --frontend-json ast tests/basic/array/access.an
yianc --frontend-json desugared tests/basic/array/access.an
```

两种实现各自输出自身的前端结构；文本格式与诊断呈现不要求严格一致。

## 前端数据与资源

`frontend/source.an` 的 `SourceManager` 拥有路径和源码字符串，`SourceFile` 提供借用视图。
`Position` 使用从 0 开始的行列；`Span.write_json(Writer&)` 在打开的 JSON 对象中写入
`start` 与 `end` 坐标数组。

`frontend/lex/` 实现 token 与词法器，`frontend/parse/` 实现递归下降语法分析。
`frontend/ast/` 保存 AST arena、遍历、重写和观察格式；`frontend/desugar.an` 执行语法糖展开。
源码、token、AST 与 JSON writer 的清理由各自显式的释放接口完成；浅复制不产生独立资源所有权。

## JSON 库

`json.value.Value` 支持 null、布尔、数字、字符串、数组和对象；数字分别保存 `i64`、`u64` 与 `f64`。
`Object` 保持成员插入顺序，查找线性扫描成员表。替换成员时 `insert()` 返回原值，原值的清理由调用者负责。
`Value.clone()` 与 `Object.clone()` 递归复制所拥有的 JSON 存储；显式 `drop()` 递归释放这些存储。

`json.parse` 解析文本并报告结构化错误。`json.write.Writer` 提供标量写入、对象 key、数组与对象
开始/结束接口，记录首次错误；`finish()` 返回 `Result<String, WriteError>` 并取出输出存储。
writer 默认最大嵌套深度为 128，可用 `with_max_depth()` 指定；前端观察使用 512。

## 现有测试

```bash
anx test bootstrap/compiler
anx test bootstrap/compiler --raw-pointers
anx test bootstrap/json
anx test bootstrap/json --raw-pointers
```

编译器包的 `tests/unit/` 覆盖源码坐标、token、语法、AST 遍历和去糖，`tests/integration/`
覆盖源码管理、前端处理与资源生命周期。JSON 包的测试覆盖值、解析、Unicode、数字和写入。
这些测试由 `anx test` 运行，与仓库 `tests/package/` 的 anx fixture 套件是不同入口。
