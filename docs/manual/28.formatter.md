# 28 格式化器

权威实现：`fmt/src/`，安装命令 `yian-fmt`。

格式化器把一份 `.an` 源码重新排版成规范形式：它读入文本，用 native `yianc` 的词法器取 token，再按固定
规则重排空白、换行与注释位置。**内容不改**——除空白与注释位置外，token 序列逐字不变，因此格式化后的
文件是同一个程序。

```bash
yian-fmt main.an
yian-fmt --check main.an
anx fmt --check path/to/package
```

## 入口

| 入口 | 用法 |
| --- | --- |
| `yian-fmt FILE` | 选择恰好一个 `.an` 文件，把格式化结果写到 stdout；不写回 |
| `yian-fmt -w/--write PATH...` | 逐个处理文件或目录中的 `.an`，原地写回有变化的文件 |
| `yian-fmt --check PATH...` | 不写文件；每个有差异的路径一行，随后打印 `N of M file(s) need formatting`，有差异时退出码 1 |
| `yian-fmt --stdin --stdin-filepath PATH` | 从 stdin 读到 EOF，格式化内存文本；`PATH` 只是来源标签，不读取也不写入该路径 |
| `anx fmt` | 按原生项目索引只选择根包自己的源码，通过一个 `yian-fmt -w` / `--check` 子进程完成格式化 |
| `yian-lsp` | 声明 `documentFormattingProvider`，把当前打开文档的内存文本通过 `yian-fmt --stdin` 格式化，返回覆盖整文档的 `TextEdit` |

格式化不读取标准库、包图或编译根，也不做语义分析。`anx fmt` 的项目发现与根包文件选择仍属于包管理器；
语言服务器的文档查找、协议分发与 UTF-16 位置计算仍属于 `lsp/`。文本无法词法或语法分析时，文件模式打印
`skip <path>: cannot be formatted` 并继续处理其余文件；stdin 模式不输出源码。

### 选项与退出码

- `yian-fmt FILE` 只接受一个被选中的 `.an`；默认模式没有摘要。
- `-w` 与 `--check` 互斥；`--stdin` 与位置路径、`-w`、`--check` 互斥；`--stdin-filepath` 必须与
  `--stdin` 同时出现且非空。没有输入、未知选项、互斥组合与空的文件选择都以退出码 2 结束，不写任何文件。
- `--` 之后的位置参数一律当作文件名。
- 退出码：`0` 成功；`1` `--check` 发现差异；`2` 参数、IO、UTF-8 或执行错误；`3` 词法/语法失败。
  多文件继续处理，最终状态按 `2 > 3 > 1 > 0` 汇总，不取数字最大值。写回模式下的正常差异不产生 `1`。
- `--help`/`-h` 与 `--version` 写 stdout 并返回 0；版本文本为 `yian-fmt 0.1.0`。
- 文件读取沿用 `read_source` 的 CRLF/CR 转 LF；stdin 原样传递内存文本，输出布局使用 LF。opaque
  literal 与 f-string 内部保持原字节。

### 子进程查找

`anx fmt` 与语言服务器按以下顺序查找 `yian-fmt`：

1. 非空 `YIAN_FMT`：含路径分隔符时按显式路径，裸名称按 `PATH`；配置无效时直接失败，不回退。
2. 未设置或空值：调用进程可执行文件同目录下的 `yian-fmt`。
3. 同目录不存在时才搜索 `PATH`。

最终候选必须是可执行的普通 native ELF 文件。查找过程只使用 `std.core.process` 的进程 API，不扫描
checkout、不构建工具、不调用 native `yianc` 的旧格式化参数，也不在进程内回退到格式化算法。

`anx fmt` 把根包源文件的绝对路径放在一次子进程的 `--` 之后，stdout/stderr 继承；子进程返回 0 时父进程
返回 0，任何非零、信号或启动错误都映射为 1。零个根包源文件时打印 `0 file(s) checked, 0 rewritten` 或
`0 of 0 file(s) need formatting` 并返回 0，不启动子进程。

语言服务器把当前内存文本的 UTF-8 字节写入子进程 stdin 并关闭输入，同时捕获 stdout/stderr。退出码 0 的
stdout 解码后成为编辑文本；退出码 3 产生空编辑；其他状态、启动错误或非 UTF-8 输出写 server stderr 后
产生空编辑。子进程 stdout 从不直接写入 server 的协议 stdout。相对原文无变化时返回 `[]`。编辑范围总是
基于**原始内存文本**的 UTF-16 末端，包括 CRLF 与末尾换行，使应用编辑后不会残留旧换行。

日常命令、`anx` 和 formatter 验收都使用 native 实现。`python/yianc/format/` 是恢复用途的参考副本，
不作为日常命令、测试或预期生成器的依赖；Python recovery CLI 保留自己的格式化参数，与 native 命令边界
无关。

## 结构

```text
fmt/src/trivia.an   从 token 间隙恢复注释与空行
fmt/src/rules.an    空格、缩进、换行、空行与注释放置规则
fmt/src/layout.an   按规则布局 token
fmt/src/api.an      format_text 的 native API
fmt/src/cli.an      独立命令的参数、stdin、文件枚举与退出码
fmt/src/main.an     以 run 的返回值退出
anx/src/driver/formatter.an
                    命令查找与 stdin 文本子进程协议
tests/format/fixtures/                  固定输入与手工审阅的 .expected.an
fmt/tests/integration/formatter.an
                                       native token、幂等、注释、布局与间距断言
```

`fmt` 包依赖 `yianc` 的前端模块（token、`prepare_file`、`SourceText`、`AnalysisError`），接受包级
LLVM 构建依赖；`yianc` 不依赖 `fmt`。`anx` 与 `lsp` 不链接格式化实现，它们通过子进程使用同一个命令。

### 注释来自 token 间隙

词法器跳过空白与注释，不产出 token，因此相邻两个 token 之间的源文本是它们唯一的记录。字符串与字符
字面量各自是一个 token，其内容不会出现在间隙里，所以扫描间隙即可完整恢复注释（`//` 到行尾、
`/* */` 到闭合）与空行数（前后 token 的行号差）。最后一个 token 后的终端间隙也会保留末尾注释；
只有注释、没有 token 的文件同样会被格式化并保留注释。

例外是 f-string：它的 `{` 不在任何 token 的 span 内，所以整段 f-string（`FStrStart` 到 `FStrEnd`）
按原文逐字保留，内部排版不在格式化范围内。

### 布局规则

缩进 4 空格一层；`{` 与所属行同行、`}` 单独一行，除非源里把这一对写在同一行（单行块保持单行）；
单行块以外的语句以 `;` 结尾后换行；圆括号与方括号内的 `;` 不强制换行，数组重复表达式保持
`[7; 2]`。`else`、`elif` 与前面的 `}` 同行；其余位置除结构要求外保留作者写下的换行。
格式化器不按行宽折行。

三类 token 需要上下文才能定空格，它们在布局前一次性算好：

| 情况 | 判定 | 写法 |
| --- | --- | --- |
| 泛型括号与比较 | 词法器按"前有无空白"分成 `LAngle`/`RAngle` 与 `Less`/`Greater` | `Vec<i32>` 紧贴；`a < b` 两侧空格 |
| 后置指针/引用 | 左侧是操作数结尾且右侧不能起操作数 | `i32*`、`T**`、`Vec<i32>*` 紧贴；`a * b`、`*p` 按前后文 |
| 字段初始化与闭包 | `=` 前是名字且名字前是 `(`/`,`；`|` 出现在操作数不能结束的位置 | `Point(x=1.0)`、`Unit(value=())`、`Holder(values=[1, 2], pair=(3, 4))` 的等号两侧紧贴；`|x_in = x| (y: i32) -> i32 { … }` |
| 模式测试关键字 | `matches` 后开始圆括号、方括号或一元负数的模式 | `value matches (0 \| 1)`、`items matches [first, .., last]`、`value matches -1` |

其余规则：`:` 类型标注前无空格后有；`,` 前无空格后一个；`.` 紧贴；`..` 通常紧贴，括号端点的例外见
“已知限制”；`@name` 在 `@` 前留空格、
与名字紧贴；二元运算符与 `->`、`=>`
两侧各一个空格；空行最多保留一个；注释文本原样保留，只去掉每行行尾空白，独占一行的注释按当前缩进
对齐，行尾注释前至少一个空格；条件括号（`if (x)` 与 `if x`）保留作者写法；`let` 与解构模式的
左圆括号之间保留一个空格，如 `let (a, b) = (1, 2);`。

无法词法或语法分析的文件返回 `None`：不输出半成品，编辑器侧表现为不做任何修改。

## 检查

固定用例和不变式由 native 集成测试验证；格式检查使用 `yian-fmt` 或 `anx fmt`。恢复副本的 `--bless`
不用于更新权威预期：

```bash
yian-fmt --check yianc/src
anx fmt --check yianc/src
anx fmt --check lsp
```

fixture 不变式由 `fmt/tests/integration/formatter.an` 覆盖，作为 native 包测试的一部分运行。

五条不变式在 `fmt/tests/integration/formatter.an` 中以固定 fixture 核对：

1. **token 守恒**：格式化后重新词法分析得到相同的 token 序列（种类与拼写都相同）。语法分析是 token
   的函数，所以这同时保证语法树不变。
2. **幂等**：对输出再格式化不产生变化。
3. **注释守恒**：注释条数、文本、独占一行/行尾的归属都不变。
4. **排版**：没有行尾空白、缩进是整层、文件以单个换行结束（字面量与 f-string 内部除外，那里逐字保留）。
5. **邻接空格**：词法器不敏感、因而 token 守恒看不见的那些位置单独检查——`Holder([1])` 与
   `f([1, 2])` 的 `([` 紧贴、`return [1, 2]` 与 `assert **p` 的空格、`i32*[3]` 的后缀、`*(p + 2)` 的
   前缀、`![4]` 与 `-> ! {` 的 never 类型。检查独立于布局引擎重述这些期望，再从输出文本里量回来。

固定 fixture 包含独占行、行尾和块注释、嵌套泛型、指针、关键字操作数间距、`let` 解构模式、
数组重复表达式与字段初始化的括号间距；测试读取固定
`.expected.an`，不会从当前 formatter 自动生成或 bless 期望。

## 已知限制

- 不折行、不做列对齐。单行分支体之间的 `} elif`、`} else` 合并到同一行，长分支链也不按行宽拆分。
- 圆括号、方括号之外的表达式续行只按块层级缩进，没有额外的续行缩进。
- 同一行连续闭合多层圆括号时，缩进只按第一个右括号计算；嵌套调用的 `));` 可以比调用起始行多缩进一层。
- 范围端点以左圆括号开始时保留一个空格，例如 `start.. (start + 1u64)`。
- 不排序 import、不增删括号：格式化只做保内容的排版。
- f-string 内部逐字保留。
- 不格式化语法错误的文件（类型错误的文件可以：格式化只需要词法与语法）。
- 只支持整文件格式化：语言服务器只提供 `textDocument/formatting`（整文档编辑），不提供
  `textDocument/rangeFormatting` 与 `onTypeFormatting`，因此编辑器的 `editor.formatOnSaveMode` 需保持默认 `file`。
- 行尾统一为 LF：CRLF 输入格式化后变成 LF。
