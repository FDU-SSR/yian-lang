# 28 格式化器

对应源文件：`compiler/format/`

格式化器把一份 `.an` 源码重新排版成规范形式：它读入文本，用词法器取 token，再按固定规则重排空白、
换行与注释位置。**内容不改**——除空白与注释位置外，token 序列逐字不变，因此格式化后的文件是同一个
程序。

```python
from compiler.format import format_text

formatted = format_text(text, path=Path("main.an"))   # None 表示无法格式化
```

## 三个入口

| 入口 | 用法 |
| --- | --- |
| `yianc --format` | 单文件打到 stdout；`-w` 原地写回；`--check` 只报告差异并以退出码 1 表示需要格式化 |
| `anx fmt` | 按 `Project.files` 格式化根包自己的源码；`--check` 同样只报告 |
| `textDocument/formatting` | 编辑器请求：返回一个覆盖全文的 `TextEdit`（`lsp/formatting.py`），可一次撤销 |

三者共用 `compiler/format/` 的同一实现，对同一文件产生字节相同的结果。

## 结构

```text
trivia.py     从 token 间隙恢复注释与空行
layout.py     布局引擎：空格表、缩进、换行、空行、注释放置
formatter.py  format_text / lex_tokens：唯一的公开入口
stats.py      语料统计（--stats）：风格规则的实测依据
selfcheck.py  五条不变式的检查（--verify）
cases.py      自带固定用例与 --cases / --bless
fixtures/     用例本体，按主题分目录
__main__.py   python3 -m compiler.format 的命令行
```

### 注释来自 token 间隙

词法器跳过空白与注释，不产出 token，因此相邻两个 token 之间的源文本是它们唯一的记录。字符串与字符
字面量各自是一个 token，其内容不会出现在间隙里，所以扫描间隙即可完整恢复注释（`//` 到行尾、
`/* */` 到闭合）与空行数（前后 token 的行号差）。

例外是 f-string：它的 `{` 不在任何 token 的 span 内，所以整段 f-string（`FStrStart` 到 `FStrEnd`）
按原文逐字保留，内部排版不在第一版范围内。

### 布局规则

缩进 4 空格一层；`{` 与所属行同行、`}` 单独一行，除非源里把这一对写在同一行（单行块保持单行）；
语句以 `;` 结尾后换行。**换行是保守的**：只在结构要求处强制换行（`{` 之后、`;` 之后、`}` 之前），
其余保留作者写下的换行，因此不会重排长行。

三类 token 需要上下文才能定空格，它们在布局前一次性算好：

| 情况 | 判定 | 写法 |
| --- | --- | --- |
| 泛型括号与比较 | 词法器按"前有无空白"分成 `LAngle`/`RAngle` 与 `Less`/`Greater` | `Vec<i32>` 紧贴；`a < b` 两侧空格 |
| 后置指针/引用 | 左侧是操作数结尾且右侧不能起操作数 | `i32*`、`T**`、`Vec<i32>*` 紧贴；`a * b`、`*p` 按前后文 |
| 字段初始化与闭包 | `=` 前是名字且名字前是 `(`/`,`；`|` 出现在操作数不能结束的位置 | `Point(x=1.0)` 紧贴；`|x_in = x| (y: i32) -> i32 { … }` |

其余规则：`:` 类型标注前无空格后有；`,` 前无空格后一个；`.`、`..`、`@` 紧贴；二元运算符与 `->`、`=>`
两侧各一个空格；空行最多保留一个；注释文本原样保留，只去掉每行行尾空白，独占一行的注释按当前缩进
对齐，行尾注释前至少一个空格；条件括号（`if (x)` 与 `if x`）保留作者写法。

无法词法或语法分析的文件返回 `None`：不输出半成品，编辑器侧表现为不做任何修改。

## 检查

格式化器自带检查，不进入编译器的测试运行器：

```bash
python3 -m compiler.format --verify lib/src tests/basic ide-support/sample  # 五条不变式
python3 -m compiler.format --cases                                          # 自带用例
python3 -m compiler.format --bless                                          # 重新生成用例期望
python3 -m compiler.format --stats lib/src                                  # 语料统计
```

五条不变式（`selfcheck.py`）：

1. **token 守恒**：格式化后重新词法分析得到相同的 token 序列（种类与拼写都相同）。语法分析是 token
   的函数，所以这同时保证语法树不变。
2. **幂等**：对输出再格式化不产生变化。
3. **注释守恒**：注释条数、文本、独占一行/行尾的归属都不变。
4. **排版**：没有行尾空白、缩进是整层、文件以单个换行结束（字面量与 f-string 内部除外，那里逐字保留）。
5. **邻接空格**：词法器不敏感、因而 token 守恒看不见的那些位置单独检查——`Holder([1])` 与
   `f([1, 2])` 的 `([` 紧贴、`return [1, 2]` 与 `assert **p` 的空格、`i32*[3]` 的后缀、`*(p + 2)` 的
   前缀、`![4]` 与 `-> ! {` 的 never 类型。检查独立于布局引擎重述这些期望，再从输出文本里量回来。

`--verify` 跳过 `*.err.an`：那些文件本来就是给编译器报错用的。

## 耗时

单文件（含词法、语法分析与重排）：284 行的 `lib/src/core/string.an` 8.3 ms，语料最大的
`lib/src/core/str.an`（389 行）13.9 ms；579 个文件整批 0.68 s（平均 1.2 ms/文件）。

## 已知限制

- 不折行、不做列对齐：语料的 p99 行长 82 列，超过 100 列的只有 20 行，重排长行收益小于规则复杂度。
- 不排序 import、不增删括号：格式化只做保内容的排版。
- f-string 内部逐字保留。
- 不格式化语法错误的文件（类型错误的文件可以：格式化只需要词法与语法）。
- 只支持整文件格式化：`textDocument/rangeFormatting` 与 `onTypeFormatting` 未提供，因此编辑器的
  `editor.formatOnSaveMode` 需保持默认 `file`。
- 行尾统一为 LF：CRLF 输入格式化后变成 LF。
