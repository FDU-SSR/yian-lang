# 07 调用 Lowering

`compiler/analysis/lowering/call_dispatcher.py` — 将函数调用和方法调用 AST 节点翻译为 HIR。

## CallDispatcher

```python
class CallDispatcher:
    def handle_call(self, node: AST.Call) -> HIR.Expr
    def handle_builtin(self, node: AST.BuiltinCall) -> HIR.Expr
    def handle_method_call(self, node: AST.MethodCall) -> HIR.Expr
```

## 函数调用：handle_call

```python
def handle_call(self, node):
    # Generic functions are called through their symbol (records a name ref).
    if callee is Identifier and symbol.kind is Function and contains_generic(symbol.type_id):
        return handle_function_call()
    # Otherwise the callee is evaluated as a value and dispatched by its type.
    callee = self.__expr.value(node.callee)
    match callee:
        case HIR.Ty:               return __handle_type_call()      # 类型构造
        case FunctionType:         return __emit_concrete_call()    # 函数项
        case ClosureType:          return __emit_concrete_call()    # 闭包
        case FunctionPointerType:  return __emit_concrete_call()    # 函数指针

def handle_builtin(self, node):
    # The parser has already resolved @name to AST.BuiltinKind.
    match node.kind:
        case BuiltinKind.Panic | RuntimeFail | Argc | …:
            return self.__handle_…(node)
```

内置指令统一使用 `@name`：`@sys_read`、`@sys_write`、`@panic`、`@open`、
`@close`、`@sqrt`、`@assume_init`、`@memcpy`、`@slice_*`、`@str_*`、
`@runtime_fail`、`@argc`、`@arg_bytes` 和 `@exit`。解析器在 `AST.BuiltinCall` 中
记录 `BuiltinKind`，随后由 `handle_builtin` 按 `kind` 派发；受限指令仍由 restricted-operation
检查限制在标准库。

> `@sizeof`、`@Undef`、`@dangling`、`@bitcast`、`@alloc` 由 parser 直接生成
> `AST.SizeOf` / `AST.Undef` / `AST.Dangling` / `AST.BitCast` / `AST.Alloc`，不经过
> `CallDispatcher`；它们不是关键字，因此裸名称可以由用户定义。

### 函数变量（函数项）的调用

若被调者的静态类型是 `FunctionType`（函数项，见 `05.type_system.md`）——例如
`let f = foo` 后的 `f()`、`(h.f)(x)`、`arr[i](x)`——`handle_call` 走 `__emit_concrete_call`：

- **固定签名直接派发**：实参按函数项已固定的参数类型协调，**不做泛型推断、不接受
  泛型实参**（与函数指针调用一致）。
- 生成 `HIR.Invoke`（携带被调表达式以保留其副作用）；CFG 中 `resolve_invoke`
  发现被调者类型为 `FunctionType` 时，先求值被调表达式与实参，再发**直接** `IR.Call`
  （被调身份来自具体静态类型）。
- 因函数项是 ZST，被调值不占运行期空间，整体为零开销直接调用。

绑定泛型参数未解析的函数（`let f = generic_fn;`）会报错：函数变量必须绑定具体函数。

## 方法调用：handle_method_call

```python
def handle_method_call(self, node):
    receiver = self.__expr.value(node.receiver)
    if receiver is HIR.Ty:                       # Self.method() / Type.method()
        return self.__handle_static_or_variant_method_call(node, receiver)
    return self.__handle_instance_method_call(node, receiver)
```

`Clone` 和用户定义方法都走正常的 `method_lookup` 和 `HIR.MethodCall`，不存在按方法名改写返回值的捷径。标准库 `Clone` 不是指针自身的实现：对指针调用 `clone()` 时，方法查找按常规自动解引用，对指向的值调用 `Clone`，返回值类型为指向值本身，`ptr.clone()` 等价于 `(*ptr).clone()`。

方法名到 HIR 的映射只由解析到的 trait 实现决定：`move`、`clone`、`invalidate`、`is_valid` 与其他方法名一样走普通查找，没有针对名称的捷径，也不存在按类型分类自动成功的分支。

## dispatch_method_call — 核心流程

```python
def dispatch_method_call(self, span, receiver, method_name, generic_args, args, context_name):
    # 1. 方法查找
    lookup = type_ctx.method_lookup(receiver, method_name, generic_args, args)

    # 2. 静态调用检查
    if receiver is HIR.Ty and not method.is_static:
        raise AnalysisError("cannot call instance method as static")

    # 3. Auto-deref: 沿 deref chain 自动解引用
    for _ in range(lookup.deref_count):
        if PointerType:  receiver = Deref(receiver)
        else:            receiver = call deref() trait method

    # 4. 构建 HIR.MethodCall
    return build_method_call(span, receiver, lookup, args, context_name)
```

## Deref Chain

```python
def deref_chain(self, type_id):
    chain = [type_id]
    while True:
        next_ty = self.try_deref(current)
        if next_ty is None: break
        chain.append(next_ty)
    return chain

def try_deref(self, type_id):
    ty = self[type_id]
    if PointerType or RefType: return ty.pointee_type  # 指针/引用解引用
    return impl_registry.find_deref_target(type_id)    # Deref trait
```
