# 14 CLI 与构建

`compiler/main.py` — 编译入口和构建流程。

## CLI 参数

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `paths` (位置) | `.an` 源文件或目录 | 必需 |
| `-t` / `--target` | 输出类型: `exe`/`none`/`ll`/`bc`/`obj`/`asm` | `exe` |
| `-o` / `--output` | 输出路径 | 自动推导 |
| `-O` | 优化等级 (0-3) | `0` |
| `--profile` | 输出各阶段耗时 | — |
| `--dump` | 输出 tokens/AST/HIR/CFG 和 LLVM IR 中间文件 | 关闭 |
| `--log-spec` | 日志配置 | `""`（使用默认日志级别） |
| `--log-file` | 日志输出路径 | `build/compile.log` |
| `--packages` | JSON 文件，v2 包图，启用 Package 模式 | — |
| `--compiler-root` | YIAN 检出根，用于定位标准库 | `$YIAN_LIB` → `$YIAN_ROOT` → 本检出 |
| `--analyze` | 完成语义分析并报告诊断，不生成代码、不写 `build/` | 关闭 |
| `--json` | 配合 `--analyze`，在 stdout 打印一个 JSON 对象 | 关闭 |
| `--format` | 按规范排版给定源文件，默认打到 stdout | 关闭 |
| `-w` / `--write` | 配合 `--format`，原地写回 | 关闭 |
| `--check` | 配合 `--format`，只报告需要格式化的文件并以退出码 1 结束 | 关闭 |
| `--raw-pointers` | 使用裸 8 字节指针（无检查、无锁槽、无帧锁） | 关闭 |

## 两种编译模式

### Standalone 模式（默认）

不传 `--packages`。所有源文件作为位置参数传入。import 路径按相对路径解析。

```bash
yianc lib/src tests/basic/array/assign.an
```

### Package 模式

通过 `--packages pkg.json` 启用。import 的第一段被解析为包名，编译器从 v2 包图的 `packages` 表查找对应 `sourceRoot`。通常由 `anx build` 自动调用。

```bash
yianc --packages pkg.json file1.an file2.an ...
```

## 编译流程 (`main()`)

CLI 通过 `AnalysisSession` 运行完整语义分析，结果包含全部已检查定义、entry 可达的代码生成定义和
供查询使用的过程/名称引用快照。`-t none` 保留完整分析并跳过 CFG/LLVM；`--analyze` 也完成类型检查、
编译期条件专门化和 definite-assignment 检查，但不生成代码或写入 `build/`。

CLI 的代码生成阶段按以下接口连接；省略错误处理、日志、dump、计时和链接参数：

```python
analysis = session.analyze(paths, require_entry=target != "none", recover=False)
type_ctx = analysis.type_ctx
cfg_functions = CfgPipeline(type_ctx, raw_pointers).run(dict(analysis.generated_def_points))

translator = LLTranslator(type_ctx, dict(analysis.unit_names), raw_pointers, analysis.entry_type_id)
translator.run(cfg_functions)
llvm_module = translator.export()
Emitter().emit_module(llvm_module, ...)
```

此代码段展示阶段接口，不是可直接执行的完整 CLI。闭包具体化包含在 `CfgPipeline` 的 HIR → CFG 阶段。

## 输出目录

默认情况下，可执行文件、LLVM bitcode 和目标文件写入 `build/`；汇编文件写入当前目录：

```text
build/
├── tokens.txt     # Token 列表
├── ast.txt        # AST dump
├── hir.txt        # HIR dump
├── cfg.txt        # CFG dump
├── ir.ll          # LLVM IR
├── compile.log    # 日志
├── a.out          # exe
├── <name>.o       # obj
├── <name>.ll      # ll
├── runtime/       # 运行时库产物 (libyian_rt.o/.a, 首次使用时构建)
```

`-t asm` 的默认输出为当前目录下的 `<name>.s`；使用 `-o` 可以显式指定任意目标路径。

`--dump` 控制中间产物的生成；`-t ll` 输出未优化 LLVM IR。`-O` 对非 `ll` 目标同时影响 LLVM 优化、后端和 clang 链接。

## __link_exe

```python
def __link_exe(obj_path, output_path, opt_level, profile=False):
    runtime_archive = ensure_archive()   # compiler/runtime_lib.py; 首次使用时构建 runtime/
    cmd = [linker, str(obj_path), str(runtime_archive), "-o", str(output_path), f"-O{opt_level}"]
    # 失败时报错并以链接器退出码结束
    obj_path.unlink()                    # 清理中间 .o
```

`compiler/runtime_lib.py` 负责定位与按需构建运行时库：运行时源码比 `build/runtime/` 的产物新时才重新构建，构建失败抛 `RuntimeBuildError`。

`__merge_runtime_object` 服务于 `-t obj`：用 `clang -r -nostdlib` 把用户对象与运行时对象合并成一个可重定位对象，使产物单文件自包含。
