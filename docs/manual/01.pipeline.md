# 01 编译管线概览

## 管线图

```text

  │
  ▼
┌──────────────────────────┐
```

## main() 函数

`compiler/main.py` 调用 `AnalysisSession` 完成前端和语义分析，再把生成集合送入 CFG 与 LLVM。
完整分析会检查 entry 可达定义及根包中未实例化、不可达的定义；只有 entry 可达的具体定义进入
代码生成。以下伪代码概括命令行构建流程，省略错误处理与 dump/profile 分支：

```python
def main(argv=None) -> int:
    args = parse_cli(argv)              # 1. 解析 CLI 参数
    CompilerLog.init(...)               # 2. 初始化日志
    src_files = collect_an_files(...)   # 3. 收集 .an 文件
    token_lists = __lex(src_files)      # 4. Lex
    programs = __parse(token_lists)     # 5. Parse
    programs = __desugar(programs)      # 6. Desugar
    unit_datas = ...                    # 7. 构建 UnitData
    source_trust = build_source_trust() # 8. 标注标准库 / 受限操作权限
    inject_prelude(unit_datas.values()) # 9. Prelude 注入
    check_restricted_ops(...)           # 10. 受限操作检查
    type_ctx = TypeCtx(raw_pointers=…)  # 创建本次分析使用的类型上下文
    semantic = SemanticState(...)       # 解析期共享的类型、过程、名称与包状态
    GlobalResolve(semantic).run()        # 全局符号与类型解析
    type_ctx.finalize()                  # 完成类型与 impl 索引
    checker = TypeCheck(DefinitionState(semantic), ...)
    checker.run()                        # 类型检查并构造 HIR DefPoint
    ComptimeIfSpecializer(...).run()     # 编译期条件专门化
    DefiniteAssignment(...).run()        # 定值分析
    cfg_functions = __cfg(type_ctx, ..., generated_def_points)
    llvm_module = __llvm_codegen(...)    # CFG → LLVM IR
    Emitter().emit_module(...)           # 输出目标文件
```

`SemanticState` 持有一次分析共用的 `TypeCtx`、`ProcedureRegistry`、`NameReferences` 和
`TypeResolver`；`DefinitionState` 持有当前 definition 的符号作用域与遍历状态。分析结束后，
`AnalysisResult` 暴露过程、名称引用及代码生成所需定义的快照，不暴露可变的语义上下文。

闭包在 HIR 中保留 `HIR.Closure`、`HIR.Invoke` 与 `ClosureType`。HIR → CFG 时，闭包环境成为普通
结构体，捕获值按字段构造；闭包体以隐藏的环境引用作为首参数，捕获变量映射到环境字段，闭包调用
变成对闭包调用函数的普通 `IR.Call`。CFG 的类型映射把闭包类型及嵌套类型转换为环境结构体类型，
不改写语义分析阶段的类型签名。

## 关键数据结构

| 阶段 | 输入 | 输出 |
|------|------|------|
| Lex | `CharStream` | `list[Token]` |
| Parse | `list[Token]` | `AST.Program` |
| Desugar | `AST.Program` | `AST.Program` |
| Resolve | `UnitData` × N + `SemanticState` | 符号、类型与过程体登记 |
| TypeCheck | `SemanticState` + `DefinitionState` | `DefPoint`（带 HIR body） |
| Specialize / DA | `DefPoint` | 专门化并验证后的定义 |
| CFG | `TypeCtx` + 生成用 `DefPoint` | `CFG_IR.Function` |
| LLVM | `CFG_IR.Function` + `TypeCtx` | `ir.Module` |
| Emit | `ir.Module` | 目标文件 |

## 中间产物

所有中间产物写入 `build/`：

| 文件 | 阶段 | 说明 |
|------|------|------|
| `build/tokens.txt` | Lex 后 | 全文 token 列表 |
| `build/ast.txt` | Desugar 后 | AST 树形 dump |
| `build/hir.txt` | CFG 前 | HIR bundle dump |
| `build/cfg.txt` | CFG 后 | 各函数 CFG dump |
| `build/ir.ll` | 代码生成时 | LLVM IR 文本 |
| `build/compile.log` | 全流程 | 日志消息 |
| `build/a.out` | Emit | 可执行文件 (exe) |
