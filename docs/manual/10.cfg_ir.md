# 10 CFG IR

`yianc/src/codegen/cfg/model.an` 定义从 HIR 到 LLVM 之间的控制流图。一个 `CfgModule` 持有函数；
每个 `CfgFunction` 包含基本块、SSA 值、局部存储和逻辑作用域。块使用 `BasicBlock` 表示，持有指令
和终结符。值、块、local 与 scope 使用各自的 ID。

`Instruction` 记录 `Operation`、可选结果以及安全义务。终结符表示控制流边或函数退出。
CFG 验证检查类型、SSA 支配关系和安全阶段约束。

## Native enum place 操作

原生 `yianc` 的 CFG 模型（`yianc/src/codegen/cfg/model.an`）在通用值操作之外提供枚举专用的
place 操作。它们只用于带显式 tag word 与 payload 区的 tagged enum；ZST 与 niche 表示继续使用
`EnumConstruct`、`EnumTag` 与 `EnumPayload`。`--dump` 写出的 `build/cfg.txt` 以
`enum-init-at`、`enum-tag-at`、`enum-field-at`、`enum-copy-at` 记录这些操作。

| 操作 | 输入 | 结果 | 约束 |
| --- | --- | --- | --- |
| `EnumInitAt` | address、enum_type、discriminant、fields | 无 | 目标地址 pointee 为 enum_type；字段数与类型匹配所选变体 payload；按声明布局顺序写入 |
| `EnumTagAt` | address、enum_type | `u32` | 只读取 tag word，不加载整个 enum |
| `EnumFieldAt` | address、enum_type、discriminant、field_index | payload 字段类型 | 只在对应变体成功的分支生成；字段属于该变体 |
| `EnumCopyAt` | destination、source、enum_type | 无 | 两侧地址 pointee 均为 enum_type；按目标布局字节复制，允许重叠 |

`yianc/src/codegen/lowering/enum_storage.an` 用 `EnumPlace` 携带 `type_id`、`address` 与
provenance：`FreshDestination`（尚未发布的构造目标）、`Borrowed`（已有 place）与 `Snapshot`
（独立浅复制）。前两者可作为构造目标，快照只用于按值匹配读取。

相关不变量：

- payload 字段表达式按源码顺序求值一次，`EnumInitAt` 随后按声明布局顺序写入 tag 与字段。
- 未选变体的 payload 区保持零初始化（在存储上 `memset`），不读取未初始化字节。
- `EnumFieldAt` 不加载整个 payload 聚合；字段引用仍走 `EnumPayloadAddress` 与 `FieldAddress`。
- 新增临时槽通过现有 entry `alloca` 分配，循环体不产生动态 alloca，也不用共享槽指针 Phi
  替代值 Phi。
- `EnumCopyAt` 使用 `memmove` 语义，自复制与重叠来源合法。
- CFG verifier 对错误的 pointee、未知判别式、不匹配的字段数量/类型以及单位变体字段读取等内部不变量违反直接 panic。

## Native yianc 的作用域、阶段与安全计划

### 逻辑作用域

`CfgFunction.scopes` 是 `InlineScope` 列表。root scope 的 `parent` 为 `None`、`callable` 为函数自身；内联调用为被内联 callable 建立子 scope，父 scope 是调用点所在的逻辑 scope。`Local.scope` 指定局部地址属于哪个逻辑 scope。

`Operation.ScopeEnter` 与 `Operation.ScopeExit` 标记逻辑帧的动态进入和退出，不携带结果或 ValueId operand。`Operation.SafetyPoint` 是不产生值的安全检查承载点，供循环外提使用。三者参与 CFG dump，但不改变 SSA 值编号。

### 安全阶段

`CfgModule.safety_stage` 取值为：

| 阶段 | 内容 |
| --- | --- |
| `Neutral` | 无 `SafetyCheck`、无 `OperationGuard`、无 `live_proofs`、无 `FunctionFatPlan`、无表示表 |
| `Prepared` | 表示表已绑定，frame 计划已建立，所有安全检查与模板 guard 已插入 |
| `Optimized` | 在 `Prepared` 上消除冗余 `Live` 检查并可外提；proof 与 `SafetyPoint` 已记录 |

`CfgFunction.fat_plan` 为每个 scope 记录 `needs_lock`：只有该 scope 存在非 ZST 的局部地址操作时才为 true。raw 模式不建立该计划。

### 检查、guard 与 proof

`SafetyCheck` 保留原有的访问、范围、视图、索引、非空与拷贝义务，并增加 `Live` 和 `AccessBounds`。fat 模式把一次访问规范化为两个独立义务：`Live` 验证生命周期字，`AccessBounds` 验证裸指针索引范围；引用只产生 `Live`。

`OperationGuard` 描述 LLVM 模板在固定 `GuardSite` 处应展开的隐藏检查（例如 `Count`、`AllocationSize`、`HeapRoot`、`PointerStep`、`IndexOffset`、`CastAccess`、`DynamicReceiver`）。guard 的顺序由 CFG 固定，LLVM 只按序消费。

`LiveProof` 只出现在 `Optimized` 阶段：`address` 是被省略检查的地址，`witness` 是仍然保留并支配该使用点的 `Live` 检查位置（block、instruction、check）。独立验证会重新计算支配事实，不信任 proof 自身。

### 表示表

`CfgModule.representations` 按 TypeId 稳定列出 `TypeRepresentation`。fat/raw 分类在激活时一次完成并绑定到 `BackendTypes`；LLVM 不再根据类型临时决定指针表示。`PointerRepresentation` 覆盖非指针、ZST、raw/fat 地址、raw/fat 视图、raw/fat trait object、fat pointer 与 fat reference。
