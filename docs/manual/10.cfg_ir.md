# 10 CFG IR

CFG（Control Flow Graph）IR 是 HIR 与 LLVM IR 之间的中间表示。采用 SSA（静态单赋值）形式和 basic block 结构化控制流。

## 源文件

`python/yianc/codegen/cfg/ir.py`

## 核心类型

### Function

```python
@dataclass
class Function:
    name: str
    type_id: int                        # Function/method type_id.
    blocks: list[Block]                 # All basic blocks.
    entry: Block                        # Entry block, also in blocks.
    local_vars: dict[int, VarRef]       # symbol_id → VarRef
    params: list[int]                   # Parameter symbol_id list.
    frame_lock: tuple[Value, Value] | None  # <e_f,k_f>; None means no materialized frame lock.
```

### Block

```python
@dataclass
class Block:
    label: str                          # For example entry or loop.body.3.
    phis: list[Phi]                     # Phi nodes.
    stmts: list[Stmt]                   # Instruction list.
    terminator: Terminator | None       # Terminator.
```

### Value

```python
Value = Literal | Reg

@dataclass
class Reg:
    name: str       # SSA register name, such as %3.
    type_id: int    # Value type.
```

Literal 包含：`IntLiteral`、`FloatLiteral`、`BoolLiteral`、`CharLiteral`、`StringLiteral`。编译期条件在 AST → HIR 时求值并选择分支；AST 的 `CompileConfig` 在该阶段产生布尔字面量，不形成独立 CFG 节点。

`HIR.Defer` 同样不会形成 CFG/LLVM 独立节点。CFG builder 为每个 HIR block 维护活动的延迟操作栈：正常离开 block、函数返回、循环 `break` 或 `continue` 时，在生成调用、赋值、`Delete` 和控制流指令前按 LIFO 展开相应范围；延迟操作本身若产生终结符，则停止展开该范围的剩余操作。

### VarRef

```python
@dataclass
class VarRef:
    name: str        # Variable name.
    symbol_id: int   # Symbol ID.
    type_id: int     # Variable type.
```

## 终结符 (Terminator)

| 终结符 | 说明 | 关键字段 |
|--------|------|---------|
| `Ret` | 返回 | `value` |
| `Br` | 无条件跳转 | `target` |
| `CondBr` | 条件跳转 | `cond`, `then_block`, `else_block` |
| `Unreachable` | 不可达位置 | 无 |
| `Panic` | 运行时错误 | `message` |
| `RuntimeFail` | 固定运行时错误 | `code` |
| `ProcessExit` | 立即退出进程 | `code` |

### Phi 节点

```python
@dataclass
class Phi:
    result: Reg
    incoming: list[tuple[Block, Value]]   # (source block,value).
```

## Native enum place 操作

原生 `yianc` 的 CFG 模型（`yianc/src/codegen/cfg/model.an`）在通用值操作之外提供枚举专用的
place 操作。它们只用于带显式 tag word 与 payload 区的 tagged enum；ZST 与 niche 表示继续使用
`EnumConstruct`、`EnumTag` 与 `EnumPayload`。`--dump` 写出的 `build/cfg.txt` 以
`enum-init-at`、`enum-tag-at`、`enum-field-at`、`enum-copy-at` 记录这些操作。

| 操作 | 输入 | 结果 | 约束 |
| --- | --- | --- | --- |
| `EnumInitAt` | address、enum_type、discriminant、fields | 无 | 目标地址 pointee 为 enum_type；字段数与类型匹配所选变体 payload；按声明布局顺序写入 |
| `EnumTagAt` | address、enum_type | `u32` | 只读取 tag word，不加载整个 enum |
| `EnumFieldAt` | address、enum_type、discriminant、field_index | payload 字段类型 | 只在对应变体成功的分支生成；字段属于该变体 |
| `EnumCopyAt` | destination、source、enum_type | 无 | 两侧地址 pointee 均为 enum_type；按目标布局字节复制，允许重叠 |

`yianc/src/codegen/lowering/enum_storage.an` 用 `EnumPlace` 携带 `type_id`、`address` 与
provenance：`FreshDestination`（尚未发布的构造目标）、`Borrowed`（已有 place）与 `Snapshot`
（独立浅复制）。前两者可作为构造目标，快照只用于按值匹配读取。

相关不变量：

- payload 字段表达式按源码顺序求值一次，`EnumInitAt` 随后按声明布局顺序写入 tag 与字段。
- 未选变体的 payload 区保持零初始化（在存储上 `memset`），不读取未初始化字节。
- `EnumFieldAt` 不加载整个 payload 聚合；字段引用仍走 `EnumPayloadAddress` 与 `FieldAddress`。
- 新增临时槽通过现有 entry `alloca` 分配，循环体不产生动态 alloca，也不用共享槽指针 Phi
  替代值 Phi。
- `EnumCopyAt` 使用 `memmove` 语义，自复制与重叠来源合法。
- CFG verifier 拒绝错误的 pointee、未知判别式、不匹配的字段数量/类型以及单位变体字段读取。

Python recovery compiler 的 CFG 指令集不包含这些操作，仍按本章前面的表生成通用值操作。
