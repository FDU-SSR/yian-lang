# 25 anx 自身的测试

对应源文件：`anx/project_tests.py`（项目测试运行器）、`scripts/run_tests.py` 的 package 套件、
`tests/package/`、`tests/output/package/`、`tests/input/package/`

anx 有两层「测试」需要区分：

- **`anx test`**：跑**用户项目**的测试。实现在 `anx/project_tests.py`。
- **anx 自身的回归测试**：跑 `tests/package/` 下的 fixture。实现在 `scripts/run_tests.py`，
  由 `--suite package` 驱动，用的是同一个 `anx` 命令。

## `anx test` 的内部结构

### 发现

```python
TESTS_DIR_NAME = "tests"
TEST_PACKAGE = "__anx_test"

def discover(project_root: Path) -> tuple[ProjectTest, ...]
```

- 用例 = `<项目根>/tests/**/*.an`，按路径排序；
- 期望文件在 `<项目根>/tests/output/`，镜像 `tests/` 的相对路径；
- 进程参数与标准输入在 `<项目根>/tests/input/<base>.args` / `.stdin`，
  `<base>` 是相对路径去掉 `.an` / `.err.an`；
- 名字以 `.err.an` 结尾 → 期望编译失败；否则期望正常退出。

`__expectation()` 读 `.ans`：首行 `Exit code <N>` 指定期望退出码，其余是期望输出；
`.err.an` 的 `.ans` 内容是必须出现的诊断子串（不看编译器退出码）。

### 合成测试包

每个用例都以 **package 模式**编译。`__test_package_map(project, test)` 在
`Project.package_specs()` 之上追加一条：

```json
"__anx_test": {
  "sourceRoot": "<项目根>/tests",
  "kind": "bin",
  "entry": "<当前用例文件>",
  "dependencies": ["<根包（仅 lib/hybrid）>", "<根包的依赖>…", "<根包的 dev 依赖>…"]
}
```

把这个合成包设为 `root` 之后：

| 问题 | 解法 |
| --- | --- |
| 用例要能当程序跑 | `entry` 指向用例文件本身，它在 `src/` 之外也没关系——编译器只按路径找 unit |
| 用例要能导入项目 | 把根包与它的直接依赖放进 `dependencies` |
| 用例要能用 dev 依赖 | 把 `dev_dependencies` 也放进去（[21](21.anx_manifest.md)） |
| 根包自己的 `main` 不撞程序入口 | 程序入口是 `__anx_test.entry`，根包的 `main` 只是普通函数 |
| 可见性规则不能被绕开 | 合成包只声明「项目代码能看见的」那些边，传递依赖照样报 `AX009` |
| 检查根不扩散 | 检查根按 `packages.root` 判定，落在测试包上，只有当前用例被全量检查 |

**根包是 `bin` 时故意不加入 `dependencies`**：bin 没有库接口，用例导入它应当报 `AX009`。
这与 Cargo 一致（bin-only crate 的 `tests/` 没有 library 可链接），`__bin_root_hint()` 会在
失败详情里补一句「declare kind = "hybrid"」，因为那条 `AX009` 单看很难懂。

### 执行

`__run_one` 为每个用例：

1. 写 `<项目根>/build/test/pkg.json`（每个用例重写，因为 `root`/`entry` 不同）；
2. 组装命令：`compiler --packages pkg.json <flags> <用例文件> <project.files…>`，
   `.err.an` 用 `-t none`，否则 `-t exe -o build/test/<name>.out`；
3. cwd 取**项目根**（编译器的 `build/` 产物落在项目里）；
4. `.err.an`：编译必须失败，且输出里含期望子串；
5. 否则编译必须成功，运行可执行文件（带 `.args` / `.stdin`），把 stdout+stderr 合并、
   去首尾空白后与期望比较，再检查退出码。

汇总输出 `[ok]` / `[FAIL]`，最后一行 `N passed, M failed, T total`，失败详情在汇总之后打印。
`run()` 的返回值：有失败、没有用例、项目诊断非空、或 `__anx_test` 与项目已有包重名时返回 1。

## 仓库怎么测 anx

`tests/package/` 下的每个 fixture 就是一个真实项目，由 `scripts/run_tests.py` 的 package
套件驱动：

```bash
python3 scripts/run_tests.py --suite package          # 全部 fixture
python3 scripts/run_tests.py --suite package -f deps  # 只跑名字含 deps 的
python3 scripts/run_tests.py --suite package --no-run # 用 anx check 代替 build
```

### 什么算一个 fixture

`discover_package_tests()` 遍历 `tests/package/**/package.anx`，满足任一条件才算一个用例：

- 有 `src/main.an`（bin/hybrid 根包），或
- 有期望文件 `tests/output/package/<fixture>.{ans,err.ans}`，或
- 有命令文件 `tests/input/package/<fixture>.command`。

被已注册的用例包住的目录会跳过——所以一个 fixture 的**依赖包**（没有入口、没有期望、没有命令）
不会被误当成用例。

### 驱动方式

`tests/input/package/<fixture>.command` 指定用哪个子命令（可带参数）：

| 内容 | 行为 |
| --- | --- |
| （缺省） | `anx build`，成功后运行 `build/app`；`--no-run` 时改 `anx check` |
| `check` | `anx check`：只验证分析通过（`lib` 根包只能这样测） |
| `test` | `anx test`：验证项目测试运行器的行为（fixture 自带 `tests/`） |
| `graph --json` | `anx graph`：只验证退出码与输出里的诊断子串 |

只有 `build` 会产生可执行文件，其余三种都按「分析型」用例处理（不比对程序 stdout）。

期望文件与仓库其它套件同一套约定：

| 文件 | 含义 |
| --- | --- |
| `tests/output/package/<fixture>.ans` | 期望 stdout（首行可为 `Exit code <N>`） |
| `tests/output/package/<fixture>.err.ans` | 必须出现的诊断子串（包括 `AXnnn`） |

其中 `test` 驱动的 fixture 自带**自己的** `tests/output/`（项目测试的期望），与套件的
`tests/output/package/` 是两棵树。

### 指针模式矩阵

package 套件和 basic 套件一样跑 **fat / raw 两遍**：`__package_mode_test()` 给用例补
`anx_args`（`--raw-pointers`），用例名带 `@fat` / `@raw` 后缀。`graph` 驱动的 fixture 不参与
展开（它不编译任何东西）。因此 fixture 数 × 2 ≈ 用例数。

## 加一个 fixture 的步骤

1. 在 `tests/package/` 下建目录（通常按主题分组：`basic/`、`deps/`、`errors/`、`migrated/`），
   写 `package.anx` 与 `src/`；
2. 期望正常构建 → 什么都不用加（有 `src/main.an` 即被认作用例）；
   期望报错 → 加 `tests/output/package/<fixture>.err.ans`，内容写必须出现的子串（例如 `AX009`）；
3. 需要非 `build` 的驱动 → 加 `tests/input/package/<fixture>.command`；
4. 需要验证项目测试 → 建 `tests/`、`tests/output/`、`tests/input/`，并把 `.command` 写成 `test`；
5. 跑 `python3 scripts/run_tests.py --suite package -f <名字> -v`。

依赖包通常放在 fixture 目录内部（`deps/`、`vendor/`、`lib/`…）。发现顺序按路径字典序，
**父目录先注册就会把整棵子树排除**；因此只要依赖包自己不满足「算用例」的三个条件就没问题
（普通的 `lib` 依赖都没有入口、没有期望文件）。

例外是**依赖自己带 `src/main.an`**（`hybrid` / `bin` 依赖）：这种目录名必须排在
`package.anx` 之后，否则它会被当成一个独立用例。仓库里的写法是把这类依赖目录命名为
`tool`（`p` < `t`）；如果非要用 `a`–`o` 开头的名字，就把它挪到 fixture 之外再引用。
