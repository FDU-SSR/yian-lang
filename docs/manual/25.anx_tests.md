# 25 anx 项目测试与仓库 fixtures

对应源文件：`bootstrap/anx/src/driver/test.an`、`project/package_map.an`、`scripts/run_tests.py`、
`tests/package/`、`tests/output/package/`、`tests/input/package/`。

## `anx test`：测试项目自己的程序

原生 anx 递归收集 `<project>/tests/**/*.an`。每个源文件都是独立测试入口，按收集顺序逐个编译和执行；
`.err.an` 文件是预期编译失败用例。项目没有测试时返回失败。根包不能已经声明 `__anx_test`，因为该名字用于
合成测试根。

每个用例的期望文件位于 `<project>/tests/output/`，路径镜像测试名并以 `.an.ans` 结尾。例如
`tests/smoke.an` 对应 `tests/output/smoke.an.ans`；`tests/errors/bad.err.an` 对应
`tests/output/errors/bad.an.ans`。普通用例可在首行写 `Exit code <N>`；后续文本是期望输出。没有首行时，
预期退出码为 0。错误用例要求 compiler 失败，期望文件余下文本若非空则必须作为诊断子串出现在合并输出中。
文本比较忽略首尾空白。

可选输入放在 `<project>/tests/input/`：同 stem 的 `.args` 以空白拆成程序参数，`.stdin` 提供标准输入；
没有 `.stdin` 文件时测试进程继承 anx 的 stdin。测试程序以其源文件所在目录作为当前目录。

## 合成测试根

`test_package_map_json()` 为每个用例生成 package map，根名为 `__anx_test`，`sourceRoot` 是项目的 `tests/`，
`entry` 是当前 `.an` 文件，`kind` 为 `bin`。该合成包的依赖包括根包（根 kind 为 `lib`/`hybrid` 时）、根包的
普通依赖和 dev 依赖；合成根继承根包的 FFI 标志。项目中其他包各自的权限和 LLVM shim 元数据继续保留。

因此普通项目源码不能通过 dev dependency 导入，测试源码可以；`bin` 根包本身不能被测试代码作为库导入。
所有测试都在 package mode 编译，编译器看到合成测试根作为程序入口。错误用例使用 `-t none`，其他用例生成
`<project>/build/test/` 下的独立可执行文件。源码入口和项目索引文件一并传给 compiler。

## 仓库 package fixtures

`tests/package/` 中的每个 fixture 是一个真实项目，由 `scripts/run_tests.py --suite package` 驱动。目录下的
`tests/input/package/<fixture>.command` 可指定 `build`、`check`、`test` 或 `graph [--json]`；缺省为 `build`。
期望位于 `tests/output/package/`，`.ans` 比较成功输出，`.err.ans` 记录必须出现的错误子串。

package 套件按 fat/raw 编译器选项运行适用的 fixture；`graph` 不进入指针模式展开。默认 `both` 选择会分别
使用 Python 和 native compiler，但两者都由同一个安装的 native anx 驱动，`YIANC` 指向被测 compiler。选择包含
`native` 时 runner 要求所选 prefix 已安装可执行的 native `yianc`；package/bootstrap suite 还要求可执行的
native `anx`。runner 不会安装或刷新工具。缺工具时，冷启动使用
`scripts/bootstrap_toolchain.sh --prefix PATH --python PYTHON`；已有兼容 native seed 时使用
`scripts/refresh_toolchain.sh --prefix PATH --anx PATH --yianc PATH`。用 `--prefix` 或 `YIAN_INSTALL_PREFIX` 指定位置。

例如，下面是完整 package 套件入口（是整个 suite，不是一个单用例检查；所需native工具必须已安装）：

```bash
conda run --no-capture-output -n yian-env python scripts/run_tests.py --suite package --implementation both
```

## fixture 文件与 suite 边界

| 文件 | 用途 |
| --- | --- |
| `tests/package/<name>/package.anx` | fixture manifest |
| `tests/input/package/<name>.command` | 选择 anx 子命令和额外参数 |
| `tests/output/package/<name>.ans` | 期望成功输出/退出码 |
| `tests/output/package/<name>.err.ans` | 期望错误子串 |

`test` 命令 fixture 还可带自己的 `tests/`, `tests/input/`, `tests/output/`，那是被测项目的 package tests，
与仓库 package suite 的期望树分开。被父 fixture 注册为依赖的嵌套目录不会作为独立 fixture；包含入口的
可执行依赖应保持其目录顺序，使 runner 在父 fixture 下发现它。

bootstrap 套件则调用原生 anx 对 `bootstrap/yianc`、`bootstrap/json`、`bootstrap/toml`、
`bootstrap/jsonrpc` 和 `bootstrap/lsp_protocol` 执行 package tests。`scripts/run_tests.py` 的实现轴选择
compiler；`anx test` 本身始终是安装的原生包管理器。
