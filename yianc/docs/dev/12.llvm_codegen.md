# 12 LLVM 代码生成

`yianc/src/codegen/llvm/module.an::LlvmLowering` 在目标布局上声明符号、创建基本块，并将 CFG 指令和终结符映射到 LLVM IR。`codegen/types.an` 负责后端类型及表示，`bootstrap/llvm` 提供 LLVM 22 绑定。

`codegen/driver.an` 调度 LLVM 验证、优化和目标输出。LLVM 层使用 CFG 已经绑定的指针表示及安全义务。

## Native yianc 的 enum place 下降与 linkage

### Enum place 下降

`yianc/src/codegen/llvm/enums.an` 把四个 place 操作翻译为目标地址上的标量与内存操作：

| 操作 | LLVM 下降 |
| --- | --- |
| `EnumInitAt` | 写 tag word；对 payload 区 `memset` 零初始化；按 payload 结构 GEP 逐字段 `store`（对齐 1） |
| `EnumTagAt` | 对 enum 第 0 字段 GEP 并 `load i32` |
| `EnumFieldAt` | 对 payload 区按字段下标 GEP 并 `load` 字段类型（对齐 1） |
| `EnumCopyAt` | 以目标布局字节数调用 `llvm.memmove` |

tag word 与 payload 区都不经过完整 enum 聚合值的 `load`/`store`；按值匹配的快照是一次
`memmove`，控制流合流仍使用原有聚合 `Phi`。

### 链接性

`LlvmLowering.declare` 在声明时按同一 record 分类一次，native 输出目标（`ll`、`bc`、`exe`）共用该分类：

| 分类 | 链接性 |
| --- | --- |
| 普通生成函数、方法、泛型实例、闭包生成函数 | `internal`，保留 `yian.fn.<TypeId>` 名称与原函数类型 |
| 入口 | `__yian_main`，保持 `external`，由运行时 C `main` 调用 |
| `extern "C"` 声明、runtime 函数 | 保留外部符号名与声明，不 internalize |
| trait thunk、vtable、字符串等 global | 保持既有 `internal`/`private` 策略 |

`pub` 是 YIAN 级可见性，不改变原生符号分类；地址被使用、递归或未被调用的普通函数仍为
`internal`，其函数体在真实引用消失后可被 LLVM 删除。trait 方法声明与 `extern "C"` 声明没有
函数体，保持外部链接性；已发射 body 的普通函数不产生不同链接性的重复声明。

## Native yianc 的运行时 profiling 插桩

`yianc/src/codegen/llvm/profile.an` 在启用 `--runtime-profile-dir` 时扩展 LLVM 下降：

1. 按 CFG 中实际生成 body 的 callable 分配本次构建唯一的 `function_id`，从各定义的
   `DefinitionHeader`、接收者类型、具体类型实参和源码路径构造只读描述符；闭包生成函数保留其源位置并标记
   `closure` 来源，extern、头文件声明和 ABI thunk 不进入描述符表。
2. 发射私有描述符表和外部可见的 `__yian_profile_config`；配置含 ABI 版本、报告目录、run id、程序绝对
   路径、指针模式、优化级别、描述符数量和指针，字符串以指针与长度表示。
3. 声明 `void __yian_profile_enter(uint64_t)` 与 `void __yian_profile_leave(uint64_t)`，在函数入口块
   的支配位置调用 enter；正常路径先由 `ScopeExit` 完成逻辑帧失效，再在 `Return` 的 `ret` 前调用
   leave；`Unreachable` 不产生 leave。启用 `--runtime-profile-dir` 时跳过 CFG 内联，保持逻辑函数边界。
4. 对每个插桩函数添加 `noinline`、`nomerge` 和字符串属性 `"disable-tail-calls"="true"`；profiling
   session 通过 `LLVMPassBuilderOptionsSetMergeFunctions(false)` 关闭函数合并，同时保留所选
   `-O`/`--release` 的其余优化。hook 声明没有 `readnone`/`pure` 等允许消除或移动的属性。

`runtime/include/yian_profile.h` 定义上述结构布局与 hook 原型；`runtime/src/profile.c` 只在
`YIAN_RUNTIME_PROFILE` 下提供活动栈、`(parent_node_id, function_id)` 路径聚合、`CLOCK_MONOTONIC`
经过时间、函数汇总与 JSON/文本序列化。`runtime/src/runtime.c` 在同一宏下于 `__yian_main` 正常返回后
调用 finish；panic、runtime fail 与安全终止的 `_exit` 路径不经过 finish。普通构建不编译 collector
实现、不引用插桩符号，也不改变函数的链接性或既有调用 ABI。

## Native yianc 的表示绑定与 guard 消费

LLVM 下降展开 CFG 已经决定的安全计划。

- 激活阶段把 `TypeRepresentation` 绑定到 `BackendTypes`。LLVM 的 `fat()` 只查询绑定表；缺项是内部错误，不回退到按类型重新分类。
- 完整胖指针使用 `{ptr, i64, i32, i32}`，末两项为零扩展读出的字节偏移和字节范围。
  有效地址以 `i8` GEP 计算。切片长度为元素数，字符串长度为字节数，引用保留地址和生命周期字。
- 每个逻辑 scope 在函数入口预留私有 frame word；`ScopeEnter` 在运行时清零该字，第一次实际执行 `Address` 时申请槽与新键，`ScopeExit` 在退出时对该字做 volatile 失效并恢复帧深度。raw 模式没有 frame word，也不发射 fat 动作。
- 隐藏检查由指令的 `OperationGuard` 序列驱动。模板在固定 site 消费 guard；缺失 guard、顺序不一致或未消费完都是内部错误。模板只计算中间值并展开失败分支，不自行删除或添加安全策略。
- `byte-extent` guard 校验构造完整胖指针或由完整胖指针构造视图时的范围位宽。
  fat 分配的 `allocation-size` guard 校验 `count * ABI size(T) <= 0xFFFF_FFB0`，
  堆头首个 u32 保存逻辑负载字节数。
- `Live` 与 `AccessBounds` 分别展开生命周期检查和完整 typed 跨度检查。
  消除后的 `Live` 不再发射检查。proof 仅用于验证。
- `Copy` 在 native fat 模式下检查非空复制的两个生命周期字和两个完整字节跨度。
  两端使用字节地址且 LLVM memcpy 对齐参数为 1。CFG 检查消除保留 `Copy` 义务。
- `SafetyPoint` 的检查与普通指令一样在 preheader 展开一次；其后循环内的 proof 指向该保留检查。
