# 20 FFI 编译与链接

`yianc` 负责 FFI 语义检查，`anx` 把包的 FFI 权限和原生依赖写入 v2/v3 包图。普通 `ffi fn` 使用 YIAN ABI，`extern "C"` 保留未修饰的 C 符号名和 C 调用约定。公开封装与 C 边界的语言规则见[语言参考](../../../docs/grammar/17.ffi.md)。

## 解析与语义检查

- `yianc/src/frontend/` 解析 `ffi fn`、`pub(ffi)`、`extern "C"`、`opaque type`、C 标量、`cptr<T>` 和六个 `@ffi_*` 操作。
- `yianc/src/analysis/` 检查包权限、FFI 声明和封送操作。
- `AnalysisSession` 从包图中取得各包的 `ffi` 值。独立编译使用显式 `--allow-ffi`；包模式按每个文件所属包分别判断，依赖关系不传递权限。原生语言服务器通过自举编译器的编辑器分析入口使用同一包映射与权限规则。

不完整 C 类型只有经 `cptr<T>` 才有运行时表示。编译期求值不执行 `extern "C"` 调用。

## CFG 与 LLVM

CFG 为外部函数保留符号名和 C ABI 属性，普通 FFI 函数按 YIAN 函数生成。LLVM 下降把 C 标量映射到目标机器整数，把 `cptr<T>` 映射成单个原生指针。raw/fat 模式下 C 调用边界的表示相同。封送操作由 `yianc/src/codegen/lowering/` 与 `codegen/llvm/` 下降。

地址提取先执行当前模式可用的 YIAN 来源检查。复制检查 YIAN 一侧的切片范围，C 一侧的地址有效性由绑定承担。FFI 操作不把 C 地址伪装成 YIAN 胖指针，也不开放修改胖指针元数据的通道。

## 包图与原生链接

`anx/src/project/package_map.an` 为每个包写入 `ffi: bool`，有 `[native.llvm]` 时写入 `nativeLLVM`
（`major`、`components`、`sources`），有 `[native.c]` 时写入 `nativeC`（`sources`、`includeDirs`、`archives`）。native compiler 的 `yianc/src/package/` 校验这些值及原生路径；
原生 `anx test` 的
合成包映射也保留依赖包的权限和原生元数据。

`yianc/src/driver/native.an` 收集可达包的 LLVM 与 generic C 输入；generic shim 使用 `-O2 -fPIC -std=c11`，显式归档按依赖闭包顺序放入 linker group。无 LLVM 声明时不查询 `llvm-config`。构建命令使用参数数组；清单不会作为 shell 命令执行。`-t exe` 链接运行时和可达原生输入，`-t ll` 与 `-t bc` 输出 LLVM 产物。独立编译的 `--link-lib` 和 `--link-search` 只在生成可执行文件的链接步骤使用。

`bootstrap/ffi` 提供 C 字节复制辅助函数；`bootstrap/llvm` 使用 LLVM C API 构建结构化 IR。其公开 `Module` 拥有 context、module、builder 和目标机资源，`Builder`、`Function`、`Global` 以及 IR 类型、值和基本块是非拥有视图。 `Module.target_triple()` 与 `Module.data_layout()` 返回复制后的字节，调用者不持有 LLVM 字符串；`llvm.core.llvm_version()` 返回运行库的 `(major, minor, patch)`。`yianc.codegen.session.target_identity()` 复制这三项并核对 Linux x86-64 LP64 目标，不分析源码且不接收编辑器状态。调用者显式关闭 `Module` 一次，并停止使用其副本和子视图；外部句柄没有自动生命周期检查。LLVM 返回的消息和缓冲区先复制到 YIAN 存储，再按 LLVM API 释放。

## 验证边界

LLVM 操作的 `OperationObserver` 同步接收按操作种类配对的开始和结束事件，结束事件携带成功状态。观察者不持有 LLVM 资源。

`tests/package/ffi_*` 覆盖权限、签名、标量/输出参数、封送、包间导入及 LLVM IR、bitcode、object 生成；项目测试在 raw/fat 模式运行。测试通过不能证明手写 C 声明与头文件一致，也不能证明外部地址的范围或资源释放正确。FFI 绑定本身属于可信代码边界。
