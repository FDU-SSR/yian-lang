# 14 CLI 与构建

`yianc/src/config.an` 解析命令行，`yianc/src/main.an` 调度前端、中端和后端。完整命令和选项见[编译器命令行指南](../compile_script.md)。

## 编译输入

独立模式接收位置参数指定的文件或目录。包模式通过 `--packages PATH` 加载由 `anx` 产生的 v2/v3 包图，确定源码归属、入口、依赖可见性和原生链接输入。

## 编译流程

`FrontendDriver.new` 读入包图和源码，`run` 执行词法分析、语法分析和脱糖。完成的会话进入 `MiddleEndDriver`。`--check` 执行语义检查，默认编译还使用 `BackendDriver` 生成 `exe`、`ll` 或 `bc`。

## 诊断与退出状态

参数解析失败时 `main` 先写出用法文本，再通过统一 renderer 输出 `E601`：未知选项或参数用法错误以状态 2 结束，配置组合校验失败以状态 1 结束。帮助请求写 stdout 并以 0 结束；日志配置失败以 `E602` 报告。

输入、前端、中端、后端和外部工具的用户错误都渲染到 stderr，退出状态为 1。native 工具失败先写出 `E604` 标题，再按原字节转发工具 stderr。可恢复诊断由 `DiagnosticReporter` 同步报告：`--check` 在检查过程中逐条写出，普通编译在严格分析成功后按发现顺序写出 warning 和提示，然后继续后端。只有 warning 时退出 0。

## 输出与链接

`--dump` 输出已完成阶段的中间产物，`--profile --profile-output PATH` 输出 JSON 与文本计时报告；报告写出失败作为 `W601` 非致命警告输出，编译失败时不发布报告。`exe` 构建由 `yianc/src/driver/native.an` 组织运行时、C shim、包声明的原生依赖和最终链接。`ll` 与 `bc` 输出由 LLVM 后端序列化。
