# 14 CLI 与构建

`yianc/src/config.an` 解析命令行，`yianc/src/preprocess.an` 准备输入，`yianc/src/main.an` 调度前端、中端和后端。完整命令和选项见[编译器命令行指南](../compile_script.md)。

## 编译输入

独立模式接收位置参数指定的文件或目录。包模式通过 `--packages PATH` 加载由 `anx` 产生的 v2/v3 包图，确定源码归属、入口、依赖可见性和原生链接输入。

## 编译流程

`preprocess.an` 读取包图、确定源码根、建立信任规则并收集源码为 `SourceTable`；`FrontendDriver.new` 只用该文件表构造准备期；`FrontendDriver.run` 执行词法分析、语法分析和脱糖并返回 `UnitTable`。CLI 随后分配 `AnalysisSession`，并由 `TargetLayout.new` 用会话类型库建立目标布局。`MiddleEndDriver.new` 接收会话、借用 `AnalysisOptions` 和 reporter，在 `semantic_analysis` 开始时通过 `AnalysisSession.classify_sources` 判定每个文件的权限。成功结果以 `MiddleEndResult` 交付会话和输出。`--check` 执行语义检查且不构造后端；默认编译在中端成功后构造 `BackendDriver` 生成 `exe`、`ll` 或 `bc`。

## 诊断与退出状态

参数解析失败时 `parse_args` 先写出用法文本，再通过统一 renderer 输出 `E601` 并以进程状态退出，不向 `main` 返回错误值：未知选项或参数用法错误以状态 2 结束，配置组合校验失败以状态 1 结束。帮助请求由 `parse_args` 写 stdout 并以 0 结束；日志配置失败由 `CompilerTrace.new` 以 `E602` 报告并以状态 1 退出。

输入、前端、中端、后端和外部工具的用户错误都立即终止当前阶段并渲染到 stderr，退出状态为 1。native 工具失败先写出 `E604` 标题，再按原字节转发工具 stderr。warning 由 `DiagnosticReporter` 在发现时同步写出，不中断后续阶段；只有 warning 时退出 0。`--check` 与普通编译的区别仅是不构造后端和产物。

## 输出与链接

`--dump` 输出已完成阶段的中间产物，`--profile --profile-output PATH` 输出 JSON 与文本计时报告；报告写出失败作为 `W601` 非致命警告输出，编译失败时不发布报告。`exe` 构建由 `yianc/src/codegen/native.an` 组织运行时、C shim、包声明的原生依赖和最终链接。`ll` 与 `bc` 输出由 LLVM 后端序列化。
