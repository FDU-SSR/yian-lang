# 19 分析接口

`yianc` 在前端处理完成后把 `FrontendSession` 交给 `MiddleEndDriver`，由 `AnalysisSession` 持有文件表、单元、`SourceTrust`、`Option<PackageMap>`、`allow_ffi`、源码权限表、符号、类型和 HIR。`MiddleEndDriver.run` 在 `semantic_analysis` 开始时、`analysis.restricted` 前执行 `analysis.classify_sources`。分析会话按准备、分析中和完成或失败的顺序转换，同一会话重复开始分析直接 panic。会话内 ID 的有效范围是该会话；诊断需要跨会话保留时，调用者在会话有效期内复制消息、路径和范围。

`AnalysisOptions` 控制入口检查、恢复模式、HIR 验证和目标布局查询。`MiddleEndDriver.run(options, reporter)` 在本次同步分析期间借用 `DiagnosticReporter`，在每个语义阶段发现 warning 或可恢复错误时立即报告。`Ok(Some(output))` 表示分析成功，`Ok(None)` 表示恢复检查结束且已有错误被报告，`Err(error)` 表示致命失败。调用方接管成功结果；`AnalysisOutput` 引用会话记录，须先于会话释放。

`analysis/driver.an::MiddleEndDriver.run_cli(options, sources)` 提供 CLI 报告器：`--check` 在回调内逐条写 stderr；普通编译把渲染文本按接收顺序暂存，严格分析成功后一次写出，失败时释放暂存文本。`lsp/src/analysis/compiler.an::analyze` 提供 LSP 报告器：成功时把警告交给 `CompilerAnalysis`，失败时先释放已收集警告，再借同一张源码表转换致命错误。

## 命令行与编辑器

`yianc --check` 从磁盘输入运行前端和语义检查，输出文本诊断。LSP 使用 `lsp/src/analysis/compiler.an` 把编辑器文档构造成 `SourceFile` 后通过 `SourceTable.from_files` 一次性装入文件表，交给 `FrontendDriver.new`；随后把 trust/packages/allow_ffi 交给 `MiddleEndDriver`，由 `AnalysisSession` 分类权限并运行严格语义分析。

LSP 接收 UTF-16 代码单元列坐标，使用标准库的 `LineIndex` 转换至编译器源码坐标。诊断在会话释放前转换为 `LspDiagnostic`，由快照持有消息、路径和范围；发布时从同版本快照文本计算 UTF-16 范围，严重级别由诊断码推导。文档覆盖层、调度、协议和快照范围见[语言服务器](../../../docs/manual/27.language_server.md)。包模式的源码归属与可见性见[依赖图与包图](../../../docs/manual/23.anx_graph.md)。
