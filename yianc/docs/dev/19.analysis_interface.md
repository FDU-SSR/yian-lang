# 19 分析接口

`yianc` 在前端处理完成后由编排者分配 `dyn AnalysisSession`，会话持有单元表（每单元含源文件、token 与脱糖 AST）、`SourceTrust`、`Option<PackageMap>`、源码权限表、符号、类型和 HIR。编排者再用 `TargetLayout.new(&session.types, ...)` 建立目标布局，并把布局类型库提供给 `AnalysisOptions.sizes`。`MiddleEndDriver.new(session, options, reporter)` 取得会话指针的唯一释放责任；`run()` 不带参数，在 `semantic_analysis` 开始时、`analysis.restricted` 前执行 `analysis.classify_sources`。分析会话按准备、分析中和完成或失败的顺序转换，驱动和会话各拒绝第二次运行，重复调用直接 panic。会话内 ID 的有效范围是该会话；诊断需要跨会话保留时，调用者在会话有效期内复制消息、路径和范围。

`AnalysisOptions` 控制入口检查、HIR 验证和目标布局查询，由驱动在构造时借用。`MiddleEndDriver.run()` 在本次同步分析期间借用 `DiagnosticReporter`，warning 在被发现时立即报告；任何用户错误都会立即终止后续 pass 并返回 `Err(error)`。`Ok(result)` 表示分析成功，`MiddleEndResult` 独占会话分配和 `AnalysisOutput`；驱动不再产生表示“恢复检查结束”的空成功值。成功结果须在布局之后释放，结果自身先释放输出、再释放会话；`AnalysisOutput` 引用会话记录，不能晚于会话释放。

`yianc/src/main.an` 的 CLI 报告器在回调内立即渲染并写 stderr，不区分 `--check` 与普通编译。`lsp/src/analysis/compiler.an::analyze` 独立持有 LSP 报告器：分析成功时把警告交给 `CompilerAnalysis`，失败时先释放已收集警告，再借同一张源码表转换错误。

## 命令行与编辑器

`yianc --check` 从磁盘输入运行前端和语义检查，输出文本诊断；检查使用 `TargetLayout` 按真实 LLVM 布局求编译期 `sizeof`，但不构造 `BackendDriver`、CFG 或发布路径。LSP 使用 `lsp/src/analysis/compiler.an` 把编辑器文档构造成 `SourceFile` 后通过 `SourceTable.from_files` 一次性装入文件表，交给 `FrontendDriver.new`；`run()` 返回 `UnitTable` 后分配 `AnalysisSession` 并用 `TargetLayout` 提供尺寸，再运行严格语义分析。成功时先释放布局，再把会话内容和输出交给 `CompilerAnalysis`；失败时在会话释放前转换诊断。

LSP 接收 UTF-16 代码单元列坐标，使用标准库的 `LineIndex` 转换至编译器源码坐标。诊断在会话释放前转换为 `LspDiagnostic`，由快照持有消息、路径和范围；发布时从同版本快照文本计算 UTF-16 范围，严重级别由诊断码推导。文档覆盖层、调度、协议和快照范围见[语言服务器](../../../docs/manual/27.language_server.md)。包模式的源码归属与可见性见[依赖图与包图](../../../docs/manual/23.anx_graph.md)。
