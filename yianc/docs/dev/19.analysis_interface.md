# 19 分析接口

CLI 的 `main` 和 LSP 分析入口在收集源码前分别创建本次编译的 `NameInterner`；前端和语义分析共用它。前端完成后，入口准备 `UnitTable`、包图、`TypeSpace` 和 `SymbolSpace`；`MiddleEndDriver` 创建 HIR 表。`TargetLayout.new(types, ...)` 和 `MiddleEndDriver` 使用同一张类型表，布局类型库通过 `AnalysisOptions.sizes` 提供给语义检查。`MiddleEndDriver.new(units, packages, names, types, symbols, trust, raw_pointers, options, reporter)` 接收共享表和报告器，创建 HIR 表，并准备 `SourceTrust`、源码权限表及定义、worklist、impl 注册表。`run()` 先分类源权限并在 `analysis.restricted` 前执行 `analysis.classify_sources`；编译内 ID 引用本次分析的类型、符号、HIR 和单元记录。

`AnalysisOptions` 控制入口检查、HIR 验证和目标布局查询，由驱动在构造时按值保存。选项包含布局尺寸服务和跟踪器。`MiddleEndDriver.run()` 通过 `DiagnosticReporter` 同步报告 warning；任何用户错误都会立即终止后续 pass 并返回 `Err(error)`。`Ok(output)` 表示分析成功并返回 `AnalysisOutput`；输出包含 checked/procedure 列表和 HIR 表；其中的 `DefId`、`TypeId`、`SymbolId`、`HirId` 和 `UnitId` 引用本次分析的对应记录。CLI 由进程退出回收入口资源。显式清理时，调用方清理后端、输出及符号/类型表。失败时中端清理未完成输出并报告错误。

`yianc/src/main.an` 的 CLI 报告器在回调内立即渲染并写 stderr，不区分 `--check` 与普通编译。`lsp/src/analysis/compiler.an::analyze` 使用独立的 LSP 报告器：分析成功时把警告交给 `CompilerAnalysis`，分析失败时使用单元表复制错误诊断，并清理已收集的警告。

## 命令行与编辑器

`yianc --check` 从磁盘输入运行前端和语义检查，输出文本诊断；检查使用 `TargetLayout` 按真实 LLVM 布局求编译期 `sizeof`，但不构造 `BackendDriver`、CFG 或发布路径。LSP 使用 `lsp/src/analysis/compiler.an` 用同一驻留表把编辑器文档构造成 `SourceFile` 后通过 `SourceTable.from_files` 一次性装入文件表，交给 `FrontendDriver.new`；`run()` 返回 `UnitTable` 后准备 `TypeSpace`、符号表和 `TargetLayout`，由 `MiddleEndDriver` 创建 HIR，再运行严格语义分析。成功时复制按 `UnitId` 排列的 stdlib 标志并清理驱动和布局，然后由 `CompilerAnalysis` 保存单元表、包图、共享语义表、输出、分类位与类型空间；清理输出（包含 HIR）及其引用的表，并清理类型表。失败时复制诊断，并清理已创建的驱动、布局和共享表。

LSP 接收 UTF-16 代码单元列坐标，使用标准库的 `LineIndex` 转换至编译器源码坐标。诊断转换为 `LspDiagnostic`，由快照保存消息、路径和范围；发布时从同版本快照文本计算 UTF-16 范围，严重级别由诊断码推导。`SourceIndex.build(units: UnitTable&, packages: Option<PackageMap&>, names: NameInterner&, stdlib: Vec<bool>&, std_root: str)` 按 `UnitId` 顺序读取源码和分类位；源码索引重新词法分析和解析时使用驻留表。语义索引和查询快照从编译记录提取数据，查询快照保存后续查询所需的数据。文档覆盖层、调度、协议和快照范围见[语言服务器](../../../docs/manual/27.language_server.md)。包模式的源码归属与可见性见[依赖图与包图](../../../docs/manual/23.anx_graph.md)。
