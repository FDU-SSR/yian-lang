# 01 编译管线概览

`yianc/src/main.an` 按顺序驱动 `FrontendDriver`、`MiddleEndDriver` 和 `BackendDriver`。三者分别持有前端会话、分析会话及其结果、代码生成所需的后端状态。

| 阶段 | 主要工作 | 实现 |
| --- | --- | --- |
| 输入 | 读取包图、确定源码根、建立信任规则、收集并加载源码 | `frontend/driver.an::FrontendDriver.new` |
| 前端 | 分词、判定源码权限、构造 AST、脱糖 | `frontend/driver.an::FrontendDriver.run` |
| 中端 | 解析名字和类型、实例化与检查过程、生成 HIR、验证和确定赋值检查 | `analysis/driver.an::MiddleEndDriver` |
| 后端 | HIR 下降为 CFG、构造安全计划、生成 LLVM IR、输出目标产物 | `codegen/driver.an::BackendDriver` |

`FrontendDriver.take_session()` 把已完成的会话交给中端。中端的分析结果保存已检查过程与供代码生成使用的过程集合。后端在分析前提供目标类型布局，供需要即时计算的 `sizeof` 使用。

致命用户错误以值返回 `main`；可恢复诊断和 warning 通过同步的 `DiagnosticReporter` 报告，由 CLI 渲染或由 LSP 复制为自己的记录。编译器内部不变量违反在发现处直接 panic。输入读取与校验成功后文件表冻结，前端、中端、后端和 LSP 会话索引用同一 `UnitId` 查询会话内文件。

`--check` 运行至中端检查，默认编译继续生成产物。启用 `--dump` 时，已完成的阶段可以写出 `build/tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`。命令与输出选项见[编译器命令行指南](../compile_script.md)。
