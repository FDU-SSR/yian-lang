# 01 编译管线概览

`yianc/src/main.an` 先通过 `preprocess.an` 加载包图、解析源码根、建立信任规则并把源码收集为 `SourceTable`，`FrontendDriver` 接收该表并在 `run()` 结束时产出按 `UnitId` 索引的 `UnitTable`，然后按顺序驱动 `FrontendDriver`、`MiddleEndDriver` 和 `BackendDriver`。权限分类在中端 `AnalysisSession` 中完成。

| 阶段 | 主要工作 | 实现 |
| --- | --- | --- |
| 输入 | 读取包图、确定源码根、建立信任规则、收集并加载源码 | `preprocess.an::{load_packages,build_trust,collect_sources}` |
| 前端 | 分词、构造 AST、脱糖 | `frontend/driver.an::FrontendDriver.run` |
| 中端 | 分类源码权限、解析名字和类型、实例化与检查过程、生成 HIR、验证和确定赋值检查 | `analysis/driver.an::MiddleEndDriver`、`analysis/session/session.an::AnalysisSession.classify_sources` |
| 后端 | HIR 下降为 CFG、构造安全计划、生成 LLVM IR、输出目标产物 | `codegen/driver.an::BackendDriver` |

`FrontendDriver.run()` 直接返回已完成的 `UnitTable` 交给中端，main 同时把 `SourceTrust`、`Option<PackageMap>` 和 `allow_ffi` 交给 `MiddleEndDriver`。`AnalysisSession` 在 `semantic_analysis` 开始时执行 `analysis.classify_sources`，之后的权限查询都经由该会话。

阶段致命用户错误以值返回 `main`，命令行参数、日志配置和输入预处理错误分别由 `parse_args`、`CompilerTrace.new` 和 `preprocess.an` 输出并直接退出；可恢复诊断和 warning 通过同步的 `DiagnosticReporter` 报告，由 CLI 渲染或由 LSP 复制为自己的记录。编译器内部不变量违反在发现处直接 panic。输入读取与校验成功后文件表冻结；前端成功时把全部源文件与各单元 token/AST 移入 `UnitTable`，此后中端、后端和 LSP 用同一 `UnitId` 查询该表。

`--check` 运行至中端检查，默认编译继续生成产物。启用 `--dump` 时，已完成的阶段可以写出 `build/tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`。命令与输出选项见[编译器命令行指南](../compile_script.md)。
