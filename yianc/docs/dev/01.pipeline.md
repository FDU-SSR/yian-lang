# 01 编译管线概览

`yianc/src/main.an` 先通过 `preprocess.an` 加载包图、解析源码根、建立信任规则并把源码收集为 `SourceTable`，`FrontendDriver` 接收该表并在 `run()` 结束时产出按 `UnitId` 索引的 `UnitTable`。CLI 或 LSP 持有完成的单元表、包图、名称表、符号表和 HIR 表，创建一张 `TypeStore` 并用同一张表初始化 `TargetLayout`；`MiddleEndDriver` 借用这些共享对象并取得信任规则的所有权。权限分类在中端驱动中完成。

| 阶段 | 主要工作 | 实现 |
| --- | --- | --- |
| 输入 | 读取包图、确定源码根、建立信任规则、收集并加载源码 | `preprocess.an::{load_packages,build_trust,collect_sources}` |
| 前端 | 分词、构造 AST、脱糖 | `frontend/driver.an::FrontendDriver.run` |
| 中端 | 分类源码权限、解析名字和类型、实例化与检查过程、生成 HIR、验证和确定赋值检查 | `analysis/driver.an::MiddleEndDriver.classify_sources/run` |
| 后端 | HIR 下降为 CFG、构造安全计划、生成 LLVM IR、输出目标产物 | `codegen/driver.an::BackendDriver`；目标布局由 `codegen/session.an::TargetLayout` 提供 |

`FrontendDriver.run()` 返回已完成的 `UnitTable`；编排者创建 `TypeStore`、名称/符号/HIR 表和 `TargetLayout`，然后用这些对象与包图构造 `MiddleEndDriver`。驱动借用共享表，拥有 `SourceTrust`、源码权限及定义、工作列表和 impl 注册表，按值保存 `AnalysisOptions` 并借用 `DiagnosticReporter`。`run()` 先标记单次运行，再分类源码并执行 restricted 检查；成功返回 `AnalysisOutput`，错误时由调用者继续持有共享表并报告诊断。只有编译动作在中端成功后构造 `BackendDriver`，它校验输出与布局引用同一张类型表。CLI 的共享表与目标布局存活到进程退出。显式清理时，输出和后端先于其引用的共享表释放，布局先于类型表释放。

用户错误以值返回 `main`，命令行参数、日志配置和输入预处理错误分别由 `parse_args`、`CompilerTrace.new` 和 `preprocess.an` 输出并直接退出；第一个用户错误立即终止中端分析。warning 通过同步的 `DiagnosticReporter` 立即报告，由 CLI 渲染或由 LSP 复制为自己的记录。编译器内部不变量违反在发现处直接 panic。输入读取与校验成功后文件表冻结；前端成功时把全部源文件与各单元 token/AST 移入 `UnitTable`，此后中端、后端和 LSP 用同一 `UnitId` 查询该表。

`--check` 运行至中端检查，默认编译继续生成产物。启用 `--dump` 时，已完成的阶段可以写出 `build/tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`。命令与输出选项见[编译器命令行指南](../compile_script.md)。
