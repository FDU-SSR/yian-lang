# 01 编译管线概览

`yianc/src/main.an` 先通过 `preprocess.an` 加载包图、解析源码根、建立信任规则并把源码收集为 `SourceTable`，`FrontendDriver` 接收该表并在 `run()` 结束时产出按 `UnitId` 索引的 `UnitTable`。CLI 或 LSP 准备单元表、包图、名称表、符号表和 `TypeSpace`，`TargetLayout` 使用同一张类型表；`MiddleEndDriver` 使用这些输入并创建 HIR 表。权限分类在中端驱动中完成。

| 阶段 | 主要工作 | 实现 |
| --- | --- | --- |
| 输入 | 读取包图、确定源码根、建立信任规则、收集并加载源码 | `preprocess.an::{load_packages,build_trust,collect_sources}` |
| 前端 | 分词、构造 AST、脱糖 | `frontend/driver.an::FrontendDriver.run` |
| 中端 | 分类源码权限、解析名字和类型、实例化与检查过程、生成 HIR、验证和确定赋值检查 | `analysis/driver.an::MiddleEndDriver.classify_sources/run` |
| 后端 | HIR 下降为 CFG、构造安全计划、生成 LLVM IR、输出目标产物 | `codegen/driver.an::BackendDriver`；目标布局由 `codegen/session.an::TargetLayout` 提供 |

`FrontendDriver.run()` 返回已完成的 `UnitTable`；编排者准备 `TypeSpace`、名称/符号表和 `TargetLayout`，然后用这些对象与包图构造 `MiddleEndDriver`。驱动负责分类源码权限、执行 restricted 检查和安排分析 pass，按值保存 `AnalysisOptions`，并通过 `DiagnosticReporter` 报告 warning。成功时 `run()` 返回包含 HIR 的 `AnalysisOutput`，错误时报告诊断。只有编译动作在中端成功后构造 `BackendDriver`，它使用分析所用的类型表并检查输出、布局和配置的 raw 模式一致；`--check` 在中端后停止。

用户错误以值返回 `main`，命令行参数、日志配置和输入预处理错误分别由 `parse_args`、`CompilerTrace.new` 和 `preprocess.an` 输出并直接退出；第一个用户错误立即终止中端分析。warning 通过同步的 `DiagnosticReporter` 立即报告，由 CLI 渲染或由 LSP 复制为自己的记录。编译器内部不变量违反在发现处直接 panic。输入读取与校验成功后建立文件表；前端完成后由 `UnitTable` 提供源文件、token 和脱糖 AST，中端、后端和 LSP 用 `UnitId` 查询该表。

`--check` 运行至中端检查，默认编译继续生成产物。启用 `--dump` 时，已完成的阶段可以写出 `build/tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`。命令与输出选项见[编译器命令行指南](../compile_script.md)。
