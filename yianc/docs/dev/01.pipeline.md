# 01 编译管线概览

`yianc/src/main.an` 先通过 `preprocess.an` 加载包图、解析源码根、建立信任规则并把源码收集为 `SourceTable`，`FrontendDriver` 接收该表并在 `run()` 结束时产出按 `UnitId` 索引的 `UnitTable`。CLI 或 LSP 为完成的单元表创建一张 `TypeStore`，分配借用该表的 `AnalysisSession`，再用同一张表初始化 `TargetLayout`，最后把会话指针交给 `MiddleEndDriver`。权限分类在中端 `AnalysisSession` 中完成。

| 阶段 | 主要工作 | 实现 |
| --- | --- | --- |
| 输入 | 读取包图、确定源码根、建立信任规则、收集并加载源码 | `preprocess.an::{load_packages,build_trust,collect_sources}` |
| 前端 | 分词、构造 AST、脱糖 | `frontend/driver.an::FrontendDriver.run` |
| 中端 | 分类源码权限、解析名字和类型、实例化与检查过程、生成 HIR、验证和确定赋值检查 | `analysis/driver.an::MiddleEndDriver`、`analysis/session/session.an::AnalysisSession.classify_sources` |
| 后端 | HIR 下降为 CFG、构造安全计划、生成 LLVM IR、输出目标产物 | `codegen/driver.an::BackendDriver`；目标布局由 `codegen/session.an::TargetLayout` 提供 |

`FrontendDriver.run()` 返回已完成的 `UnitTable`；编排者创建一张 `TypeStore`，为单元表分配借用它的 `AnalysisSession`，再由 `TargetLayout.new` 借用同一张表建立目标布局。`MiddleEndDriver.new` 接收会话的唯一释放责任并借用 `AnalysisOptions` 与 `DiagnosticReporter`；`run()` 在 `semantic_analysis` 开始时执行 `analysis.classify_sources`，成功时以 `MiddleEndResult` 移交所拥有的会话和输出，失败或恢复检查结束时仍由驱动持有会话。只有编译动作在中端成功后构造 `BackendDriver`，它校验布局与会话引用同一张表。成功路径中布局和会话都释放后，入口释放类型表；失败路径报告诊断后直接退出。

用户错误以值返回 `main`，命令行参数、日志配置和输入预处理错误分别由 `parse_args`、`CompilerTrace.new` 和 `preprocess.an` 输出并直接退出；第一个用户错误立即终止中端分析。warning 通过同步的 `DiagnosticReporter` 立即报告，由 CLI 渲染或由 LSP 复制为自己的记录。编译器内部不变量违反在发现处直接 panic。输入读取与校验成功后文件表冻结；前端成功时把全部源文件与各单元 token/AST 移入 `UnitTable`，此后中端、后端和 LSP 用同一 `UnitId` 查询该表。

`--check` 运行至中端检查，默认编译继续生成产物。启用 `--dump` 时，已完成的阶段可以写出 `build/tokens.txt`、`ast.txt`、`hir.txt`、`cfg.txt` 和 `ir.ll`。命令与输出选项见[编译器命令行指南](../compile_script.md)。
