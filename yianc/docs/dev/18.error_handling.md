# 18 错误处理

## 用户诊断模型

`yianc/src/diagnostics/model.an` 定义 `UserDiagnostic`、`DiagnosticReporter`、`DiagnosticCode`、`Severity` 和 `DiagnosticLocation`。每条诊断提供消息、一个决定等级的稳定诊断码，以及 `Global`、`File` 或 `Source` 之一的位置。`DiagnosticCode.text()` 给出编号，`severity()` 按编号首字母推导等级：`E` 为错误、`W` 为警告、`N` 为提示。同类别错误共享编号，具体原因由消息说明。

各阶段定义自己的错误类型并直接实现 `UserDiagnostic`。输入读取、源码根、包图与资源定位使用顶层 `input_error.an::InputError`；词法、语法和脱糖使用 `LexDiagnostic`、`ParseDiagnostic`、`DesugarDiagnostic` 及按变体委托的 `FrontendStageError`；中端使用 `AnalysisError`；后端、产物和外部工具使用 `CodegenError`、`OutputError`、`BackendCompileError`；命令行、日志和 profile 使用 `CliError`、`LogConfigError`、`ProfileWarning`。错误联合按变体转发消息、位置和诊断码。

`diagnostics/render.an::render(diagnostic: UserDiagnostic&, sources: SourceMap&) -> String` 从诊断码取得等级并生成标题。`Global` 只有标题；`File` 追加 `--> path`；`Source` 通过 `SourceMap.file(value.unit)` 取得路径和源码，追加 `--> path:line:column` 以及源码行、缩进和 caret。返回的文本由调用方释放。

## 传播与输出

阶段用户错误通过 `Result` 和 `?` 逐层返回，最终由 `main` 渲染并以进程状态退出；中端收到第一个错误后立即停止后续 pass。命令行参数解析失败不返回错误值：`config.an::parse_args` 直接写出用法和 `E601` 诊断，并以进程状态退出；日志配置失败也由 `telemetry/trace.an::CompilerTrace.new` 报告 `E602` 并以状态 1 退出；输入预处理失败由 `preprocess.an` 标记 `preprocessing` 失败、用空表渲染 `InputError` 并以状态 1 退出；前端失败由 `main` 标记 `frontend` 失败后渲染前端诊断。warning 由产生点通过调用者提供的 `DiagnosticReporter&` 同步报告并立即输出；回调只在本次调用内读取阶段值，调用者随后释放它。CLI 在回调中渲染，LSP 在回调中把消息、路径和范围复制进自己的记录。

`--check` 和普通编译都按相同的中端顺序检查，第一个用户错误终止分析并由 `main` 渲染；warning 在发现时立即写出，然后继续当前可继续的阶段。`--check` 只跳过后端和产物发布。输入预处理失败时由预处理模块自行用空 `SourceTable` 渲染全局或文件级诊断；`main` 处理阶段终止性错误，并决定退出状态和是否发布 profile 报告。

编译器内部不变量违反（无效的编译内 ID、损坏的中间表示、对已绑定表示的非法修改）在发现处直接 `@panic`，不经过 `Result` 向上传递，也不伪装成用户错误。用户错误、常量探测结果和外部 LLVM 环境失败按各自类型返回；运行时安全错误与 C ABI 不属于用户诊断通路。

## 源码身份

`frontend/source.an::SourceTable` 与 `frontend/unit.an::UnitTable` 都实现 `SourceMap`。`SourceTable` 保存输入文本和规范路径；一次编译内每个规范路径对应一个 `UnitId`；磁盘和内存输入共用同一 ID 空间。前端完成后，`UnitTable` 按 `UnitId` 提供源文件、token 与脱糖 AST。诊断、dump 和默认输出命名使用规范路径。`SourceMap.file(unit)` 返回对应源码；缺失的 ID 属于内部错误并直接 panic。

`preprocess.an` 构造文件表，`FrontendDriver.new` 用该表构造准备期；前端失败时 `FrontendDriver.source_table()` 提供渲染诊断所需的源码表，CLI 报告后退出，LSP 在错误路径清理准备期。前端完成后，`UnitTable` 提供各单元 token/AST。`MiddleEndDriver.new` 接收单元表、包图、名称/符号/类型表，创建 HIR 表，并根据 `SourceTrust` 建立本次分析的权限表；权限分类不是用户错误路径。中端失败时报告诊断，成功时 `run()` 返回包含 HIR 的 `AnalysisOutput`。中端、后端、dump 和 LSP 索引使用相应表。显式释放分析资源时清理输出（含 HIR）、符号和类型表。跨编译保留的诊断由 LSP 复制路径、范围和消息，不保存编译内 ID。
