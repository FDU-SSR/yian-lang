# 18 错误处理

## 用户诊断模型

`yianc/src/diagnostics/model.an` 定义 `UserDiagnostic`、`DiagnosticReporter`、`DiagnosticCode`、`Severity` 和 `DiagnosticLocation`。每条诊断提供消息、一个决定等级的稳定诊断码，以及 `Global`、`File` 或 `Source` 之一的位置。`DiagnosticCode.text()` 给出编号，`severity()` 按编号首字母推导等级：`E` 为错误、`W` 为警告、`N` 为提示。同类别错误共享编号，具体原因由消息说明。

各阶段定义自己的错误类型并直接实现 `UserDiagnostic`。输入读取、源码根、包图与资源定位使用顶层 `input_error.an::InputError`；词法、语法和脱糖使用 `LexDiagnostic`、`ParseDiagnostic`、`DesugarDiagnostic` 及按变体委托的 `FrontendStageError`；中端使用 `AnalysisError`；后端、产物和外部工具使用 `CodegenError`、`OutputError`、`BackendCompileError`；命令行、日志和 profile 使用 `CliError`、`LogConfigError`、`ProfileWarning`。错误联合按变体转发消息、位置和诊断码。

`diagnostics/render.an::render(diagnostic: UserDiagnostic&, sources: SourceMap&) -> String` 从诊断码取得等级并生成标题。`Global` 只有标题；`File` 追加 `--> path`；`Source` 通过 `SourceMap.file(value.unit)` 取得路径和源码，追加 `--> path:line:column` 以及源码行、缩进和 caret。返回的文本由调用方释放。

## 传播与恢复

阶段致命用户错误通过 `Result` 和 `?` 逐层返回，最终由 `main` 渲染并以进程状态退出。命令行参数解析失败不返回错误值：`config.an::parse_args` 直接写出用法和 `E601` 诊断，并以进程状态退出；日志配置失败也由 `telemetry/trace.an::CompilerTrace.new` 报告 `E602` 并以状态 1 退出；输入预处理失败由 `preprocess.an` 标记 `source_preparation` 失败、用空表渲染 `InputError` 并以状态 1 退出。可恢复的语义错误与 warning 由产生点借用调用者提供的 `DiagnosticReporter&` 同步报告；回调只在本次调用内借用阶段值，调用者随后释放它。CLI 在回调中渲染，LSP 在回调中把消息、路径和范围复制进自己持有的记录。

`--check` 在检查过程中逐条写出可恢复诊断；普通编译只在严格分析成功后按发现顺序写出 warning 和提示，然后继续后端。输入预处理失败时由预处理模块自行用空 `SourceTable` 渲染全局或文件级诊断；`main` 处理其余阶段终止性错误，并决定是否继续、退出状态和是否发布 profile 报告。

编译器内部不变量违反（重复开始同一会话的分析、无效的会话内 ID、损坏的中间表示、对已绑定表示的非法修改）在发现处直接 `@panic`，不经过 `Result` 向上传递，也不伪装成用户错误。用户错误、常量探测结果和外部 LLVM 环境失败按各自类型返回；运行时安全错误与 C ABI 不属于用户诊断通路。

## 源码身份

`frontend/source.an::SourceTable` 实现 `SourceMap`。它只保存文本和规范路径，并在全部输入读取与校验成功后冻结，之后不再追加文件；同一编译会话内每个规范路径对应一个 `UnitId`；磁盘和内存输入共用同一 ID 空间。诊断、dump 和默认输出命名使用规范路径。`SourceMap.file(unit)` 返回借用，调用方只能传入所属会话中的有效 `UnitId`，缺失的 ID 属于内部错误并直接 panic。

`preprocess.an` 构造文件表，`FrontendDriver.new` 构造前端会话后由其接管传入的文件表；前端失败时调用方通过 `FrontendDriver.source_table()` 借用同一张表渲染，错误处理完成后释放会话。`MiddleEndDriver.new` 接收 trust/packages/allow_ffi，`AnalysisSession` 持有权限表；权限分类不是用户错误路径。中端、后端、dump 和 LSP 会话索引继续借用冻结的表。跨编译会话保留的诊断由 LSP 复制路径、范围和消息，不保存会话内 ID。
