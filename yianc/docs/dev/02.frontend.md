# 02 前端

## 源码与单元表

`preprocess.an::collect_sources(config, trace)` 收集命令行输入并把每个规范路径读入 `SourceTable`；同一规范路径只分配一个 `UnitId`。`SourceFile` 只保存 `text` 和规范化的 `path`；诊断、dump 和默认输出命名使用该路径。`FrontendDriver.new(sources, dump, trace)` 只接收源码表并构造准备期对象 `FrontendPreparation`（`SourceTable` + 每单元 `PreparedFile`），不持有包图、源码根或信任策略。`FrontendDriver.run()` 按全词法、全语法、全脱糖的顺序处理输入，不再判定权限；成功后 `FrontendPreparation.finish()` 把 `SourceTable` 持有的全部 `SourceFile` 与各单元 token、脱糖 AST 移入 `UnitTable` 并返回。`UnitTable` 以 `UnitId` 索引 `UnitData` 并实现 `SourceMap`；失败时准备期仍持有全部源码，供 `source_table()` 渲染。LSP 和测试自行构造 `SourceFile`，通过 `SourceTable.from_files` 一次性装入，随后调用同一个 `run()`。

`FrontendDriver.new` 保存调用者提供的 `CompilerTrace` 非拥有引用，调用者须保证它在 driver 使用期间有效。`main` 先完成预处理，再把共享 trace 与文件表交给 `new`；LSP 使用禁用的实例。前端转储由 `--dump` 独立控制。源码权限由 `MiddleEndDriver` 持有，并在语义分析开始时按 `UnitId` 分类。

## Lexer

`yianc/src/frontend/lex/lexer.an` 的 `Lexer` 生成带源码范围的 token。token 的种类和载荷定义位于 `frontend/lex/token.an`。词法错误由 `LexError` 返回。

## Parser

`frontend/parse/state.an` 的 `Parser` 管理 token 消费、诊断及 AST 分配，`frontend/parse/items.an::parse_program` 解析顶层声明。表达式、类型和模式的解析分别位于 `frontend/parse/expr.an`、`type.an` 和 `pattern.an`。

## 阶段错误

`frontend/prepare.an` 把低层消息和 span 包装成具体阶段诊断：`LexDiagnostic`、`ParseDiagnostic` 和 `DesugarDiagnostic` 各持有诊断码、`SourceSpan` 与正文，`FrontendStageError` 按变体委托 `UserDiagnostic` 与释放。源码位置由调用方指定的 `UnitId` 构造，因此属于当前会话的文件表。`PreparedFile` 是准备期的单元值，拥有 token 和可选 AST；脱糖完成后 `FrontendPreparation.finish()` 把它们与源文件一起移入 `UnitTable`。前端失败时准备期对象仍持有全部源码，供 `FrontendDriver.source_table()` 渲染诊断。

## AST 与脱糖

`frontend/ast/` 定义 AST 节点、遍历和存储。准备期按整个输入集合完成词法、语法和[脱糖](03.desugar.md)阶段；每个完成后单元在 `UnitTable` 中保存 token 和脱糖后的 AST，`run()` 返回该表交给中端，准备期对象仅供阶段转储读取。

`--dump` 由 `frontend/dump.an` 写出 token 和脱糖后的 AST，由 `analysis/dump.an` 写出 HIR，由 `codegen/dump.an` 写出 CFG 与 LLVM IR。文件阶段错误的结构及位置所有权见[错误处理](18.error_handling.md)。
