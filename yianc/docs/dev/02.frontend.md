# 02 前端

## 源码与会话

`FrontendDriver.new(config, trace)` 加载可选包图，确定标准库根和源码信任规则，收集命令行输入并把每个规范路径读入 `SourceTable`；同一规范路径只分配一个 `UnitId`。全部读取与校验成功后文件表冻结，再构造 `FrontendSession`。`FrontendDriver.run()` 按全词法、全语法、全脱糖的顺序处理会话中的文件。LSP 使用 `from_documents` 装入内存文档并返回待运行的 driver，随后调用同一个 `run()`。

`new` 和 `from_documents` 保存调用者提供的 `CompilerTrace` 非拥有引用，调用者须保证它在 driver 使用期间有效。命令行共享按配置构造的实例；LSP 使用禁用的实例。前端转储由 `--dump` 独立控制。

## Lexer

`yianc/src/frontend/lex/lexer.an` 的 `Lexer` 生成带源码范围的 token。token 的种类和载荷定义位于 `frontend/lex/token.an`。词法错误由 `LexError` 返回。

## Parser

`frontend/parse/state.an` 的 `Parser` 管理 token 消费、诊断及 AST 分配，`frontend/parse/items.an::parse_program` 解析顶层声明。表达式、类型和模式的解析分别位于 `frontend/parse/expr.an`、`type.an` 和 `pattern.an`。

## 阶段错误

`frontend/prepare.an` 把低层消息和 span 包装成具体阶段诊断：`LexDiagnostic`、`ParseDiagnostic` 和 `DesugarDiagnostic` 各持有诊断码、`SourceSpan` 与正文，`FrontendStageError` 按变体委托 `UserDiagnostic` 与释放。源码位置由调用方指定的 `UnitId` 构造，因此属于当前会话的文件表。`PreparedFile` 拥有 token 和可选 AST；成功结果才携带它们进入分析会话。

## AST 与脱糖

`frontend/ast/` 定义 AST 节点、遍历和存储。会话按整个输入集合完成词法、语法和[脱糖](03.desugar.md)阶段。每个单元保存 token 和脱糖后的 AST，`take_session()` 将该会话交给中端。

`--dump` 由 `frontend/dump.an` 写出 token 和脱糖后的 AST，由 `analysis/dump.an` 写出 HIR，由 `codegen/dump.an` 写出 CFG 与 LLVM IR。文件阶段错误的结构及位置所有权见[错误处理](18.error_handling.md)。
