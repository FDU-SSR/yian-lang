# 02 前端

## 源码与单元表

`main` 在收集源码之前创建本次编译的 `NameInterner`。`preprocess.an::collect_sources(config, trace, names)` 收集命令行输入并把每个规范路径读入 `SourceTable`；同一规范路径只分配一个 `UnitId`。`SourceFile` 表示输入文本和规范路径；诊断、dump 和默认输出命名使用该路径。`FrontendDriver.new(sources, dump, trace, names)` 接收源码表并构造准备期对象 `FrontendPreparation`（`SourceTable` + 每单元 `PreparedFile`），不接受包图、源码根或信任策略。`FrontendDriver.run()` 按全词法、全语法、全脱糖的顺序处理输入，不再判定权限；成功后 `FrontendPreparation.finish()` 产出包含全部 `SourceFile`、各单元 token 和脱糖 AST 的 `UnitTable`。`UnitTable` 以 `UnitId` 索引 `UnitData` 并实现 `SourceMap`；失败时 `source_table()` 提供源码用于渲染。LSP 和测试自行构造 `SourceFile`，通过 `SourceTable.from_files` 一次性装入，随后调用同一个 `run()`。

`FrontendDriver.new` 使用 `CompilerTrace` 和 `NameInterner`。词法分析把 token 原始拼写和解码后的文字放进驻留表，语法树复用已驻留的字面量和拼写。解析和脱糖新生成的名字、字面量和文字片段也放入同一张表。token 与 AST 引用驻留文本。`main` 先完成预处理，再把共享 trace、驻留表和文件表提供给 `new`；LSP 使用禁用的实例。前端转储由 `--dump` 独立控制。源码权限由 `MiddleEndDriver` 在语义分析开始时按 `UnitId` 分类。

## Lexer

`yianc/src/frontend/lex/lexer.an` 的 `Lexer` 生成带源码范围的 token。token 的种类和载荷定义位于 `frontend/lex/token.an`。词法错误由 `LexError` 返回。

## Parser

`frontend/parse/state.an` 的 `Parser` 管理 token 消费、诊断及 AST 分配，`frontend/parse/items.an::parse_program` 解析顶层声明。表达式、类型和模式的解析分别位于 `frontend/parse/expr.an`、`type.an` 和 `pattern.an`。

## 阶段错误

`frontend/prepare.an` 把低层消息和 span 包装成具体阶段诊断：`LexDiagnostic`、`ParseDiagnostic` 和 `DesugarDiagnostic` 各包含诊断码、`SourceSpan` 与正文，`FrontendStageError` 按变体委托 `UserDiagnostic` 与释放。源码位置由调用方指定的 `UnitId` 构造。`PreparedFile` 是准备期的单元值，包含 token 和可选 AST；脱糖完成后 `FrontendPreparation.finish()` 产出包含源文件与各单元 token/AST 的 `UnitTable`。前端失败时 `FrontendDriver.source_table()` 提供源码用于渲染诊断。

## AST 与脱糖

`frontend/ast/` 定义 AST 节点、遍历和存储。准备期按整个输入集合完成词法、语法和[脱糖](03.desugar.md)阶段；每个完成后单元在 `UnitTable` 中保存 token 和脱糖后的 AST，`run()` 返回该表交给中端，准备期对象仅供阶段转储读取。

`--dump` 由 `frontend/dump.an` 写出 token 和脱糖后的 AST，由 `analysis/dump.an` 写出 HIR，由 `codegen/dump.an` 写出 CFG 与 LLVM IR。文件阶段错误的结构及位置信息见[错误处理](18.error_handling.md)。
