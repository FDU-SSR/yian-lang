# 08 HIR

`yianc/src/analysis/hir/` 定义带类型的高级中间表示。会话用 `HirId` 和 `PatternId` 标识节点；
节点记录类型、源码范围和值或 place 属性。具体过程检查产生 HIR，地址存储规范化处理需要稳定地址的操作，
随后进行 HIR 验证、覆盖检查与确定赋值检查。

## 原生 HIR 名字范围

原生 `yianc` 的 `HirNode.span` 表示完整表达式或诊断范围。`Call`、`MethodCall`、
`TraitObjectMethodCall`、`FieldAccess`、`StructConstruct` 和 `VariantConstruct` 另外保存可选的
`name_span`；结构构造和变体构造还按源码顺序保存字段名字范围。这些范围来自 parser/AST 的真实名字
token，合成名字没有对应用户 token 时为空。字段、变体和方法的声明范围由类型定义中的声明记录提供。

名字范围只用于诊断和阅读导航，不参与类型身份、方法选择或代码生成。去糖、实例化、闭包转换和地址存储
规范化复制已有真实来源，生成临时节点不伪造用户引用。

## 原生 HIR 验证

原生 `yianc` 在地址存储规范化后按每条 HIR 入边验证节点、模式、绑定、捕获、调用、trait object、
控制流和所有权结构。一次验证运行内，同一具体 `TypeId` 的完整值类型验证成功结果、同一具体
callable `TypeId` 的签名以及同一 trait 身份的动态方法表只查询或计算一次，后续相同请求复用结果。
失败查询不保存，重试仍按当次调用位置产生原错误。

缓存由验证入口创建，在同一次运行的过程之间共享，并在成功或失败结束时释放；它拥有保存的签名
参数和方法表，不跨验证运行、分析阶段或 session 共享。`Return`、`Break`、循环栈、HIR 环检测和
共享节点的每条入边仍逐次检查，结果类型和 loop 上下文按过程独立。
