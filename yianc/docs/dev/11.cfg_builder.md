# 11 CFG 构建

`yianc/src/codegen/lowering/` 将具体过程的 HIR 下降为 `CfgModule`。局部存储及其逻辑作用域属于
当前函数。条件、循环、模式匹配和短路运算构造基本块与控制流边，返回路径展开活动的 `defer`。

HIR 地址存储规范化在下降前为数据取地址和隐式存储消费提供 place。CFG 下降根据不同地址形态选择对应操作。

## Native enum place 构造点

原生 lowering 在 `yianc/src/codegen/lowering/expression.an` 与 `patterns.an` 中直接生成枚举
place 操作：

- `let` 以 `VariantConstruct` 初始化 tagged enum 时，新 local 的地址就是构造目标，不生成中间聚合值。
- 赋值先求左侧地址，再按源码顺序求值 payload 字段，随后在原地写入 tag 与字段。
- 按值匹配在原表达式求值点建立独立快照；引用匹配的每个 arm 从原 place 读取当前 tag 与字段。
- niche/ZST 枚举、非 place 来源与函数边界继续使用通用值路径。

下降细节见[原生 LLVM 代码生成](12.llvm_codegen.md#native-yianc-的-enum-place-下降与-linkage)。

## Native yianc 的 CFG 优化流水线

原生 `yianc` 在 HIR 检查完成后由 `codegen/lowering/` 构造 `CfgModule`，随后按固定顺序运行 CFG pass：

```text
lower_module → verify_structure → cleanup
  → verify_cfg(Neutral) → inline_cfg → verify_cfg(Neutral)
  → prepare_safety → verify_cfg(Prepared)
  → eliminate_checks → verify_cfg(Optimized)
  → LLVM lowering
```

- `inline_cfg` 只在中立图上运行，受指令数、block 数、嵌套深度、调用方与模块增长预算约束；递归 SCC、无法解析的间接调用和超预算调用保留。克隆时重映射 block、value、local、scope、Phi predecessor、Temporary 与全部嵌套 operand；多返回在 continuation 合并为 Phi。
- `prepare_safety` 一次绑定表示表、建立每个 scope 的 frame 计划、插入安全检查与隐藏模板 guard，并把阶段推进到 `Prepared`。
- `eliminate_checks` 在 `Prepared` 图上做按 word 的 must 数据流，只省略有支配见证的 `Live` 检查，并为自然循环的必执行检查建立 preheader `SafetyPoint`，最后推进到 `Optimized`。
- LLVM 驱动只验证并消费 `Optimized` 图，不在代码生成阶段重新插入检查。

`--no-cfg-inline`/`YIAN_CFG_INLINE=0` 与 `--no-fat-check-elimination`/`YIAN_FAT_CHECK_ELIMINATION=0` 分别关闭可选 pass；关闭后仍执行安全激活与阶段校验。raw 模式跳过 fat 帧计划与生命周期检查，但保留裸指针原有检查。`--check` 停在语义分析，不构造这些 CFG pass。
