# AGENTS.md

YIAN is a statically-typed programming language whose compiler is written in Python (strict typing, pyright `strict` mode). Pipeline: `.an source → Tokens → AST → (desugared) AST → HIR → CFG IR → LLVM IR → native exe` (via clang). Requires Linux, python3.10+, clang.

## Compiler CLI (current)

**Always pass `lib` as a positional path** — the stdlib is not implicit. Paths may be files or directories (`.an` files are collected recursively):

```bash
python3 -m compiler.main lib tests/array/access.an              # build exe
python3 -m compiler.main -t none lib tests/array/access.an      # analysis only
python3 -m compiler.main -t ll lib tests/array/access.an        # LLVM IR text
python3 -m compiler.main -o build/func -O2 lib tests/array/access.an
python3 -m compiler.main --log-spec "type_check=DEBUG" lib tests/array/access.an
```

- Flags: `-t/--target {none,exe,ll,bc,obj,asm}` (default `exe`), `-o/--output`, `-O {0..3}` (default 0; passed to clang when linking an executable), `--profile`, `--log-spec`, `--log-file`, `--packages`.
- **`--token`, `--ast`, `--hir`, `--cfg`, `--emit-llvm` were removed** (argparse rejects them). Replacements:
  - Structured logging: `--log-spec "channel=LEVEL"` — levels `OFF/ERROR/WARN/INFO/DEBUG/TRACE` (default `WARN`), comma-separated (`all=INFO,type_check=DEBUG`), optional span filter `channel=LEVEL@substring`. `YIAN_LOG` sets the spec via env (CLI wins), `YIAN_LOG_FILE` adds a log file. Logs go to stderr + `build/compile.log` by default (`--log-file` overrides). Channels are created lazily by name, and a spec also matches dotted subchannels (`type_check` covers `type_check.expr`). Channels in code: `lex`, `parse`, `desugar`, `main`, `type_check`, `type_check.expr`, `type_check.coerce`, `call_dispatch`, `cfg.block`, `cfg.logical`, `llvm` (`compiler/utils/log.py`).
  - Intermediate dumps are written to `build/`: `tokens.txt`, `ast.txt`, `hir.txt`, `cfg.txt` (plus `ir.ll` whenever codegen runs).
- Default output paths: exe → `build/a.out`; ll/bc/obj → `build/<stem>.<ext>`; **asm → `<stem>.s` in the CWD** (not `build/`). `<stem>` comes from the first collected `.an` file — with `lib` passed first that's a stdlib file — so pass `-o` when the name matters.
- `--packages pkg.json` enables package-name import resolution (JSON maps package name → source root); when set, every import's first segment must be a known package name (strict mode). Normally generated by `anx build`; standalone mode uses relative paths.

## Tests

```bash
python3 scripts/run_tests.py               # full suite
python3 scripts/run_tests.py -f call       # filter by substring in test name
python3 scripts/run_tests.py -v            # failure details
python3 scripts/run_tests.py -q            # quiet: summary line only
python3 scripts/run_tests.py -x            # include tests/experimental/ (excluded by default)
python3 scripts/run_tests.py --no-run      # compile only, don't execute
```

- Sources: `tests/<category>/<name>.an`; expected outputs live in `tests/output/`.
- `.err.an` suffix → error test: compilation must fail (any non-zero exit); the `.ans` file content is the expected error substring.
- Normal tests: `.ans` = expected stdout; if the first line is `Exit code <N>`, a non-zero exit code is expected. No `.ans` → success test (exit 0, no output check).
- `tests/input/<name>.args` (whitespace-split CLI args) and `tests/input/<name>.stdin` feed the compiled executable — used by `tests/env/` (args, stdin, exit code).
- The runner compiles with `-O3` and runs binaries from `build/test_exe/<name>`.
- Failure details are auto-written to `build/test_failures.log`; the runner also warns about orphaned `.ans` files with no matching source.
- Multi-file tests are configured via `EXTRA_SOURCES` / `MULTI_FILE_DIRS` constants at the top of `scripts/run_tests.py` (currently empty; helper files listed there are excluded from discovery).
- **`scripts/test.py` and `run_tests.py --dump` are broken** — they still pass the removed `--token`/`--ast`/`--hir`/`--cfg` flags. Don't use them for verification.

## anx package manager

`anx/` is a small package manager: `python3 -m anx.main new myapp`, `new --lib`, `run`, `check`, `build`, and `test` (runs its own integration fixtures via `anx/tests/run.py`). Projects declare deps in `package.anx` (TOML: `[package] name/version`, `[dependencies]` path deps); imports use package names (`from myapp.utils.math import add`). It shells out to `compiler.main --packages build/pkg.json`. Its fixtures live in `anx/tests/` (with `expected.stdout`/`expected.stderr`/`expected.exit`).

## Architecture

- `compiler/frontend/` — hand-written lexer (`lex/`), recursive-descent parser (`parse/`; `parser.py` / `parser_type.py` / `parser_expr.py` — statement parsing lives in `parser_expr.py`, there is no separate `parser_stmt.py` anymore). Keywords/constants live in `compiler/frontend/lex/token.py` (`KeywordKind`) — there is no `compiler/config/` anymore.
- `compiler/analysis/passes/` — `desugar.py` (lowers for/while/assert/elif/range/`in`), `prelude.py` (`inject_prelude()` prepends stdlib imports), `global_resolve.py` (3-phase symbol/import/type collection into `TypeCtx`), `type_check.py` (worklist-driven from `main()`; lowers AST→HIR; no separate statement checker — `ExprChecker` handles both), `closure_lowering.py` (`ClosureLowering`, runs right after TypeCheck), `definite_assignment.py` (guards variable uses).
- `compiler/analysis/lowering/` — `expr_checker.py` (`ExprChecker`), `call_dispatcher.py`, `op_builder.py`, `expr_evaluator.py`, `sem_ctx.py`, `assign_check.py`, `closure.py`.
- `compiler/analysis/ty/` — type system (`TypeCtx` registry in `context.py`, representations in `ty.py`, unification in `type_ops.py`, generics in `generic_inference.py`, trait impls in `impl.py`, plus `name.py`/`resolver.py`/`space.py`).
- `compiler/analysis/unit/` — HIR (`hir.py`, export in `hir_export.py`), `DefPoint` (one per monomorphized function, holds `validity` after DA), `UnitData` (unit of compilation). `compiler/analysis/symbol/` — symbol contexts (`symbol.py`/`context.py`).
- `compiler/codegen/cfg/` — CFG IR plus `CfgBuilder`/`CfgTranslator`. `compiler/codegen/llvm/` — llvmlite lowering (`LLTranslator`, handler-map dispatch on CFG node types; `LLTypeCtx` maps type ids to LLVM types) and target emission through `Emitter`; the default output directory is `build/`.
- `lib/` — stdlib written in YIAN itself (`core/`, `collections/`, `num/`).
- Pipeline order in `compiler/main.py`: lex → parse → desugar → `inject_prelude` → `GlobalResolve` → `type_ctx.finalize()` → `TypeCheck` → `ClosureLowering` → `DefiniteAssignment` → `CfgTranslator` → `LLTranslator` → `Emitter`.

## Conventions & gotchas

- When modifying project code, do not automatically synchronize documentation. Update documentation only when the user explicitly requests it.
- If required tools, dependencies, or other environment setup are missing, it is acceptable to stop and ask the user to install or configure them. Resume after the user confirms the environment is ready; a workaround is not always required.
- Strict typing enforced by pyright (`pyproject.toml`: `include = ["compiler", "anx"]`, `exclude = ["bak", "tests", "docs", "**/node_modules", "**/__pycache__", "**/.*"]`, `typeCheckingMode = "strict"`). No `Any`, no `object`, no `hasattr()`, no imports except at top of file, don't line-wrap long lines. `.pylintrc` disables most checks and ignores `bak/`. (Preexisting deviations: `compiler/main.py` imports `ClosureLowering` mid-function; `compiler/utils/log.py` has a few local imports.)
- Handler-map dispatch (`dict[type[T], Callable[[T], None]]`) is the pattern for both the type checker and the LLVM translator — register new IR nodes there.
- `bak/` is gitignored legacy — don't touch it. `.conda/` is a local environment — don't modify it. `build/` holds compiler and test output and is gitignored.
- `ide-support/` contains the packaged VS Code language extension (`*.vsix`); `licenses/` holds the dual Apache/MIT license texts.
- Docs (all Chinese): `docs/grammar/` is the language manual (16 chapters, 00–15), `docs/manual/` documents compiler internals (19 chapters, 01–19), and `docs/llvm_note.md` contains LLVM notes. `mkdocs_cn.yml` still references removed chapter files. Known broken links: `docs/manual/index.md` → `docs/anx.md`, `README.md` → `bak/anx_design.md`, `docs/compile_script.md` §6 → `bak/quest_log.md` (targets don't exist).
- `CLAUDE.md` is a symbolic link to `AGENTS.md`; maintain repository guidance in this file.
- No CI, pre-commit hooks, or formatter configuration are present.
- Assignment, argument passing, and return use shallow value copies. `Move`, `bitcopy`, `@BitCopy`, simple-type assignment restrictions, and resource-validity checks tied to `Move` have been removed. `Clone` and `Drop` remain explicit standard-library traits. Pointers do not implement `Clone`; method lookup auto-dereferences `ptr.clone()` and clones the pointed-to value.
