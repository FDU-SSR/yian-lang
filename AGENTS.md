# AGENTS.md

YIAN is a statically typed programming language. Its compiler is written in Python and checked with pyright in strict mode. The compilation pipeline is:

`.an source → tokens → AST → desugared AST → HIR → CFG IR → LLVM IR → native executable`

The supported development environment is Linux with Python 3.10 or newer and clang.

## Working rules

- When modifying project code, do not automatically synchronize documentation. Update documentation only when the user explicitly requests it.
- If required tools, dependencies, or other environment setup are missing, it is acceptable to stop and ask the user to install or configure them. Resume after the user confirms the environment is ready; a workaround is not always required.
- Preserve unrelated local changes. Inspect the worktree before editing or committing.
- Keep `raw` and `nocheck` as diagnostic modes. The default checked mode is the mode for which the memory-safety guarantee is claimed.

## Compiler CLI

Always pass `lib` as a positional input because the standard library is not implicit. Input paths may be files or directories; directories are searched recursively for `.an` files.

```bash
python3 -m compiler.main lib tests/array/access.an
python3 -m compiler.main -t none lib tests/array/access.an
python3 -m compiler.main -t ll lib tests/array/access.an
python3 -m compiler.main -o build/func -O2 lib tests/array/access.an
python3 -m compiler.main --dump --log-spec "type_check=DEBUG" lib tests/array/access.an
```

Current options include:

- `-t/--target {none,exe,ll,bc,obj,asm}`; the default is `exe`.
- `-o/--output PATH`.
- `-O {0..3}`; for non-`ll` targets this controls LLVM IR passes, backend optimization and executable linking. `-t ll` emits unoptimized LLVM IR.
- `--profile`, `--dump`, `--log-spec`, `--log-file`, and `--packages`.
- `--no-fat-checks` keeps the fat-pointer representation and lock protocol but omits CFG access checks.
- `--raw-pointers` uses bare pointers without fat metadata, lock slots or safety checks.

The removed `--token`, `--ast`, `--hir`, `--cfg`, and `--emit-llvm` flags must not be used. `--dump` writes `tokens.txt`, `ast.txt`, `hir.txt`, and `cfg.txt` under `build/`; code generation also writes `ir.ll`.

Default outputs are `build/a.out` for executables and `build/<stem>.<ext>` for LLVM bitcode and objects. Assembly defaults to `<stem>.s` in the current directory. Pass `-o` whenever the output name matters.

`--packages pkg.json` enables strict package-name import resolution. The JSON maps package names to source roots and is normally generated by `anx build`.

## Tests and checks

Main compiler regression suite:

```bash
python3 scripts/run_tests.py
python3 scripts/run_tests.py -q
python3 scripts/run_tests.py -f call
python3 scripts/run_tests.py -v
python3 scripts/run_tests.py -x
python3 scripts/run_tests.py --no-run
```

- Sources are under `tests/<category>/`; expected results are under `tests/output/`.
- A `.err.an` source must fail compilation, and its `.ans` file contains the required diagnostic substring.
- For a normal test, `.ans` contains expected stdout. A first line of `Exit code <N>` specifies an expected nonzero exit code.
- `tests/input/<name>.args` and `tests/input/<name>.stdin` provide process arguments and standard input.
- The main runner excludes `tests/fat/` and `tests/fat_cve/`, which have dedicated runners.
- `scripts/test.py` and the obsolete `run_tests.py --dump` path use removed compiler flags and must not be used for verification.

Additional suites and checks:

```bash
python3 anx/tests/run.py
python3 scripts/run_fat_tests.py -q
python3 scripts/run_raw_tests.py -q
python3 scripts/run_fat_cve.py -q
python3 tests/unit/test_lockmech.py
python3 scripts/check_frame_lock_ir.py
python3 scripts/check_raw_free_ir.py
pyright
python3 -m compileall -q compiler anx scripts
```

`run_fat_tests.py` covers checked fat-pointer behavior. `run_raw_tests.py` runs selected cases in checked, raw, and nocheck modes. `run_fat_cve.py` runs the paired vulnerable/fixed CVE regression suite. Expected outputs for the dedicated suites live under `tests/output/fat/` and `tests/output/fat_cve/`.

## Package manager

`anx/` implements `new`, `new --lib`, `run`, `check`, `build`, and `test`. Projects declare metadata and path dependencies in `package.anx`; imports use package names. `anx` invokes `compiler.main` with a generated `build/pkg.json` package map. Integration fixtures are under `anx/tests/`.

## Architecture

- `compiler/frontend/` contains the hand-written lexer and recursive-descent parser. Statement parsing is in `frontend/parse/parser_expr.py`.
- `compiler/analysis/passes/` contains desugaring, prelude injection, restricted-operation checking, global resolution, type checking, closure lowering, and definite-assignment analysis.
- `compiler/analysis/lowering/` lowers expressions and calls into HIR.
- `compiler/analysis/ty/` contains type representations, unification, generic inference, trait implementation lookup, and the shared `TypeCtx`.
- `compiler/analysis/unit/` and `compiler/analysis/symbol/` contain HIR compilation units and symbol contexts.
- `compiler/codegen/cfg/` contains CFG IR, `CfgBuilder`, and the fat-pointer lock/check mechanism.
- `compiler/codegen/llvm/` lowers CFG nodes with llvmlite and emits target files.
- `lib/` is the standard library written in YIAN.

The pass order in `compiler/main.py` is: lex, parse, desugar, prelude injection, restricted-operation checking, global resolution, type finalization, type checking, closure lowering, definite assignment, CFG lowering, LLVM lowering, and emission.

## Memory-safety implementation

In checked mode, `T*` values use five fields: `data`, `lock_ptr`, `key`, `index`, and `size`. Slices/strings omit `index`; references omit both `index` and `size`. Heap blocks carry a lock slot, stack addresses use frame locks, and stale, dangling, out-of-bounds, invalid arithmetic, invalid comparison, and invalid delete operations trap when their preconditions fail.

The CFG nodes and lock constants are defined in `compiler/codegen/cfg/ir.py` and `compiler/codegen/cfg/lockmech.py`; LLVM lowering is in `compiler/codegen/llvm/`. The safety model is documented in `docs/security.md`, and its compiler correspondence is documented in `docs/security-code.md`.

Restricted operations such as arbitrary `bitcast`, raw system-call wrappers, `from_raw_parts`, internal slice/string part accessors, `assume_init`, and `__memcpy` are unavailable to ordinary user code. The standard library and explicit standard-library test harnesses form the audited exception and are part of the trusted computing base.

Assignment, argument passing, and return use shallow value copies. They do not invalidate the source or perform implicit cleanup. `Move`, the `bitcopy` builtin, `@BitCopy`, compiler-provided `Clone`, and simple-type assignment restrictions are absent. `Drop` is explicit, and `del` releases the selected allocation without recursive member destruction.

## Coding conventions

- Pyright strict checking covers `compiler/` and `anx/`; avoid `Any`, `object`, `hasattr()`, and local imports in new code.
- Keep imports at the top of the file and preserve the existing handler-map dispatch style in the type checker and LLVM translator.
- Do not modify `bak/`, `.conda/`, `build/`, or local agent/tool state.
- `AGENTS.md` is the repository guidance source. `CLAUDE.md` must remain a relative symbolic link to it.
- There is no CI, pre-commit hook, or formatter configuration; run checks locally and use `git diff --check` before committing.
